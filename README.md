# 奇点之后 · 地图编辑器

《奇点之后》跑团专用的网页地图编辑器：画地图、写预测分支（事件流程图）、试玩视野、带团时开着用。

需求、决定和已做的功能都在 [需求.md](需求.md)。

## 一键启动（Windows / macOS）

先安装 [Node.js LTS](https://nodejs.org/)（22或更新版本，包含 npm），再把整个编辑器文件夹下载并解压。

- **Windows**：双击根目录的 `启动编辑器.cmd`。
- **macOS**：双击根目录的 `启动编辑器.command`。下载的 ZIP 若没有保留执行权限，可在编辑器目录的终端运行下面的命令。

首次启动会联网安装依赖，随后自动打开默认浏览器；以后依赖没有变动就直接启动。使用过程中保留终端窗口，结束后按 Ctrl+C。页面没自动弹出时，打开终端打印的本机网址（端口冲突时会自动选择空闲端口）。

macOS 命令：

```bash
bash ./启动编辑器.command
```

Windows PowerShell 命令：

```powershell
.\启动编辑器.cmd
```

两平台也可以在编辑器目录使用同一条命令，并传入要自动载入的工程；路径包含空格时保留双引号：

```bash
node scripts/launch.mjs "工程的路径"
```

不带工程路径时打开编辑器已有的浏览器存档；新用户会看到示例工程，用界面导入地图。发送给别人时，编辑器需要整个文件夹（包含 `scripts`、`src`、`package.json`、`package-lock.json` 等），不用发送 `node_modules`；地图可另附 `.tsmap.zip`。启动脚本不会下载你的私有模组。

## 运行

已经安装依赖时也可直接使用原入口：

```bash
npm start
```

直接打开工程并支持快捷键保存回原路径：

```bash
npm start -- "工程的路径"
```

工程可以是：
- 文件夹（`world.json` + `media/`）：适合放进 git；
- `.tsmap.zip`：一个文件，方便发给别人；
- Rabbithole 的包（`.zip` / `map.json`）：导入后另存为 `.tsmap.zip`。

两种格式互转：

```bash
node scripts/tsmap.mjs unpack 工程.tsmap.zip 工程文件夹
node scripts/tsmap.mjs pack 工程文件夹 工程.tsmap.zip
```

## 局部细分与薄墙

地图默认使用0.75米主格。用「细分为3×3」手动选定区域后，该处才能按0.25米定位；缩放不会自动细分。「显示0.25米子格线」默认关闭并记住显示偏好，需要定位时可以打开，隐藏辅助线不影响建筑与精细走位。

在细分区可绘制薄墙、透明玻璃，以及墙上的可开关门洞。墙厚独立以毫米设置；玻璃透视但挡路，关闭的实心门挡路和视线。现有整格厚墙保持原样。人物在细分区按0.25米移动，家具仍按主格摆放；目前支持水平、竖直墙段，不模拟门扇摆动。

墙和门均为 `map.objects` 中的普通物件，共用 ID、名字、状态、主持人备注、隐藏信息、媒体与流程事件。墙附加 `geometry: {kind:"wall", a, b, thickness, material}`，门附加 `opening: {wallId, offset, width, openStates}`；端点、偏移和宽度以0.25米子格为单位，厚度以毫米计。`physical: {blocksMove?, blocksSight?}` 可选覆盖默认物理属性；门洞是否打开始终由普通 `state` 是否属于 `openStates` 决定。整数 `x/y/w/h` 仅是建筑物件的索引范围，不作为家具再次绘制或碰撞。

点击墙／门，或在检查器「建筑层」点名字，即可编辑同一物件的备注、线索、媒体与状态；流程节点可直接绑定该门的状态。手动切换、流程发生／撤销、房间排布／复位、滑块关联门均会拒绝把门关在人物或挡路家具上，失败时整项操作保持原状。房间快照保存状态，静态建筑不随家具移动；墙端点目前通过重画或工程数据调整。旧 `map.architecture` 导入时保留 ID 迁入物件，并合并旧门快照。复制地图会重映射墙门引用。玩家同步仅发可见几何裁片和冻结记忆，不带完整墙端点、门引用或主持人内容。

## 区域与同格物件

虚线区域是 `kind: 'zone'` 的范围物件，用于触发或主持人范围说明，与房间划分分开。选择工具下，从区域内部拖动会平移地图（已选中区域也一样）；沿虚线边界可选中并拖动区域，覆盖范围内的家具、棋子优先响应。区域平时只画淡虚线，悬停或选中时显示名称。房间名保持透明底，并避开家具。

同一文字锚格上的多个物件只画一个代表符号和 `+N` 数量标记，选中时显示选中者；连续点击或检查器列表仍可逐件选择。聚合只影响显示，不合并物件、状态或碰撞，玩家数量只计算自己可见或已记住的物件。

## 视野组与玩家窗口

在地图检查器、队伍面板或试玩栏选择「全队共享」「各自独立」「按组共享」。按组模式中新角色默认加入公共队伍组；队伍面板可新增/命名视野组，并为角色选择公共组、命名组或独立。分组设置跨地图生效；「各自独立」始终一键可选，切换不会清掉分组配置。

同组共享当前视野和探索记忆，包括暂时不在这张图上的组员。入组立即获得组内已有知识；拆组保留此前获知的内容，之后分别更新。合并只使用各自记忆，按世界内观察序号选择新知识；看到空地也留下证据，避免旧物件或已拆建筑从旧记忆复活。旧档缺观察序号时按0、内容稳定排序解决冲突，无法恢复旧档原本没有记录的先后。

迷雾笔刷在左侧选择「迷雾目标」，赠图在检查器选择「迷雾 / 赠图目标」：全队或一个角色。按组时角色目标包括当时组员；试玩赠图给当前角色的有效组。整图的变灰、揭示、抹黑按钮明确作用于全队。赠图只增加地形/建筑知识，不代表亲眼观察到家具消失。

顶栏「打开玩家窗口…」选择角色，或在队伍卡片打开其专属窗口，可同时打开多个不同角色窗口。玩家端固定使用主持人绑定的角色，不提供全队总览或其他角色切换。每份 world 在发送前按该角色裁剪，通过其窗口的 `postMessage` 定向发送；公共 BroadcastChannel 仅传会话/存活消息。刷新双方可以重连；删除角色或更换工程会清空原窗口，需要主持人重新打开绑定窗口。绑定在本机同源窗口间提供展示隔离，不是远程账号系统。

自动发现按发现时接收角色ID记录：独立模式只给发现者，按组模式给其当时组员；之后换组不会转发过去的线索。主持人私密揭示始终仅给选定角色，明确全队公开则全队可见。标记继续按声音交流（距离与隔墙）传播，允许跨组听到。玩家视角地图图片导出也选择对应角色，使用同一份裁剪数据。

## 打包给别人用

```bash
npm run build:single           # 打成单个 html，在 release-build/ 里
```

## 开发

Vite + React + TypeScript。`npm run build` 会先跑类型检查。开发模式下，`window.__ts` 上挂着页面实际在用的 store / actions / trial / perception / vision / sync，方便在控制台测试。

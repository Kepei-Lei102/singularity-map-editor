# 奇点之后 · 地图编辑器

《奇点之后》跑团专用的网页地图编辑器：画地图、写预测分支（事件流程图）、试玩视野、带团时开着用。

需求、决定和已做的功能都在 [需求.md](需求.md)。

## 一键启动（Windows / macOS）

**不需要先手动安装 Node.js。** 把整个编辑器文件夹下载、解压到自己可写的目录（例如桌面），再启动：

- **Windows 10/11（x64 或 ARM64）**：双击根目录的 `启动编辑器.cmd`。使用系统自带的 Windows PowerShell 5.1。
- **macOS（Apple Silicon 或 Intel）**：双击根目录的 `启动编辑器.command`。下载的 ZIP 若没有保留执行权限，可在编辑器目录的终端运行下面的命令。自动下载的 Node.js 22 要求 macOS 11 或更新版本。

首次启动会依次完成：

1. 检查现有 Node.js（22+）和 npm；可用则直接使用。
2. 缺失或版本太旧时，下载 Node.js 22 LTS 的便携包，核对 SHA-256 后解压到编辑器的 `.runtime/`。无需管理员权限，不覆盖系统 Node.js，不永久修改 PATH。
3. 安装锁定版本的项目依赖，然后自动打开默认浏览器。

首次启动需要联网并预留几百 MB 磁盘空间，请等待安装结束。以后会复用已准备的运行环境和依赖；依赖文件更新时自动重装。使用过程中保留终端窗口，结束后按 Ctrl+C。页面没自动弹出时，打开终端打印的本机网址（两个端口固定，冲突时会明确报错，避免连错端）。

### 中国境内下载源与失败处理

- Node.js 优先使用 `https://npmmirror.com/mirrors/node`，失败后尝试 `https://nodejs.org/dist`；版本和 SHA-256 清单从同一 HTTPS 来源取得。校验用于发现下载损坏，镜像仍是你信任的下载来源。
- npm 依赖优先使用 `https://registry.npmmirror.com`，失败后尝试 `https://registry.npmjs.org`；保留锁文件的完整性校验。源设置只在本次进程生效，不改用户全局 npm 配置。
- 两个来源都失败时，窗口保留错误信息；检查网络／代理、剩余空间和目录写入权限后，再次启动即可。首次运行不要同时双击多个启动窗口。
- 公司或学校设备若禁止 PowerShell 脚本／下载程序，需要遵循设备管理规则。Windows 入口遵守现有 PowerShell 执行策略，不修改或绕过策略。如果提示“禁止运行脚本”，自动下载 Node.js 这一步无法执行：可手动安装 Node.js LTS 后再次双击启动入口，或由设备管理员批准脚本。
- macOS 若弹出下载程序的安全提示，请先确认文件来源，再按系统提供的“仍要打开”操作；脚本不会关闭系统安全检查。必要时可手动安装 [Node.js LTS](https://nodejs.org/)（22+），再运行启动入口。
- 删除 `.runtime/` 可移除编辑器私有 Node，删除 `node_modules/` 可清除依赖，下次启动会重新下载。地图工程不存放在这两个目录中。

### 命令行启动

macOS 命令：

```bash
bash ./启动编辑器.command
```

Windows PowerShell 命令：

```powershell
.\启动编辑器.cmd
```

自动载入指定地图，macOS：

```bash
bash ./启动编辑器.command "工程的路径"
```

Windows PowerShell：

```powershell
.\启动编辑器.cmd "工程的路径"
```

路径含空格时保留双引号。已有可用 Node.js/npm 时，两平台也可直接执行 `node scripts/launch.mjs "工程的路径"`。

不带工程路径时打开编辑器已有的浏览器存档；新用户会看到示例工程，用界面导入地图。发送给别人时，编辑器需要整个文件夹（包含 `scripts`、`src`、`package.json`、`package-lock.json` 等），不用发送 `.runtime/` 和 `node_modules/`；地图可另附 `.tsmap.zip`。启动脚本不会下载你的私有模组。

## 运行

已经安装依赖时也可直接使用原入口：

```bash
npm start
```

直接打开工程并支持快捷键保存回原路径：

```bash
npm start -- "工程的路径"
```

工程可以是：
- 文件夹（`world.json` + `media/`）：适合放进 git；
- `.tsmap.zip`：一个文件，方便发给别人；
- Rabbithole 的包（`.zip` / `map.json`）：导入后另存为 `.tsmap.zip`。

两种格式互转：

```bash
node scripts/tsmap.mjs unpack 工程.tsmap.zip 工程文件夹
node scripts/tsmap.mjs pack 工程文件夹 工程.tsmap.zip
```

## 局部细分与薄墙

地图默认使用0.75米主格。用「细分为3×3」手动选定区域后，该处才能按0.25米定位；缩放不会自动细分。「显示0.25米子格线」默认关闭并记住显示偏好，需要定位时可以打开，隐藏辅助线不影响建筑与精细走位。

在细分区可绘制薄墙、透明玻璃，以及墙上的可开关门洞。墙厚独立以毫米设置；玻璃透视但挡路，关闭的实心门挡路和视线。现有整格厚墙保持原样。人物在细分区按0.25米移动，家具仍按主格摆放；目前支持水平、竖直墙段，不模拟门扇摆动。

墙和门均为 `map.objects` 中的普通物件，共用 ID、名字、状态、主持人备注、隐藏信息、媒体与流程事件。墙附加 `geometry: {kind:"wall", a, b, thickness, material}`，门附加 `opening: {wallId, offset, width, openStates}`；端点、偏移和宽度以0.25米子格为单位，厚度以毫米计。`physical: {blocksMove?, blocksSight?}` 可选覆盖默认物理属性；门洞是否打开始终由普通 `state` 是否属于 `openStates` 决定。整数 `x/y/w/h` 仅是建筑物件的索引范围，不作为家具再次绘制或碰撞。

点击墙／门，或在检查器「建筑层」点名字，即可编辑同一物件的备注、线索、媒体与状态；流程节点可直接绑定该门的状态。手动切换、流程发生／撤销、房间排布／复位、滑块关联门均会拒绝把门关在人物或挡路家具上，失败时整项操作保持原状。房间快照保存状态，静态建筑不随家具移动；墙端点目前通过重画或工程数据调整。旧 `map.architecture` 导入时保留 ID 迁入物件，并合并旧门快照。复制地图会重映射墙门引用。玩家同步仅发可见几何裁片和冻结记忆，不带完整墙端点、门引用或主持人内容。

## 区域与同格物件

虚线区域是 `kind: 'zone'` 的范围物件，用于触发或主持人范围说明，与房间划分分开。选择工具下，从区域内部拖动会平移地图（已选中区域也一样）；沿虚线边界可选中并拖动区域，覆盖范围内的家具、棋子优先响应。区域平时只画淡虚线，悬停或选中时显示名称。房间名保持透明底，并避开家具。

同一文字锚格上的多个物件只画一个代表符号和 `+N` 数量标记，选中时显示选中者；连续点击或检查器列表仍可逐件选择。聚合只影响显示，不合并物件、状态或碰撞，玩家数量只计算自己可见或已记住的物件。

## 视野组与玩家窗口

在地图检查器、队伍面板或试玩栏选择「全队共享」「各自独立」「按组共享」。按组模式中新角色默认加入公共队伍组；队伍面板可新增/命名视野组，并为角色选择公共组、命名组或独立。分组设置跨地图生效；「各自独立」始终一键可选，切换不会清掉分组配置。

同组共享当前视野和探索记忆，包括暂时不在这张图上的组员。入组立即获得组内已有知识；拆组保留此前获知的内容，之后分别更新。合并只使用各自记忆，按世界内观察序号选择新知识；看到空地也留下证据，避免旧物件或已拆建筑从旧记忆复活。旧档缺观察序号时按0、内容稳定排序解决冲突，无法恢复旧档原本没有记录的先后。

迷雾笔刷在左侧选择「迷雾目标」，赠图在检查器选择「迷雾 / 赠图目标」：全队或一个角色。按组时角色目标包括当时组员；试玩赠图给当前角色的有效组。整图的变灰、揭示、抹黑按钮明确作用于全队。赠图只增加地形/建筑知识，不代表亲眼观察到家具消失。

顶栏「打开玩家窗口…」选择角色，或在队伍卡片打开其专属窗口，可同时打开多个不同角色窗口。玩家端固定使用主持人绑定的角色，不提供全队总览或其他角色切换。每份 world 在发送前按该角色裁剪，通过其窗口的 `postMessage` 定向发送；公共 BroadcastChannel 仅传会话/存活消息。刷新双方可以重连；删除角色或更换工程会清空原窗口，需要主持人重新打开绑定窗口。绑定在本机同源窗口间提供展示隔离，不是远程账号系统。

自动发现按发现时接收角色ID记录：独立模式只给发现者，按组模式给其当时组员；之后换组不会转发过去的线索。主持人私密揭示始终仅给选定角色，明确全队公开则全队可见。标记继续按声音交流（距离与隔墙）传播，允许跨组听到。玩家视角地图图片导出也选择对应角色，使用同一份裁剪数据。

## 创作者／见证者端与玩家端

`npm start`、`npm run dev` 和一键启动同时启动两个端口：

- `http://localhost:5178`：创作者／见证者端，负责编辑、带团、检定与揭幕，以及工程读写。
- `http://localhost:5179`：固定玩家端，无编辑入口，不加载主持人存档，不提供工程读写接口。修改 `view` 参数也不能切到编辑模式。

在主持人端顶栏「打开玩家窗口…」选择角色，就会打开5179的绑定窗口。两个窗口须位于同一浏览器，玩家窗口由主持人窗口打开；单独输入5179会显示连接说明。角色数据通过带来源校验的 `postMessage` 发送，世界只发裁剪后的内容，私密辨识不会发送给其他角色；双方刷新后可重连。这是本机双窗口测试和展示，尚不是跨电脑联网服务。试玩沙盒仍不广播给真实玩家窗口；测试双端时在带团模式放置真实测试角色。

分别运行可用 `npm run dev:host` / `npm run dev:player`。`npm run build:split` 生成 `dist-host/` 和 `dist-player/` 两份静态产物，分别用 `npm run preview:host` / `npm run preview:player` 本地检查。自定义部署地址需在构建前设置 `VITE_HOST_ORIGIN` 与 `VITE_PLAYER_ORIGIN`；开发端口可用 `HOST_PORT` / `PLAYER_PORT`，对应的来源地址也须一致。沿用单HTML发放时仍用 `npm run build:single`，保留原有同源玩家窗口。

## 物件辨识

玩家看见物件时只显示轮廓与「未辨识物件」，名称、文字图标（例如「钟」）和状态名称要辨识后才显示。选中物件，在检查器「物件辨识」中确认「观察成功」或「见证者揭幕」，可告知全队或私密给指定角色；这里记录主持人的判定，不自动掷骰或扣能力资源。默认使用1格及视线检查，范围外由主持人确认能力确已生效。

已有「观察」或「见证者…揭幕」检定线索的成功／大成功也解锁物件名称；失败、大失败和自动浮现均不解锁。私密辨识按角色ID保存，不随共享视野或换组扩散。撤回辨识同时撤回该物件相关的检定揭示。旧存档未记录辨识证据时默认未辨识。

玩家窗口收到的数据、灰区记忆、编号图例与玩家视角图片都过滤未辨识名称、图标和状态；主持人照常看完整信息。试玩检查器列出眼前物件，可模拟辨识，退出后随沙盒恢复。自由编写的线索正文与手动播放的媒体标签仍按主持人明确揭示的内容展示。

## 开发

Vite + React + TypeScript。`npm run build` 会先跑类型检查。开发模式下，`window.__ts` 上挂着页面实际在用的 store / actions / trial / perception / vision / sync，方便在控制台测试。

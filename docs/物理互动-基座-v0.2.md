# 物理互动基座 v0.2（2026-11-23）

先把「谁能对哪个物件发起动作」收成一处，后面的动作卡、技能和前置条件都接在这条路上。这一版只做通用条件，不碰动作库效果列，也不做技能树。

## 一条链路

`看结果` 和 `确认，落账` 都调用同一个 `physicalActionError()`；面板拿它拦预览，落账前再算一遍。失败时世界不动、不写事件。判定成功但状态没变时会落一条空 delta 事件，并占行动点。

## 现在会拦什么

| 条件 | 口径 |
|---|---|
| 试玩中的行动归属 | 只能由当前行动角色发起；选别人提示「现在轮到 X」 |
| 发起者状态 | 尸体、昏厥、状态挡行动（如眩晕/恐惧）、这回合已结束都拦；流血/中毒不拦 |
| 战斗行动点 | 战斗里通用互动占 1 行动点；已用掉就拦；确认成功后置 `acted` |
| 行动点是否扣 | 非战斗不扣；试玩以外也没有行动点 |
| 物件 | 被禁用就拦；试玩里对玩家隐藏也拦 |
| 距离 | 按物件真实占位矩形（含 1/3 格吸附）到棋子的最近格距离，默认贴身 1 格；这是按格算的距离（斜角不按欧氏），接口留了 `range`，等动作卡数据 |
| 视线 | 试玩里要求从发起者能看到物件；和开门一样排除目标自己的构件，也不让高物件自己的格子挡住自己；其他物件/墙照常挡 |

## 不做什么

- 全局动作层的前置条件（同一个动作全模组统一）和 `ActionRange` 的形状/目标数：未接；物件级范围/条件见 [物理互动-动作条件-v0.3.md](物理互动-动作条件-v0.3.md)；
- ME、技能来源、技能 → 动作 `actionId`；
- 拖/抛/攀爬执行器（攀爬仍走跳跃系统）；
- 玩家窗口推送、NPC/角色作为目标、心理层、信息效果；
- 一次改多个物件/多个状态、临场 AI 效果。

## 为什么不在试玩外也查距离/视线

试玩外只有角色卡没有棋子，没有位置和朝向可算。v0.2 只查物件启用状态；v0.3 起再查目标/发起者这类不依赖位置的动作条件，距离、视线、行动点仍只在试玩里收紧。

## 测试

- `scripts/physical-base.test.mjs`：当前角色、尸体/昏厥/挡行动状态/回合结束/行动点、流血中毒、距离/吸附、视线/高物件、隐藏、禁用；确认时复核人物走开/行动点被吃/物件禁用都不落账；战斗扣行动点、非战斗不扣；空 delta 也占点。
- `scripts/object-interaction-ui.test.mjs`：面板拦错角色/太远并禁用看结果；战斗落账后 `acted` 为真；非战斗不扣；预览后人物走开/行动点被吃掉会清旧预览。

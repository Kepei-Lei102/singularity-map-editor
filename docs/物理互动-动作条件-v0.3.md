# 物理互动：动作范围与前置条件 v0.3（2026-11-23）

B 步只做「动作 × 本物件」这一层：同一个动作在不同物件上可以有不同范围/条件。公共动作层（全模组统一）的条件留到以后，避免把模组条件写进会被 `gen-actions.py` 覆盖的动作库。

## 数据

`MapObject.interaction.overrides[]` 每条增加：

```ts
range?: number;              // 0..200 格；不填按 PHYSICAL_REACH=1
preconditions?: Precondition[];
```

`Precondition` 现在放在 `core/types.ts`，规则层 `interaction.ts` 重新导出：

- `targetHasProp`：目标要有某个属性/标签
- `targetStateIn`：目标只能在某些状态
- `targetEnabled`：目标没被禁用
- `withinRange`：目标在几格内
- `actorHas`：发起者有某个标签

## 编辑器能配什么

每个动作卡下面直接配：

- 距离（格）：留空＝贴身 1 格
- 目标状态：勾选允许的状态；不勾＝不限
- 目标标签：物件互动档案的 `tags` 里要求有哪些标签
- 发动者标签：角色卡「途径/职业」栏里的标签（没有物品栏，`打火机` 这类先临时写在这里）

`targetEnabled` 和 `withinRange` 数据层支持，但编辑器目前不单独开控件：前者由公共闸门兜底；后者不要另外写条件，要放宽距离就在「距离」字段填更大的值（写入的是 `override.range`，不是 `withinRange`）。

## 判定口径

- 目标属性 = 物件互动档案的 `tags` + 锁具自动属性（`物理锁具` / `电子锁具`）
- 发起者标签 = `PC.tags`（现在存角色卡「途径/职业」栏；没有物品栏，`打火机` 这类标签先临时写在这里）
- **有试玩**：先查角色/行动点/物件启用/隐藏/距离/视线，再查全部条件（含 `withinRange`）
- **没有试玩**：不查距离/视线/行动点，但仍查目标标签/状态、目标启用、发起者标签；`withinRange` 跳过
- 距离优先级：显式传入的 `range` > 映射的 `range` > 默认 1 格
- 条件不满足时，预览和确认落账都返回同一句 `describeUnmet()`；确认失败不写状态、不写事件、不扣行动点

## 旧档与状态迁移

- `checkWorld()` 拒绝：非 0..200 整数的 `range`、不认识的条件类型、空的目标状态列表、越界状态、非整数的 `withinRange`
- `repairWorld()` 清掉坏 `range`；条件只要有坏条目（空标签、越界状态、坏 `withinRange`、未知类型等）就删整条动作映射并提示，绝不留一条“有效果但无条件”的动作；重复状态去重，重复条件去重，越界状态按坏条件处理
- `setObjectStates()` 迁移 `targetStateIn` 的序号；**如果某个条件引用的状态全被删掉，就删掉整条动作映射**，而不是让动作从「必须裂开」悄悄变成「无条件可用」，并 toast 说明

## 不做什么

- 全局动作层条件（`action-rules` 覆盖层）
- `ActionRange` 的 `shape` / `targetLimit`
- 物品栏/装备来源；`actorHas` 先吃角色标签
- ME、技能来源、技能 → 动作 `actionId`
- 拖/抛/攀爬执行器、玩家窗口、心理层、多目标

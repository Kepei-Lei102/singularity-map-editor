# 互动的三种效果面（C 方案）v0.1

## 结论

**不按“层”把动作归类，按“效果面”分。** 一个结算器，三种效果：

| 效果面 | 写到哪里 | 谁处理 |
|---|---|---|
| 物理 | 物件 `state`、位置 | `applyTransitions()` |
| 信息 | 角色发现记录（`secret.discoveries`） | `applyKnowledge()` |
| 心理 | NPC 态度／情绪（待开发） | 只有类型，没有实现 |

理由：同一个动作常常同时给信息和改状态（摸墙＝触感信息，推墙＝物理变化）。做成互斥的层，会逼着给动作选边，判定逻辑还得写两遍。

## 类型

```ts
type EffectKind = 'state' | 'knowledge' | 'attitude';
interface KnowledgeEffect { kind: 'knowledge'; mapId; objectId; secretId; to: string[]; tier; at? }
interface AttitudeEffect  { kind: 'attitude'; npcId; from?; to; label? }   // 预留
type AnyEffect = StateTransition | KnowledgeEffect | AttitudeEffect;
effectKind(e)            // 没有 kind 的老状态转移按 'state' 处理
applyTransitions(map, e) // 只处理 state
applyKnowledge(map, e)   // 只处理 knowledge，返回写了几条
```

## 已经迁移的

`autoReveal()` 原来自己往秘密里写 `discoveries`，现在改成收集 `KnowledgeEffect[]`，交给 `applyKnowledge()` 统一写。行为不变（按角色记、不随换组转发），但只有一处写入口了。

## 观察和触感归哪

- **观察**：信息效果的判定属性。它不改变世界，只决定“揭不揭示”。动作卡可以是无目标／指向自身。
- **触感**：需要物件多一个 `surface`（材质、温度、粗糙、软硬）。信息效果按它决定揭示什么。
- **视野**：距离是常数 1.56，不挂观察；观察只管“看清／发现细节／秘密”。这样两者不会打架。

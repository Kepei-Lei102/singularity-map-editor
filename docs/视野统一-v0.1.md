# 视野：统一到规则书 v0.1

实现：`src/scene/sight.ts`，测试：`scripts/sight.test.mjs`。老实现仍在 `src/scene/perception.ts`，尚未切换。

## 口径（全部来自规则书）

| 项 | 值 | 依据 |
|---|---|---|
| 视野预算 | **1.56** | 「无障碍视野就是15格。15*0.1=1.5，＜1.56」 |
| 每格基线消耗 | **0.1** | 「无障碍的情况下，系数值为最低值，0.1」 |
| 草丛这类 | 设计师填常量（0.8、窗 0.5、浓密 2＝隐身） | 「产生的障碍系数由关卡设计师自行设计」 |
| 预算断点 | 累计 **> 1.56** 就看不见 | 15 格 1.5 看得见，16 格 1.6 看不见 |
| 眼高 | 身高 × **0.93** | 由身高推，蹲／趴锁死 |
| 站姿默认身高 | 男 **173**、女 **164**、未填 **170**（厘米） | 作者定 |
| 蹲／趴眼高 | **0.9 / 0.3**（锁死，不按身高） | 作者定 |
| 视野锥 | D20 区 **120°**；D100 区 **60°** | 「非恐+完全光亮是120度」；D100＝恐怖区 |
| 朝向 | **4 向**，不做斜向 | 作者定 |
| 30° 档 | **不做** | 作者定（太少用） |

## 两套遮挡算法

1. **常量**：物件或地形显式给系数（草丛 0.8、窗 0.5、浓密 2）。优先级最高。
2. **按身高**：物件没给系数时，`高度 ≥ 眼高 → 挡死`；否则按 `高度 ÷ 眼高` 折算成消耗。
   桌 0.75m ÷ 眼 1.61m ≈ 0.47，矮凳 0.2m 更小。性质挡死（`physical.blocksSight`）优先于折算。

取两者较高者：性质可以压过高度，显式系数可以压过一切。

## 为什么不能直接用老算法

老算法（`src/scene/perception.ts`）三处与新口径不同：

1. 每格 0.1 的基线被当成 0，距离只有靠 2 以上的地形才衰减。
2. 阈值是「累计 ≥1 就断」，不是预算 1.56。
3. 累加**不含目标格**，所以会多算一格（实际能看 16 格）。

新模块 `canSee()` 累加含目标格：15 格 = 1.5 过，16 格 = 1.6 断，与规则书一致。

## 已经接进迷雾了，带一个临时开关

1. 字段：`PC` 加 `sex`、`heightCm`；`Token` 加 `facing`、`stance`。都可选，旧档不受影响。
2. `perception.withVision(next, prev, algo)` 接受 `'rulebook' | 'legacy'`，`detailedVisionRulebook()` 走 `sight.ts`。
3. 左侧面板「显示迷雾」旁边多一个勾选 **「规则书视野」**，默认开。切换会立刻重算迷雾（`setVisionAlgo()`），不用改世界。
4. 这是对照用的临时开关，确认观感后删掉。

实测：在封闭的前厅里两套算法看起来几乎一样（薄墙挡死、房间小）；差异要到空地／草坪这类开阔处才明显。

## 朝向操作（战斗中双击确认）

1. `Token.facing` 记 4 向；`trialMove()` 先算方向。
2. **战斗模式**：方向与当前朝向不同 → 只转身、不移动（再按同方向才走），等于多一次确认；不动行动点。
3. **自由行动**：不确认，朝向跟着走。
4. **缠斗**：紧邻一格内有别人（`ENGAGED_RANGE = 1`）时，一回合只能转身一次；`trialEndTurn()` 清掉这个记录。
5. 选中棋子的「看清三档」染色也换成规则书视线（`render.ts` 用 `visionOf`），不再用老的 `sightCosts`。

## 子格视线

1. 主格衰减仍按规则书整格系数算，射线不按 1/3 拆分累加。
2. 细分格额外用 1/3 精度判断射线有没有穿过**完全挡死**的小块（`visionCoef ≥ 99`，比如墙）；起点和目标子格自身不算。
3. `visionDetailOf()` / `partyVisionDetailOf()` 维护 `sub` 可见性；`detailedVisionRulebook()` 直接使用。
4. 点判定统一走 `visiblePoint()`：开门、判定可见性、滑块、看清范围都不再走老的 `sightCosts`/`seesPoint`。
5. 老口径（`legacy`）也接了同一套子格挡死检查，只影响遮挡，不影响衰减。

## 还没做

1. **角度靠 `facing`，但还没有操作**：只做了 4 向锥；「第一次按方向转身、第二次移动」和「被缠斗时只能转身一次」都还没接。
2. 30° 档、蹲趴的移动限制（蹲着走多慢）都还没做。
3. 子格衰减不做细分：草丛/窗这类系数仍按整格；如果以后需要小格渐变，再单独开版。
5. `facing`／`stance` 目前没有 UI 入口，只能由代码写入。

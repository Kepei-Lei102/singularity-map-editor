# 视野：统一到规则书 v0.1

实现：`src/sight.ts`，测试：`scripts/sight.test.mjs`。老实现仍在 `perception.ts`，尚未切换。

## 口径（全部来自规则书）

| 项 | 值 | 依据 |
|---|---|---|
| 视野预算 | **1.56** | 「无障碍视野就是15格。15*0.1=1.5，＜1.56」 |
| 每格基线消耗 | **0.1** | 「无障碍的情况下，系数值为最低值，0.1」 |
| 草丛这类 | 设计师填常量（0.8、窗 0.5、浓密 2＝隐身） | 「产生的障碍系数由关卡设计师自行设计」 |
| 预算断点 | 累计 **> 1.56** 就看不见 | 15 格 1.5 看得见，16 格 1.6 看不见 |
| 眼高 | 身高 × **0.93** | 由身高推，蹲／趴锁死 |
| 站姿默认身高 | 男 **173**、女 **164**、未填 **170**（厘米） | 作者定 |
| 蹲／趴眼高 | **0.9 / 0.3**（锁死，不按身高） | 作者定 |
| 视野锥 | D20 区 **120°**；D100 区 **60°** | 「非恐+完全光亮是120度」；D100＝恐怖区 |
| 朝向 | **4 向**，不做斜向 | 作者定 |
| 30° 档 | **不做** | 作者定（太少用） |

## 两套遮挡算法

1. **常量**：物件或地形显式给系数（草丛 0.8、窗 0.5、浓密 2）。优先级最高。
2. **按身高**：物件没给系数时，`高度 ≥ 眼高 → 挡死`；否则按 `高度 ÷ 眼高` 折算成消耗。
   桌 0.75m ÷ 眼 1.61m ≈ 0.47，矮凳 0.2m 更小。性质挡死（`physical.blocksSight`）优先于折算。

取两者较高者：性质可以压过高度，显式系数可以压过一切。

## 为什么不能直接用老算法

老算法（`perception.ts`）三处与新口径不同：

1. 每格 0.1 的基线被当成 0，距离只有靠 2 以上的地形才衰减。
2. 阈值是「累计 ≥1 就断」，不是预算 1.56。
3. 累加**不含目标格**，所以会多算一格（实际能看 16 格）。

新模块 `canSee()` 累加含目标格：15 格 = 1.5 过，16 格 = 1.6 断，与规则书一致。

## 还没做的

1. **没接进迷雾**：`perception.ts` 的 `partyVision` 仍走老算法，切换会改变现有存档的可见范围。
2. **Token / PC 还没有 `facing`、`stance`、`sex`、`heightCm` 字段**。现在靠 `viewerOf()` 传参，接 UI 时要补字段。
3. 角度只按 4 向锥；没做「转身要按两次」那套操作。
4. 30° 档、蹲趴的移动限制（蹲着走多慢）都还没做。

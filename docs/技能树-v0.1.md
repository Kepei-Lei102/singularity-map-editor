# 技能树 v0.1：树形解锁与发动入口（2026-11-23）

A 步只做“树形浏览/解锁 + 发动入口守卫”，不接技能效果、判定口径和动作卡。

## 数据

树是**运行时派生**，不写进 `world.json`，`PC.skills` 仍是唯一持久化状态：

```ts
interface SkillTreePathway {
  pathway: string;
  current: boolean;         // 角色当前途径
  unlockedCount: number;
  totalCount: number;
  groups: { name: string; skills: SkillDef[] }[];
}
```

`buildSkillTree(pc, {levelUp})` 建在现有 `groupSkills()` 上：

- `levelUp: true`：所有节点，用于主持人解锁；
- `levelUp: false`：只留已解锁的途径/组，用于发动面板；
- 未知技能 id 不计数，不改档。

当前数据：`SKILL_LIBRARY` 198 条 = 自动生成 16 条途径 / 194 条 + Ian 手工 4 条；`SKILL_DATA` 分组是通用 64 / 正位 65 / 逆位 65。所有技能都是序列 9，没有序列 8 或前置依赖边。

## 界面

- **队伍面板**：技能树按“途径 → 技能组 → 技能”折叠展开；勾选/取消直接改 `PC.skills`；搜索按名字/组/说明过滤；每条途径显示已解锁计数，当前途径有标签。
- **技能发动面板**：用同一棵派生树；只显示已解锁节点。升级视图只显示锁定名字，锁定按钮禁用，不能发动。
- **玩家窗口**：收到的仍是 `PublicSkill[]`，在玩家端按途径/组分组显示；当前途径有标签，其他途径显示“换途径 +1 ME”。玩家端独立入口不经过完整技能库；玩家端分组只依赖 `PublicSkill`。
- **入口守卫**：`beginSkillCast()` 增加 `pc.skills.includes(skillId)` 检查；未解锁返回“没有解锁【X】”，不扣 ME、不建 `cast`、不立 focus。

## 边界

不做：

- 技能效果自动结算、D100/D20 判定口径结构化；
- 技能 → 动作 `actionId` 映射（私有侧）；
- 技能点/等级/前置技能；
- 行动点消耗、战斗内技能结算；
- 存档迁移或新的世界字段。

理由：194 条里绝大多数是见证者裁决型，`判定`/`动作解锁`在私档；公开仓库不能在技能树里写死这些映射。技能树先解决“看得见、解锁得对、锁定不能发动”。

## 测试

- `scripts/skill-tree.test.mjs`：198 条/17 条途径、树节点不丢、升级视图开合、当前途径、未知 id、玩家公开分组。
- `scripts/skill-tree-editor-ui.test.mjs`：真实挂载 198 个复选框、搜索、勾选写回 `PC.skills`；发动面板升级视图里锁定按钮禁用。
- `scripts/skills.test.mjs`：未解锁技能不能发动，不扣 ME/不立 focus/不建 cast。

## 以后

- 接判定时先定私档 `判定` 怎么随模组走（私档本地导入 / 加密包 / 双版本）；
- 接效果时从私有 `actionId` 映射和动作库效果列走，不在公开技能数据里写死；
- 真有序列 8/前置技能后，再给树数据加 `requires`，现在不预留假依赖。

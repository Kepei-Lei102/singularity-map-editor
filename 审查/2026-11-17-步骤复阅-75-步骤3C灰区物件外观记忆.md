## 焦点 1：整件快照语义

实现与确认的语义一致：

- `snapshot(o, texture?)` 在 `memory.ts:42-52` 存 `texture` 克隆和当前 `ghost`；`syncLayer` 对 `live`（`anyVisible(box,o)`）用 `objectTextureOf(source,o)` 当场生成整件快照（`memory.ts:97-108`），所以**物件只要有任意一格 fog=1，整件快照就更新成当前贴图/ghost**，灰区那部分也跟着换。
- 完全转灰后物件不在 `live`，旧快照由 `kept` 保留（`memory.ts:100`），换图/开关/移动都不会改灰区记忆；重新看见时 `live` 重新生成快照，换成新版。
- 探针：
  - 2×2 物件，1 格 fog1、其余 fog2，换成 texB：`seen.texture=texB`，玩家渲染 `drawImage` 两张 B（实时 + 灰区快照）。
  - 整件转灰后换成 texA：记忆仍是 texB，玩家媒体表只有 texB，渲染只有一张 B。
  - 再整件 fog1：快照变 texA，渲染 A。
  - 开关同理：部分可见开态 → 记忆 `ghost:true`；转灰后改成关 → 记忆仍是开态虚线；重新看见 → 关态实心图。
- 测试 `objectmemory.test.mjs:117-124` 覆盖部分可见换图；`:89-115` 覆盖转灰保持旧图和重新看见换新；`:126-136` 覆盖 ghost。确认无 P2。

## 焦点 2：渲染

- 灰区 resolver 完全来自 `presented.seen.objects`：`render.ts:684-686` 建 `seenTextures`，`:687-691` 把它传给 `drawObjects` 和标签（`:734-743`）；不查当前 `map.groups`。实时层仍走 `liveTextureOf`（`:678-682`）。
- 贴图 + ghost 同时存在时 ghost 优先：`drawObject` 先判断 `ghost`（`:231`），ghost 分支只画虚线、不画贴图/底色（`:235-242`）；测试 `objectmemory.test.mjs:126-136` 和探针都确认 `drawImage=0`、有 `strokeRect`、无物件底色。
- 部分可见：实时层裁剪 fog1，灰区裁剪 fog2；2×2 部分可见 ghost 探针是两张虚线（实时 + 灰区）、无图；普通贴图是两张 B。裁剪正确，不会把整张图铺到 fog1。
- 标签：灰区记忆标签用快照 resolver，部分可见测试 `objectappearance.test.mjs:181-206` 已验证有图时不叠 `★`。浮签 `drawTag` 只在非玩家选中/悬停路径使用当前贴图，不经过灰区记忆。
- `fromMemory`（`render.ts:381-388`）剥掉 `texture`，保留 `ghost`；`rest` 还带 `identity/stateLabel` 等 MapObject 没有的额外字段，但渲染不读它们，无害。**剥 `texture` 本身没有测试咬合（见 P3-8）。**
- 一个小遗留（P3-9）：灰区 ghost 物件如果快照里也有 texture，`textured` 仍为 true，所以标签被当成“有图”处理：不叠图标、走暗描边。body 确实是虚线无图，这符合 ghost 优先；但标签口径没有测试，也没明确 docs 说明。

## 焦点 3：玩家载荷/媒体

- `playerMap` 的 `seen.objects` 先筛“任意 fog（1/2）”（`sync.ts:267-270`），再走 `playerSeen`；`playerSeen` 只对未辨识抹 `name/icon/stateLabel`（`identity.ts:31-34`），`texture/ghost` 全保留。测试 `objectmemory.test.mjs:169-178` 覆盖未辨识仍有外观。
- `playerWorld` 的 `usedTextures` 加入 `pm.seen.objects[*].texture.mediaId`（`sync.ts:210-214`）；测试/探针确认玩家媒体表只带用到的图，没用的 texC 不出现。
- `deleteMedia`（`actions.ts:1045-1059`）同时清 `m.groups`、`m.seen.groups`、`m.seen.objects`、各 `views[*].seen.groups` 和 `views[*].seen.objects`；测试 `objectmemory.test.mjs:138-152` 验证两处记忆都清掉、玩家媒体表为空、灰区回退彩色方块。
- 旧记忆贴图不在当前 `world.media` 时，`playerWorld` 的媒体表自然不带它，玩家渲染会走 `imageOf` 空回退彩色方块；这与“旧工程还能读”的 schema 口径一致，但目前没有“旧媒体缺失时灰区实际渲染”的测试（P3-11）。

## 焦点 4：sameSeen / staleMemories / mergeLayers

- 签名归一在 `memory.ts:28-31`：`mediaId~fit(默认 fill)~opacity(保留三位)`；`sameSeen`（`:54-59`）比较这个签名和 `!!ghost`。测试 `objectmemory.test.mjs:217-229` 验证 `{mediaId:'texA', opacity:1}` 与默认版相同、texB 和 ghost 变化为不同。
- `staleMemories`（`:299-304`）对“当前不可见”的物件用当前 `snapshot(o, objectTextureOf(...))` 比较；贴图/ghost 变化会 stale，灰区仍保持旧快照。测试确认换图后 stale、重新看见后不 stale。
- `mergeLayers` 的物件按 `objectRevs` 取最新整件快照（`vision.ts:75-81`），`cloneLayer` 是 JSON 深拷贝，texture/ghost 会跟着走；测试 `objectmemory.test.mjs:180-194` 验证多视野取 texB + ghost true。
- 没有发现“旧记忆永远 stale / 永远不更新”的循环：同步时只在 live 可见时生成当前快照，完全转灰就停在旧快照；`objectRevs` 在可见时更新，合并取最新。P3 级的限制是：签名只看 mediaId，不看媒体文件 key/版本；同一 mediaId 的内容被替换（存储名变了）时，灰区不会识别成新版本，仍按当前文件加载。这个问题在记忆贴图组里本来就有，3-C 沿用。

## 焦点 5：deleteMedia 与 schema

- 记忆物件旧媒体允许缺失：`seenObjects` 的 `textureSpec` 只校验 `mediaId` 合法、`fit`、`opacity`（`schema.js:374-389`），不查 `world.media`；实时组仍由 `schema.js:830-833` 对 `m.groups` 查媒体存在。测试 `objectmemory.test.mjs:196-215` 覆盖：playerWorld 通过、记忆旧 media 缺失通过、坏 fit/opacity/ghost 报错。
- `textureSpec` 抽取后实时组和记忆组共用结构校验；实时组媒体存在性检查没有丢。
- `deleteMedia` 的 views 清理测试覆盖 `m.views.a.seen.objects`；实时物件组照旧只清 texture、不删空组（P3-5）。
- 结论：这个口径与既有记忆组一致，我认为对；不需要给记忆物件单独加“媒体必须存在”的限制。若将来要实现“灰区旧图仍能显示”，应把媒体文件 key/版本纳入记忆，而不是靠 schema 卡媒体存在性。

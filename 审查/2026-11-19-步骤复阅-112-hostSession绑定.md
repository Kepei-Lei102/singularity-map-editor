## 注册表语义

- 初始化逐字等价：同一 `ts-player-bindings-${SESSION}` key、同一 `projectContext()`、同一 `typeof pcId === 'string'` 过滤、同一 try/catch。
- `saveBindings()` 逐字等价：`Object.fromEntries([...players].filter(([, p]) => !p.trialContext).map(([key, p]) => [key, p.pcId]))`，试玩 binding 不落盘这条保持。
- `bindPlayer` = 旧 `players.set(binding, { pcId, context: projectContext(), ...(trial ? { trialContext } : {}) })`；`trial ? worldContext() : undefined` 传入时等价。唯一边界差异：新代码用 `trialContext` 真值判断是否展开，而 `worldContext()` 一定以 `${epoch}` 开头、非空，所以当前不可观察。
- `unbindPlayer` / `clearPlayerBindings` 内部持久化；sync 里所有 `saveBindings()` 调用已删除，grep 无遗漏。
- `playerEntry/hasPlayerBinding/playerEntries/playerBindingKeys/trialBindings/pcIdForBinding` 都是薄读 helper；`players` 不再从 sync 可见。
- **Map 迭代中删当前项安全**：`send`/`clearTrialWindows` 的 `unbindPlayer` 删除当前 entry 后继续迭代，JS Map 语义是安全的；`saveBindings` 内部先 `[...players]` 拷贝，不会破坏外层迭代。`reset`/`onProjectReplaced` 改用 `playerBindingKeys()` 快照，避免 live iterator 被 `clear` 影响。

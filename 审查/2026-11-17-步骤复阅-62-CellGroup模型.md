## P2

### P2-1 `reshapeMaps` 裁掉物件后，`groups` 里的 `objectId` 悬空

- 位置：`src/runtime/actions.ts:731-732`（物件先移动、再过滤出界物件）与
  `:702-708`（groups 只平移 `cells`，不检查 `objectId`）。
- 复现（实测，Node bundle）：
  1. 10×10 图，物件 `edge` 在 (9,9)，1×1；
  2. `groups:[{ id:'g-edge', name:'边缘贴图', cells:[fineKey(27,27)], objectId:'edge' }]`；
  3. `reshapeMaps([map.id], 0, 0, -5, -5)` 把图缩到 5×5，`edge` 在 9,9 被过滤掉；
  4. 结果图 `objects: []`，但组仍是
     `{ id:'g-edge', cells:[], objectId:'edge' }`；
  5. `checkWorld` 报
     `工程文件有问题：地图「大图」.groups 找不到物件 edge`。
- 缩图本身成功，`reshapeMaps` 不调用 `checkWorld`，所以 UI 当下不会报；
  之后导出/保存/导入才炸。对作者来说是“只是改了一下尺寸，世界就不能导出了”。
- 建议：在 `m.objects = m.objects.filter(...)` 之后，同步清理
  `m.groups` 中 `objectId` 已不在 `m.objects` 里的组（删组或清掉 `objectId`），
  memory 组可只清引用；并补一条“物件在裁掉的边上 + 缩图”的测试。
- 影响面：这是模型/校验层的问题，不依赖后续渲染/UI；应在本段修掉。

## P3

### P3-1 `reshapeMaps` 的 groups 平移测试用的是 (0,0) 格，咬不住旧宽/新宽公式

- 位置：`src/runtime/actions.ts:702-705`；`scripts/sliding.test.mjs:204-219`。
- 实测 mutation：把 `oldWidth * 3` 改成 `W * 3`，`sliding.test.mjs` **63/63 全绿**。
- 原因：测试组只放了源图 (0,0) 的 key，`key = 0` 在两个公式里都先算 x=0/y=0，
  再按新宽高生成同一个 key，区分不了“旧宽高取坐标”。
- 建议：源组放一个非零格（如 (3,2)），再缩/扩后断言新 key；顺便断言
  memory `seen.groups` 也平移（目前 sliding 只断言 `m.groups`）。

### P3-2 `reshapeMaps` 会把整组都裁空的 groups 留下来

- `shiftGroups` 对出界格 `flatMap` 丢弃，但不删空组，也不删 `objectId` 已悬空的组；
  缩图后可能出现 `cells: []` 的组。schema 允许空 `cells`，所以不会报错，
  但后续 UI/渲染会拿到无包围盒的组（`groupBounds` 返回 null）。
- 与 P2-1 同属清理缺口，但空组本身不导致校验失败，按 P3。

### P3-3 `groupBounds` 只跳过非整数/负数，不跳过越界 key

- 位置：`src/core/grid.ts:57-73`；测试 `scripts/cellgroup.test.mjs:111-117`。
- 实测：`groupBounds(4, [fineKey(4,0,0), 999999])` 返回
  `{x0:0,y0:0,x1:4,y1:83334}`；因为函数只有 `width`、没有 `height`，
  `999999` 是非负安全整数，不触发跳过，直接算出巨大的 y。
- 当前测试自己也用了超出地图高度的 key（m 是 4×3，却给了 y=4、y=5 的 key），
  并接受 `y1=5`。所以“无效 key 静默跳过”只对 `-1 / 1.5` 生效，对越界安全整数不生效。
- schema 会挡住保存的组，但 helper 是导出函数；调用方若拿到脏数据会得到巨大包围盒。
  建议加 `height` 参数并检查 `key < width*3*height*3`，或明确文档只接受已校验数据。

### P3-4 `shiftGroupCells` 不校验负 key/小数 key，负 key 可能被“移进”地图

- 位置：`src/core/grid.ts:86-95`。
- 实测：`shiftGroupCells(4, 3, [-1], 1, 1)` 返回 `[fineKey(4,1,1)]`（即 key 0），
  把一个非法负 key 当合法格移进地图；小数 key 会产生小数 key（schema 之前无检查）。
- 当前 schema 阻止保存这种 key，`reshapeMaps` 的 inlined `shiftGroups` 也不复用这个
  helper；按 P3 补 `Number.isSafeInteger(key) && key >= 0` 的跳过，和 `groupBounds` 一致。

### P3-5 `objectFootprintCells` 不校验 anchor 的小数/负值，会生成小数 key

- 位置：`src/core/grid.ts:78-84`；测试只测了合法 `anchor:{1,2}`。
- 实测：`objectFootprintCells(4,3,{x:0,y:0,w:1,h:1,anchor:{x:1.5,y:0}})`
  返回 `[1.5, 2.5, 3.5, …]` 这类小数 key；schema 的 anchor 要求 0–2 整数，
  正常编辑路径不会产生，但 helper 本身没有兜底。
- 按 P3；若要作为渲染/贴图入口，应先校验 anchor 为 0/1/2 或 `Math.trunc`。

### P3-6 `duplicateMap` 的 `objectId` 重映射用非空断言，源组悬空时会静默丢引用

- 位置：`src/runtime/actions.ts:808`。
- `objectIds.get(g.objectId)!` 在源 `objectId` 找不到时得到 `undefined`，
  展开后 `objectId: undefined`，schema 视为“没有 objectId”，组静默变成地面组。
- 正常源图过 `checkWorld` 不会出现；但复制前若世界是旧数据/未经校验，会掩盖错误。
  按 P3 改成“找不到就清掉引用并记录/拒绝复制”，不要用 `!`。

### P3-7 `mergeLayers`/`syncLayer` 还不处理 `seen.groups`，本轮明确未接 syncMemory

- `emptyVision`、`cloneLayer` 已带 `groups`，但 `mergeLayers` 的 `out` 只合并
  cells/architecture/objects，`seen.groups` 始终是空；`syncLayer` 也不写
  `seen.groups`。
- 这轮交办说明“不接 syncMemory”，所以不是本轮 P2；但它意味着个人的记忆组快照
  目前只存在于迁移/手工数据里，individual/grouped 模式下一次同步会被空数组覆盖。
  接 syncMemory 时必须补 merge/clone 的 groups，并在测试里覆盖。

## 重点复检逐条

1. **schema 是否过严/过松**：
   - 旧 v2 没有 `groups`：迁移补数组，`checkWorld(..., true)` 通过（测试和实测都过）。
   - 记忆组缺 media：`seen.groups` 只查 `safeId`/结构，不查媒体存在，实测通过；
     这是有意的“老贴图不在了也能读记忆”。
   - `objectId` 引用：`m.groups` 要求本图 objects 里存在；`duplicateMap` 会重映射；
     **`reshapeMaps` 裁物件后不清理（P2-1）**。
   - 偏松处：`m.groups` 的 `texture` 和 `objectId` 可同时存在，没有二选一/优先级校验；
     当前模型未接渲染，先记 P3 边界。
2. **迁移是否漏 seen/views**：`m.seen.groups`、`views[*].seen.groups` 都补了，
   `emptyVision`/`cloneLayer` 也带 groups；`checkWorld(migrated=true)` 只要求
   migrated 后存在，实测迁移后通过。**player payload 不经过 `checkWorld`**，
   playerMap 也不带 groups，所以不会因为“缺 groups”被误伤。
3. **reshape 的 key 公式**：公式本身对（旧 `oldWidth*3` 取坐标，再按新 `W*3` 落 key），
   但测试用 (0,0) 格咬不住（P3-1）；`reshapeMaps` 还漏了 `objectId` 清理（P2-1）。
4. **复制 map 的 objectId 重映射**：`duplicateMap` 有 `objectIds` 映射，测试断言
   `copy.groups[0].objectId === copy.objects[0].id`，mutation 去掉重映射会 fail；
   正常路径没漏。源组悬空时用 `!` 静默丢引用（P3-6）。
5. **helper**：
   - `groupBounds` 空组 null、非整数/负 key 跳过正确；但越界安全整数不跳过（P3-3）。
   - `shiftGroupCells` 正常出界格丢弃正确；负/小数 key 没校验（P3-4）。
   - `objectFootprintCells` 锚点偏移和边界裁剪正确（测试：1×1+anchor 得 9 格、
     2×2 在 4×3 边界裁剪得 9 格），小数 anchor 没校验（P3-5）。
6. **玩家载荷泄密窗口**：
   - `playerMap` 是显式构造对象，**没有 `groups`**，`seen` 也没有 `groups`；
   - `playerWorld` 用 `...w` 但随后 `maps: [pm]` 覆盖，World 本身没有 groups；
   - `send` 的 `world` 分支对每个 player 走 `playerWorld`，不会把原始 world 广播；
   - 实测 `JSON.stringify(playerWorld(...))` **不含 `"groups"`**。
   - 本轮没有“groups 已存在但玩家载荷没过滤”的泄密窗口；等接 render/syncMemory 时
     仍要记得 groups 是主机的，不可直接进 playerMap。

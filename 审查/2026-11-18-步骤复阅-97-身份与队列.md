## queued 口径

- 正常路径：`totalFiles - startedFiles - failedFiles` 正确。失败且没 start 的 key 从排队扣掉；失败且已 start 的 key 进 `failedStartedFiles`，不再从 queued 扣（它已经因 started 被扣过），不会重复。
- `failedFiles` 只在 `files.has(key)` 为 false 时加，所以失败后 start 的恶意序列还会再扣一次 started，`max(0)` 兜底，但会让 queued 提前归零。
- `failedKeys` 对同一 key 的重复 fail 去重够用（before start）；但只按 key，不区分“fail after ended”，恶意/异常下会重复影响 inFlight。
- **P3 边界**：
  - 取消（cancel）在 start 前发生：host serve 直接 `continue`，不发 asset-fail，`failedFiles` 不加，这个 key 会一直算 queued 到 flow 结束。
  - 取消在 start 后发生：host serve 不发 end 也不发 fail，`startedFiles` 已加、`endedFiles/failedStarted` 没加，inFlight 会一直算这个 key 到 flow 结束。
  - `asset-fail` 的 key 不在 request 里（恶意 host/异常）：`failedFiles` 仍会加，`max(0)` 让 queued 提前归零；这是防御缺口。
  - `asset-end` 对未 start 的 key 不会增加 endedFiles（`files.get` 不存在直接 return），正常 serve 也不会发，安全。

## inFlight 口径

- `inFlight = max(0, startedFiles - endedFiles - failedStartedFiles)`；正常单文件是 start 后1、end/fail 后0，能表示“已开始、未结束”的文件，包含 start 后还没 chunk 的窗口。
- 一个 batch 32 key 全部 start 后 inFlight=32 在语义上合理；但当前 `serveAssetRequest` 是每个 key 完整 start→chunk→end 后才处理下一个，正常单 flow 同时最多1，不会出现32。多 flow/多 binding 才累加。
- `asset-end` 正常只对已 start 的文件发生；恶意 end 未 start 不会加 ended。**P3**：恶意重复 end 会 endedFiles++ 两次，`max(0)` 防负但会低估同 flow 其他 inFlight；ended 后再 asset-fail 会再 `failedStartedFiles++`，双重扣减；正常 serve 不会。
- **P3**：cancel after start、end send false、玩家删除导致 send false 时没有 fail/end，inFlight 会挂到 flow 结束；一个长 batch 里可能长时间显示“1个传输中”，其实已停。

## P3

1. **queued 边界**：cancel-before-start（无 fail）仍排队；恶意 unknown-key fail 会提前扣空；失败后 start 会双重扣减。正常 host 不走这些路径。
2. **inFlight 边界**：cancel-after-start、send false、end send false 会把已停文件挂到 flow 结束；恶意重复 end/fail 会低估同 flow 其他文件；正常 serve 不走。
3. **identity 时效**：改名/删角色后名字陈旧；恢复的 binding 没有名字只能回退 pcId；名字进入 stats，未来若广播 stats 会泄露。
4. **Dock**：names 少于 players 时会漏人；inFlight 文案与“正在传”重复；长文本换行/高度跳；无渲染测试。
5. **测试**：ended/failedStarted/cancel后inFlight/多binding/identity生命周期/Dock 全是0红；5字节太小。
6. **旧缺口仍在**：requestId 复用覆盖 flow、serve load 永不 settle 的 flow 残留、rate 仍是累计平均、22块/s 通知整 Dock 重渲染、listener 吞错。
7. **账本仍缺**：没有每 binding 的队列/在途上限、没有 broadcast key 过滤、没有瞬时/窗口速率、没有 lastProgress/age；identity 有了，但调度器还缺这些阈值。

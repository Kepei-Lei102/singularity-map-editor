## P2

### P2-1 灰区没有记忆贴图：`seen.groups` 不传也不画，玩家会看到贴图突然消失

- 位置：`src/runtime/sync.ts:253-262`（`seen.groups: []`）、
  `:272-283`（`groups` 只保留 `L.fog === 1` 的格子）、
  `src/scene/render.ts:40-41`（`drawCellGroups` 只读 `map.groups`）。
- 实测（Node bundle）：
  1. 10×10 图，组两格 (3,3)/(24,24)，初始 fog 全 1；`playerWorld` 两组格全发，
     `seen.groups: []`；
  2. 把这两格所在的 fog 改成 2（记忆区）；
  3. `playerWorld` 的 `maps[0].groups` 变成 `[]`，`seen.groups` 仍是 `[]`；
  4. 单独构造只带 `seen.groups` 的 map 调 `drawCellGroups`，`drawImage` 调用数
     为 **0**——即使有记忆组，渲染器也不画。
- 结果：玩家看见贴图 → 该区域转为灰色记忆 → 贴图消失，只剩地形/材质。
  这不是某个角落的轻微瑕疵，是“实时贴图 / 灰区没有记忆贴图”的整段断层。
- 修法要两半一起做：
  - `mergeLayers`/`syncLayer` 补 `seen.groups`（本段明确没做）；
  - `playerMap` 不再硬写 `seen.groups: []`，按记忆规则过滤；
  - `drawCellGroups` 接受/绘制记忆组（可能要单独的 `drawSeenCellGroups`，
    且只画 fog===2 的格子）。
- 交办明确说这种断层不要只当 P3，故标 **P2**。

### P2-2 玩家包里的 `bounds` 是整组包围盒，泄露看不见部分的形状/位置

- 位置：`src/runtime/sync.ts:274-282`；测试
  `scripts/material.test.mjs:218-233` 把 `{x0:3,y0:3,x1:25,y1:25}` 固定为期望。
- 实测：组格子 (3,3) 与 (24,24)，(24,24) 不可见；玩家包只发可见格
  `[fineKey(3,3)]`，但 `bounds` 仍是整组的 `{x0:3,y0:3,x1:25,y1:25}`。
  玩家只看见 (3,3) 一格，却知道整组延伸到 (24,24)。
- 这是有意的“只看见一角时不重新拉伸贴图”，但对玩家是信息泄露：
  - 能推断贴图组覆盖到未探索区域；
  - 组名/`id` 也原样带过去（见 P3-9）。
- 需要产品决定：
  - 整组全可见时才发全 bounds；
  - 或只发可见部分 bounds 并接受纹理拉伸；
  - 或另发“纹理原点偏移”而不是整组范围（仍可能泄露尺寸，需要评估）。
- 测试目前把泄露当正确行为，修的时候要改这条断言。

## P3

### P3-1 `bounds` 不进 schema 校验，reshape 平移后也不裁到新图

- `CellGroup.bounds` 是可选字段，`schema.js` 的 `cellGroup` 完全没有校验形状；
  `checkWorld` 接受 `{x0:-999,y0:-999,x1:999,y1:999}`（实测）。
- `reshapeMaps` 对 `bounds` 只加 `left/top`（`actions.ts:706`），不裁到新宽高；
  实测 10×10 缩到 5×5 后，组 bounds 仍是 `{x0:3,y0:3,x1:25,y1:25}`，
  即 `x1=25 > 新图 fine width 15`。
- 后果：导入/旧数据可带脏 bounds，`drawCellGroups` 直接拿 `g.bounds` 铺图；
  改尺寸后 bounds 也可超出地图。建议 schema 校验 `x0≤x1, y0≤y1` 且在
  `width*3/height*3` 内，reshape 时裁到新图，或干脆不持久化 `bounds`
  （只作为 player 派生字段）。

### P3-2 删除物件/改尺寸/删组时，`seen.groups` 不跟着清理

- `deleteMapObject` 只过滤 `m.groups`（`actions.ts:198`），不动
  `m.seen.groups`；实测删物件后 `seen.groups` 里仍留着 `objectId:'obj'` 的组。
- `reshapeMaps` 只过滤 `m.groups` 的 objectId（`:738`），`m.seen.groups`
  只平移不过滤（`:709`）。
- 现在 schema 不校验记忆组的 `objectId`，所以不报错；但 P2-1 一旦把记忆组接上
  渲染，就会画出引用了已删物件的组。建议所有删除/裁剪路径统一清 `seen.groups`。

### P3-3 生命周期的三个测试缺口：无地形格、媒体删图、reshape bounds

- 实测 mutation：
  - 去掉 `drawCellGroups` 里的 `terrainAtSubcell` 判断：**11/11 仍全绿**；
    测试名说“只画有地形的小格”，但组格子全在 floor 上，没有空格用例。
  - 去掉 `MediaPanel` 删媒体时清 `g.texture` 的代码：**全绿**，没有测试。
  - 去掉 `reshapeMaps` 的 `bounds` 平移：**全绿**，没有测试。
- 这三条都属于“功能在、测试不在”，补用例成本低；否则以后重构会把行为改掉。

### P3-4 `texture.ts` 的失败/回收/切换工程漏洞

- 缓存键是 `storageKey(mediaId)`，同 ID 换内容时 storage key 变了，旧图不会
  串到新图，这是对的。
- 但：
  - `failed.add(key)` 永久失败，没有重试入口；IndexedDB 瞬时失败或图片加载失败
    后，这个媒体在本次会话里再也不会尝试（除非 key 变化）；
  - 成功时 `URL.createObjectURL` 没有 revoke（只有 `onerror` revoke），
    `images` 也不淘汰，长时间换图/换工程会累积对象 URL 和图片；
  - `setMediaIndex` 跟着 store 当前世界走，但 `texture.ts` 的全局 `images`
    不随工程切换清空；
  - `textureImage` 在 `indexedDB`/`Image` 不存在时静默返回 null，没有通知，
    画布会一直不重画。
- 没有 `texture.ts` 的任何测试；`MapCanvas` 的 subscription 返回 unsubscribe，
  listener 本身没有泄漏（这点是好的）。

### P3-5 UI 的撤销粒度：名字/z/不透明度每敲一次各占一步

- `Txt`/`Num` 是受控组件，`onChange` 每次输入都直接调
  `renameCellGroup`/`setCellGroupZ`/`setCellGroupOpacity`（`Inspector.tsx:119-137`），
  每次 `update` 都是一步撤销。
- 拖涂的 batch 已经正确（测试 `beginBatch/endBatch` 一次撤销）；输入框没有
  blur/debounce 合并。按 P3；建议本地 state + blur/Enter 提交，或输入期间 merge。

### P3-6 上传途中删组/换工程会留下孤儿媒体

- `upload` 在 await `storeBlob` 后只检查 `worldContext()` 是否换工程
  （`Inspector.tsx:85-94`），**不检查组是否还在**；`update` 里先 `d.media.push`
  再找组，组被删了媒体仍进世界。
- 换工程时虽 return，不把媒体元数据写进世界，但 blob 已写进 IndexedDB，
  没有清理路径；同一文件重复上传也会生成多条媒体元数据。
- 按 P3；上传前记 group id，完成时找不到组就回滚媒体元数据/提示。

### P3-7 `groupId` 在切图/复制/撤销后可能悬空

- `groupId` 是全局 UI 字段，切地图、`duplicateMap`、删地图、撤销“删除组”后
  都可能指向不存在的组；`CellGroups` 面板会没有选中项，`groupPaint` 点击弹
  “先在右侧选一个组”（`MapCanvas.tsx:309-310`），不会崩，但交互上像坏了。
- 按 P3；在 `setUI` 切图/复制/删除路径里清掉或重映射 `groupId`。

### P3-8 玩家组名/id/贴图媒体名也会随可见组带过去

- `playerMap` 用 `{ ...g, cells, bounds }` 展开，组 `name`、`id`、
  `texture.mediaId` 都原样进玩家包；只看见一角也能看到“暗格”“密室地板”这类名字。
- `usedTextures` 只带可见组的媒体，这一点本段是对的，不会把隐藏组的图带过去；
  但名字本身仍是信息。按 P3，跟 P2-2 一起做产品取舍。

### P3-9 线上 asset 同步/记忆组同步仍未做

- 本地玩家窗口和主持人同源，能读同一个 IndexedDB，所以本段手工验证能显示；
  线上房间只带媒体元数据，没有分块传文件，异地玩家 `getBlob` 拿不到图，
  贴图会缺。`docs/贴图组-v0.1.md` 已写明，按 P3 记录。
- `mergeLayers`/`syncLayer` 的 `seen.groups` 也未接；这是 P2-1 的另一半。

## 重点复检逐条

1. **玩家载荷安全**：
   - 可见格过滤：`fog===1` 的格子会发，`fog===0` 的格子不发，实测和 mutation
     都咬；**但 `fog===2` 直接整组消失（P2-1）**。
   - 整组 `bounds`：**是完整组包围盒，泄露看不见部分的范围（P2-2）**；
     测试已把这个行为固定。
   - 物件组：`objectId` 组直接 `return []`，不铺地面，也不发；测试
     `imageCalls` 不含 `obj`，mutation 去掉过滤会 fail。**足够**。
   - 媒体：只带可见组用到的 `texture.mediaId`，测试 mutation 去掉过滤会 fail；
     隐藏组的 `secret-tex` 不进包，实测 `JSON.stringify` 不含。**本段正确**。
     `playerWorld.media` 过滤不影响本地播放（播放走显式 blob），线上 asset
     仍缺（P3-9）。
2. **texture.ts**：
   - 缓存键含 storageKey，同 ID 换内容不拿旧图；缓存命中/懒加载/加载完通知
     canvas 重画这套逻辑成立；
   - 失败永久、成功不 revoke、images 不淘汰、工程切换不清、无可用 IndexedDB
     时静默 null，均 P3-4；listener 本身无泄漏。
3. **drawCellGroups**：
   - z 排序、fill/contain、Path2D 裁剪、opacity、空组/无图/越界格跳过都成立；
     mutation 去掉 z 排序、objectId 过滤、fog 过滤都会 fail；
   - 无地形格的跳过没有测试（P3-3）；
   - 调用位置在地形/材质之后、高度暖色/网格之前，符合文档；高度会盖上一层
     半透明暖色，属于预期；不会盖住物件（物件更后）。
   - **它完全不读 `seen.groups`（P2-1）**；`g.bounds` 优先于 `groupBounds`，
     脏 bounds 会直接铺图（P3-1）。
4. **UI**：
   - 新建/选组/改名/z/绑图/铺法/透明度/删除/预览路径齐全；`groupPaint` 只在
     edit 模式出现，备团/带团不可用——这是对的，贴图是作者外观层。
   - `groupId` 悬空、上传孤儿、每输入一步撤销是 P3-5/6/7；`group!` 在组存在时
     安全，但组被删时上传仍会加媒体（P3-6）。
5. **数据一致性**：
   - 删除物件清 `m.groups` 有测试；改尺寸移 `bounds` 但**不裁**、schema 不校验
     `bounds`（P3-1）；媒体删除清 texture 代码对但**没测试**（P3-3）；
     `seen.groups` 各删除路径不清理（P3-2）；复制地图 groups 重映射沿用上一段。
6. **记忆断层**：确实出现，已标 **P2-1**，不是 P3。

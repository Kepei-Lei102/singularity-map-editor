## 1. 代码语义核对

### 1.1 `emptyVision` + `mergeLayers`

当前实现（`src/scene/vision.ts:5`、`:47-52`）：

- `emptyVision` 的 `seen` 增加 `materialCells: {}`；所有 `mergeLayers` 的输出都有这个对象，`delete`/赋值不会碰到 undefined。
- `choose` 的候选项带 `material`；`best` 同时决定 `out.seen.cells[i]`、`out.seen.cellRevs[i]` 和材质。
- 只有 `best?.material` 为真才写材质，否则 `delete out.seen.materialCells[i]`。
- `layers.length === 1` 仍走 `cloneLayer`，没有进入逐格重选。

这个语义与 `syncLayer` 的口径一致：`cellRevs` 是“第几次看见”，材质是那一次看见时记下的材质；最新看见的那层说“没有材质”，就应该删除旧材质。因此**材质跟随同一 `cellRev` winner** 是正确的。

### 1.2 定向 probe 结果

用临时脚本（已删）直接构造 layers：

```text
multi newer material: cells=stone material=stone
newer no material:    cells=grass material=undefined   // 删除，符合“最新观察没有材质”
reverse multi:        cells=stone material=stone        // 与输入顺序无关（同 rev 时按内容稳定）
single:               cells=grass material=wood         // cloneLayer，内容保留；对象/数组是深拷贝
empty layers:         fog=0 material=undefined           // 空集合不残留材质
```

- 单层 clone 没有回归：材质内容保留，`seen`/`materialCells` 与原 layer 不是同一引用。
- 多层的“较新无材质”会删除旧材质，这是本次修复想要的保守语义，不是误删。

### 1.3 模式切换 probe

40×30、甲 `(5,5)`、乙 `(25,20)`，材质 `(25,20)=tile`、`(5,5)=wood`；shared/individual/grouped 之间切换：

```text
init individual:             map tile/wood, a undefined/wood, b tile/undefined
→ grouped:                   map tile/wood, a tile/wood,     b tile/wood
→ individual:                map tile/wood, a tile/wood,     b tile/wood
→ shared:                    map tile/wood, a tile/wood,     b tile/wood
```

- shared→individual：`cloneLayer` 把地图材质带进各人层；没有丢。
- individual→grouped：同组 merge 把乙看见的 tile 继承给甲；没有丢。
- grouped→individual→shared：地图层/各人层材质都保留。
- grouped 下再只改 `session`：地图层与 a/b 的材质都保持，不再出现 A 批前的“任意 update 丢材质”。

注意：individual 下甲初始没有 tile 是正确的（甲看不见该格）；切到 grouped 后出现 tile 也是正确的（组内乙看见，组共享知识）。

**结论：mode switch/单层 clone 无回归。**

## 2. 独立 full 基线

`scripts/incremental-memory.test.mjs:137-141`：

```js
const visioned = withVision(next, prev, { plan });
const inc = produce(visioned, (d) => syncMemory(d, plan));
// full 必须从原始 prev 独立走全量视野，而不是拿已经 merge 过的 visioned 再 sync。
const full = produce(withVision(next, prev, { full: true }), (d) => syncMemory(d));
```

- 这确实消除了“full 拿 inc 的 `visioned` 再 sync”的 same-step 自证问题。
- 当前 `npm test` 888/888 通过，说明没有明显的假阳（独立 full 没有因为合理差异误报）。
- 新增用例和随机序列都走这条 full 基线，仍然通过。

**残余假阴窗口（P3）**：`full` 虽然绕开了本步的 `plan`，但它的 `prev` 仍是上一步 `world = inc` 的增量状态；如果增量状态在前几步已经偏了，后面的 full 也从偏掉的状态出发，两者可能继续共同漂移。要完全独立，random 测试应维护一条单独的 `fullWorld` 链（每步都用 `withVision(full)` + `syncMemory()` 推进），再用它对比 `inc`。这个缺口不影响 A 批结论，但建议作为 P2-4 的后续补强。

## 4. 有没有新 P0/P1/P2

**没有发现新 P0/P1/P2。**

P3 级观察：

1. **同 rev 的 tie-break 不含材质**（`vision.ts:47`）：`choose` 的 tie-break 仍是 `value`（地形）字典序，材质不在比较键里。若两个 layer 恰好同 `cellRev` 但材质不同，结果由地形/输入顺序决定；当前 store 路径下同 rev 通常来自同一次 live 观察，材质一致，所以未发现真实触发。建议在注释或测试里明确“同 rev 假设同一次观察”，或把 material 纳入稳定 tie-break。
2. **较新层缺材质时删除旧材质**（`:52`）：这是正确语义，但当前测试没有覆盖“最新观察材质为空、旧层有材质”的删除分支；上面的 probe 已手工确认，建议补成单元测试。
3. **新用例只覆盖可见材质**：见第 3 节；不影响正确性，但灰区/玩家投影的断言还可以更厚。
4. **random full 基线仍非完全独立**：见第 2 节；null 之外无产品问题。

另外，`emptyVision` 现在给每个 view 多一个空对象 `materialCells`，序列化体积略增；可忽略，不构成 P2。

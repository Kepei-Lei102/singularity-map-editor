## P2

### P2-1 独立/分组模式：手动雾标记在 `syncMemory` clone 后丢失，下一次视野脏动不整图覆盖

- 位置：
  - `src/scene/perception.ts:105-115` 在 `withVision` 内判断 `manual` / `manualChanged`，`:148-151` 只给这次 `withVision` 的 `out` 打 `markManualFog`
  - `src/core/store.ts:165` 随后再 `produce(withVision(...), d => syncMemory(d, plan))`
  - `src/scene/memory.ts:218-230` 非共享模式 `cloneLayer(L)` 写回每个 view（`:228`），再 `Object.assign(m, mergeLayers(...))` 重算地图层（`:230`）
  - `src/scene/vision.ts:43-45` `mergeLayers` 单层也走 `cloneLayer`，都会新建 fog 数组
- 复现（store/actions 层，50×40）：
  - 世界 `visionMode='individual'`，甲/乙两人，`map.autoFog=true`，棋子甲在 `(5,5)`、乙在 `(8,8)`
  - `paintFog(mapId, [[40,30]], 'fogReveal', ['a'])`；`views.a.fog[30*50+40]` = 1
  - `update(d => { d.session += 1 })` 后仍是 1（无关数据不覆盖，符合预期）
  - `update(d => { d.maps[0].tokens[0].x += 1 })` 后实际仍是 1；全量结果应为 `step(1,0)=2`（视野外的手动可见格降成记忆灰）
  - `visionMode='grouped'`、用 `paintFog` 不带目标角色时同样实际 1、应为 2；`map.fog` 也停在 1
  - 共享模式同序列实际 2，说明不是全模式坏，而是非共享模式的层 clone 路径坏
- 原因：`paintFog` 更新后，`withVision` 先把 `m.fog` / `m.views[*].fog` 数组登记进 WeakSet；紧接着 `syncMemory` 用 `cloneLayer` / `mergeLayers` 生成新的 fog 数组替换掉它们。`store` 返回的世界里已经没有登记过的数组，`isManualFog(world)` 为 false；下一次移动 `diffWorld` 只看到 `tokens` 脏，`planVision` 收窄到圆盘，手动改的远处格不在圆盘内，于是永远保留 1。
- 建议修法：
  - 把“保留手动雾”的标记维护从 `withVision` 内部移到整条 `store.update` 之后：在 `syncMemory` / `bumpStateRevs` 完成后，对最终世界重新 `markManualFog`；不能只给 `withVision` 的中间 `out` 打标记。
  - 需要知道哪些图这次应保留：在 `update` 入口同时算 `manualChanged`（`fog`/`views` 引用变了）和视野脏动；只有 `manualChanged && !视野脏动 && autoFog` 才给最终世界打标记。若当前图原本已是 manual pending，且这次没有触发自动覆盖，也要在同步后重打标记。
  - 这是最小修复；WeakSet 本身不必换，但标记点必须跟最终落盘的数组走。补 store 层独立/分组手动雾测试（不要只测 `withVision`）。

### P2-2 共享模式：自动覆盖时清掉历史数组标记，`undo` 回手动雾状态后下一次视野脏动不再覆盖

- 位置：
  - `src/scene/perception.ts:112-115` 把 manual pending（`manualApply`）加进 `clearIds`
  - `src/scene/perception.ts:144-147` 对 `prev` 的 fog/views 数组执行 `clearManualFog`
  - `src/core/store.ts:190-200` `undo` 直接把 `world = prev` 放回，不重建标记
- 复现（共享模式，50×40，远离棋子的格）：
  - 手动点亮 `(40,30)`：`fog=1`
  - 移动棋子一步：自动覆盖为 2，同时 `clearManualFog(prev)` 把历史世界里的标记清掉
  - `undo()`：fog 回到 1，但标记已经没了
  - 再移动棋子一步：实际仍是 1；全量应为 2
  - `redo()` 同理
- 原因：`undo` 只恢复数组内容，不恢复 WeakSet 的标记；而 `clearManualFog` 恰好把待恢复世界里的数组标记删掉了。之后 `diffWorld` 看不到 manual，`planVision` 只圈圆盘。
- 建议修法：
  - 自动覆盖时不要删历史数组的标记。fog 数组是不可变替换的：自动覆盖生成的 `out` 数组是新数组，旧世界数组只存在于 `past/future`；保留旧标记不会误伤当前自动世界，却能让 undo 恢复“待覆盖”状态。
  - 若坚持清标记，则需要把 pending 状态一起放进历史（world 侧字段或 `past/future` 旁的元数据），`undo` 时同步恢复；不要只靠数组 WeakSet。
  - 补 undo/redo 测试：手动雾 → 视野脏动自动覆盖 → undo → 再视野脏动必须覆盖。

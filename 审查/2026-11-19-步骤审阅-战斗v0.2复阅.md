## 初版 P1/P2 修法复核

### P1 单人/当前眩晕：已修

- `trialEndTurn` 现在先看当前角色 `skipTurns`：`skipped = !!t.acted[curId]`，被 switch 标记跳过则不再减，否则减 1，减到 0 删除。
- 单人测试覆盖：自定义 `setTrialStatus('眩晕',5)` 带默认 `skipTurns:1`，按一次空格后状态消失、`turn=2`、行动点回到 1；不再死锁。
- 多人 switch 路径仍保持：switch 减一次并标记 `acted`，结束时 `skipped=true` 不再重复减；`tickEffects` 式整轮倒计时也不会碰 `skipTurns`。
- **口径变化**：若眩晕是在当前回合中途挂上、且本回合没有行动（`acted=false`），结束回合就消费掉，不会让下一回合再跳一次；作者测试按这个口径，初版“跳过下个自己的回合”在单人路径实际变成“本回合被挡后结束即解除”。若作者要的是严格跳下回合，需要额外“回合开始”标记，当前没有。

### P2#1 整轮资源：部分修，仍有 P2

- **已修**：只结束一个人时，`acted/moved/turned/runMode/runTurns/sharpAttack` 只删当前 token；`movePoints` 只重算当前；`charge` 只在 `endsRound` 时 tick；`opportunityUsed` 只在整轮清。资源测试覆盖“甲结束不清乙的 acted/charge”。
- **未修**：`ended` 只用于判断整轮是否结束，**没有用来锁人**。`trialEndTurn` 在单人结束时仍删掉当前 `acted/moved/...` 并重算 `movePoints`，但 `current` 不变、`ended[curId]=true`；`actionsLeft` 只看 `acted`，所以已结束的人又能行动。
- **实测**：两人队当前甲，甲按空格结束（`ended:{ta:true}`、`turn` 仍 1），此时 `actionsLeft=1`；再对旁边 NPC 调用 `trialAttack('npc',{roll:50})`，命中并扣血 `10→9`。重复按空格或切回甲同理；`ended` 不是锁。
- **影响**：同一个人在同一整轮可二次攻击/二次移动；重复结束还会顺手重置 movePoints，并把眩晕 `skipTurns` 提前消费（因为 `t.acted` 已被清）。这是核心回合限制漏洞。
- **建议**：`ended[current]` 时不清当前 `acted/movePoints`，或所有动作入口加 `ended` guard；重复 `trialEndTurn` 对已结束的当前角色直接 no-op（至少不重置资源）。补一条“甲结束再按空格/切回甲不能攻击、不能移动”。

### P2#2 NPC 倒地：已修

- 濒死到点：`if (k.pcId)` 走 PC `settleDeath` + `corpse=true`；NPC 走 `corpse=true` + “濒死到点，尸体留在原地”日志。NPC 不再 HP 0 站着，也不再被 `hpOfToken` 当成满血目标。
- 流血归零 NPC 也有“流血倒下，进入濒死”日志；PC/NPC 双路径测试通过。
- 未见新回归。

### P2#3 动作入口：已修

- `doorContext`（开门/撬锁/撞门/密码）、`trialRescue`、`trialSense`、`trialRun`、`trialOpportunityAttack` 都加 `statusBlocksAction`；借机攻击跳过眩晕敌人。
- 测试覆盖眩晕挡救治/感知/跑法；攻击/移动/姿态仍被挡，流血/中毒仍放行。
- **小边界**：`trialRun(null)` 也在 guard 后面，眩晕时不能取消跑法；结束回合会清 `runMode`，所以可恢复，属 P3。

## P3 复核

- docs 第 3 行已改；`rules/combat.ts` 的 `tickEffects` 注释已标明旧固定值口径，生产在 `trial.ts`。
- 自定义输入“眩晕/流血/中毒”自动带默认机制；`setTrialStatus('眩晕',5)` 测试覆盖。
- `switchTrialPlayer` 只在 `changed` 时消费 skipTurns，点同一个人不再刷掉跳过回合。
- 0 玩家 `trialEndTurn` 直接 return；尸体/昏厥自动 `ended`；`perRound` 固定伤害有测试。
- **遗留 P3#1**：尸体/昏厥自动 `ended` 是粘性的。实测三人队：甲结束把 `down` 的乙自动标 ended；丙把乙救起来后，丙结束仍因乙已 ended 直接结算整轮，乙没得到本回合。若口径是“倒地即跳过本回合”没问题；若“救回来还能行动”则要重算/清除自动 ended。建议 docs 明说。
- **遗留 P3#2**：`trialRun(null)` 被 status guard 挡住；`settleJump` 的待结算跳跃没有 status guard（跳跃发起时已挡，挂起后补眩晕仍可能结算）。属边界。
- **遗留 P3#3**：测试只覆盖“昏厥自动 ended”，没覆盖尸体；没有“ended 后不能再动/重复结束不重置资源”“同一个人点击不消费 skipTurns”“倒地救回后 ended 粘性”的回归。当前重复结束漏洞全绿。

## 结论

- **P0 0 / P1 0 / P2 1 / P3 3，不可推。**
- 初版 P1、P2#2、P2#3 修法成立，P2#1 的“不替别人清”也成立；但 `ended` 不锁人，重复结束/切回已结束角色仍可二次行动，是整轮骨架的核心漏洞，建议补掉后再推。

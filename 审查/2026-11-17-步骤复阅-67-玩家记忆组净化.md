## P2 闭合复核

### 玩家包不再带内部字段

基础场景（A 可见、B 灰、tex1）实测玩家包：

`seen.groups = [{"id":"mg0","name":"贴图","cells":[744],"bounds":{"x0":24,"y0":24,"x1":25,"y1":25},"texture":{"mediaId":"tex1"},"z":0}]`

- 没有 `sourceId`、`textureKey`；
- id 是 `mg0`，不是 `g`/`g~tex1~fill~1`；
- `JSON.stringify(pm)` 不含 `sourceId`、`textureKey`、`tex1~fill~1`；
- 实时组仍是 `id:"g"`，与记忆组 `mg0` 分开；
- 旧工程记忆组（id `old`、无 sourceId）进玩家包后同样变成 `mg0`，JSON 里连
  `old` 都不出现；
- A 也转灰后两组 id `mg0`/`mg1`，tex1/tex2 各自 cells 正确，两版都不带内部字段。

测试核对：`out_spread`（换回 `{...g}`）、`id_g`（id 用 `g.id`）、
`id_composite`（id 用 `${g.id}~${g.textureKey}`）三个 mutation 都只让
「贴图版本」这一测试失败（13/14），不是全绿；新测试确实钉住了净化与
`mg` 序号。

## P3

### P3-1 `mg` 序号可能和实时组 id 碰撞，且跨更新会漂移

- `id: mg${seenGroups.length}` 只在玩家包的一次构造里唯一；它不保证与
  `m.groups` 的实时组 id 不同。实测把实时组 id 设为 `mg0` 后，玩家包
  `groups[0].id` 和 `seen.groups[0].id` 都是 `mg0`。
- `seenGroups` 的顺序来自 `L.seen.groups`；删掉/新增前面的记忆组后，后面的
  组会从 `mg1` 变成 `mg0`（实测两个组删第一个，剩余组 id 从 `mg1` 变 `mg0`）。
- 当前玩家侧没有因此出错：`PlayerView.tsx:144` 只把 `map` 交给
  `MapCanvas mode="player"`；`MapCanvas` 画组只按 `cells/texture/bounds/z`
  （`drawGroups`/`drawSeenCellGroups`），不按 id 找组；`MapCanvas:309` 的
  `m.groups.find(g => g.id === s.groupId)` 只在编辑侧 `groupPaint` 工具里，
  玩家端 `groupId` 默认 null。所以按 P3，不阻塞；但若以后有消费方按组 id
  合并/缓存，需要把 `mg` 改成稳定 id 或加命名空间。
- 测试只测了“此刻是 mg0/mg1”，没有测碰撞和漂移。

### P3-2 实时 `maps[].groups` 仍是 `{...g}`，若实时组带内部字段会漏

- `deprecated` 的 `visibleGroup` 仍 `{ ...g, name:'贴图', cells }`；正常编辑器
  只在记忆组写 `sourceId/textureKey`，但 schema 不禁止实时组带这两个字段。
- 实测手工在实时组放 `sourceId:'secret'`/`textureKey:'tex1~fill~1'`，玩家包
  `maps[0].groups` 原样带出，`JSON.stringify(pm)` 也能搜到；`checkWorld` 通过。
- 这是导入/手改数据才可能触发的防守缺口，不是本轮记忆组净化的回归；按 P3。
  要彻底堵住，`visibleGroup` 也应显式挑字段，或 schema 拒绝实时组带这两个字段。

### P3-3 render/prune 组合测试仍缺

- 删掉 `render.ts` 的 `if (player) drawSeenCellGroups(...)`：`material.test.mjs`
  14/14 通过；测试只直接调 `drawSeenCellGroups`，没走 render。
- 去掉 `pruneMemory` 的 `L.seen.groups` 过滤：14/14 通过。
- 这两条是 65/66 已列 P3，本轮净化没有新增用例；建议补 render player 模式
  实际画图和 fog 归 0 后记忆组消失。

### P3-4 旧工程 `m.seen` 仍可能同纹理两份，且旧 id 不再是玩家问题

- 旧记忆组 id `g`（B 灰、tex1）同步后，`m.seen` 里仍是旧 `g` 和新建
  `g~tex1~fill~1` 两份同纹理组（格子不重，B/A 分开）。
- 玩家包现在把两者都映射成 `mg0`/`mg1`，不再暴露原 id，也不再有实时/记忆
  id 相同的问题；但内部记忆数据仍是两份，等 B 可见后才会收敛。按 P3。

### P3-5 `mergeLayers` 跨版本同一格会进两个组

- `mergeLayers` 按记忆组 id 分组，再对每个 id 做 cells 并集；不同版本 id
  (`g~tex1~fill~1`/`g~tex2~fill~1`) 之间没有按格去重。
- 实测 a 的 `g~tex1` 和 b 的 `g~tex2` 都含同一小格，合并后 `out.seen.groups`
  两个组都含这一格；这主要落在主持人 `m.seen`。独立玩家用 `m.views[pcId]`，
  共享只有一层，所以玩家包暂不受影响。按 P3。

### P3-6 `mergeLayers` 对旧 id 仍是“最新贴图盖整组”

- 旧 id 没有版本后缀时，`mergeLayers` 仍按组 id 聚合、取 `groupRevs` 最新，
  最新贴图覆盖整组。新拆法的新记忆组一般不再跨版本合并，旧工程/旧 id 仍走
  这条。按 P3，和 P3-4 一起看。

### P3-7 fit/opacity/浮点版本键没有测试

- `textureKeyOf` 仍拼 `${mediaId}~${fit ?? 'fill'}~${opacity ?? 1}`；实测
  fill/1→contain/0.5 再回 fill/1，旧灰格留 fill/1、可见格 contain/0.5，回
  fill/1 时同版本并回一组，没有同格重复。
- 测试只换 mediaId，没测 fit/opacity 组合；opacity 用原始浮点字符串，浮点
  抖动会产生额外版本 id。按 P3。

### P3-8 schema 不校验 `sourceId`/`textureKey`/`bounds`/`groupRevs`

- `cellGroup` 只校验 id/name/cells/texture/objectId/z；`sourceId`、
  `textureKey`、`bounds` 任意内容都放过，`groupRevs` 完全不进 schema。
- 玩家包 `mg0` 这类任意非空 id 也能过 `checkWorld`；旧工程和手改数据都能
  把内部字段塞进实时组/记忆组（P3-2）。按 P3。

### P3-9 `memoryDirty` 的 groups 仍触发全量重算

- `store.ts` 把 `o.groups !== m.groups` 加入 `memoryDirty`；拖涂时每个
  pointermove 都改 groups，于是每次 update 跑全地图、全视野的 `syncMemory`。
  触发正确，但可能卡。按 P3。

### P3-10 媒体删除/删物件仍只清实时组

- `MediaPanel` 删除媒体只清 `m.groups` 的 texture，不清 `m.seen.groups`；
  玩家 `usedTextures` 过滤后找不到已删媒体，灰区记忆贴图会没有图可画。
- `deleteMapObject` 只过滤 `m.groups`；`m.seen.groups` 的 objectId 组还在，
  玩家侧现在靠 objectId 过滤不画，但数据悬空。按 P3。

### P3-11 记忆层仍只判大格地形

- `drawGroups(memory=true)` 只检查 `map.seen.cells[parent]`，不检查
  `terrainAtSubcell`；实时层会跳过空白小格，转灰后可能把贴图画到空白小格。
  按 P3。

### P3-12 texture/UI/线上 asset 仍按作者决定不修

- `texture.ts` 失败永久缓存、成功不 revoke、images 不淘汰；
- UI 名字/z/不透明度逐输入撤销、上传孤儿、groupId 悬空；
- 线上 asset 分块同步和缓存。
- 按 P3，不阻塞本段。

## 重点逐条

1. **玩家包内部路径**：
   - `seen.groups` 已净化，`sourceId`/`textureKey`/版本键 id/原组 id 都不出现；
   - `maps[].groups` 的正常实时组没有内部字段；手工塞入会漏，按 P3-2；
   - `seen` 其他字段（cells/objects/architecture/materialCells）不带组内部字段；
   - `media` 只留实际用到的贴图，名字统一「贴图」；`key` 是同源存储名，不带文件名/路径；
   - `JSON.stringify(pm)` 实测不含 `sourceId`/`textureKey`/`tex1~fill~1`。
2. **剥离后渲染/排序/缓存**：
   - `bounds` 按记忆格重算；`z` 保留（0 也带）；`texture` 只带 mediaId/fit/opacity；
   - `drawGroups` 仍按 `z` 排序、按 cells 裁剪、用 `textureImage(mediaId)`；
     不按 id 找组；
   - 多版本组 id `mg0`/`mg1` 在一次包内唯一；`mg0` 跨更新会漂移（P3-1），
     当前渲染不依赖 id，无副作用。
3. **测试咬合**：
   - `out_spread`、`id_g`、`id_composite`：13/14，失败的是「贴图版本」；
   - render/prune 两个 mutation：14/14 全绿（P3-3）；
   - 旧工程记忆组进玩家包已实测净化；测试没有覆盖旧工程，P3-4。
4. **回归/旧工程/独立/共享/merge/prune**：
   - 共享：A 可见/B 灰，实时 tex2、记忆 tex1；A 转灰后 mg0/mg1；
   - 独立：a 看见 A+B、b 只看见 A；b 记忆 B tex1，a 无记忆；切灰后两版各自
     正确，无串；
   - prune：fog 全 0 后 `seen.groups` 清空；
   - `m.seen` 合并仍有跨版本同格（P3-5）；
   - `checkWorld` 和 `checkWorld(playerWorld)` 都通过。
5. **P3**：按作者决定不修；没有新增 P2。

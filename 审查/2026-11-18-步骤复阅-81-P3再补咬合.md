## 焦点 1：applyMediaIndex filter

- 新条件：`!!m && typeof m.id === 'string' && m.id.length > 0 && typeof m.mime === 'string' && (m.key === undefined || typeof m.key === 'string')`（`media.ts:50-54`）。
- 正常条目：
  - `{id:'tex', mime, key:'v:abc'}` 通过。
  - 旧数据没有 `key` 通过，回落 id。
  - 缺 `name`/`size` 不拦；索引只需要 id/key/mime，合理。
  - `mime:''` 通过（浏览器 `File.type` 可能为空），不误杀。
- 被丢的：
  - `id:''`、缺 mime、`key: 1` 都丢；测试 `{media:[{id:'',...}]}`、`{media:[{id:'no-mime',...}]}`、`{media:[{id:'bad-key', key:1}]}` 都咬住：
    - 去掉 filter → 1 红。
    - 只查 id → 1 红（缺 mime 落回 id）。
    - 去掉空 id 检查 → 1 红。
    - 去掉 key 类型检查 → 1 红。
  - `key: null` 也被丢；旧 `m.key ?? m.id` 本可回落 id，坏数据边界。
- **仍接受 `key:''`**：空串不是 undefined，`storageKey(id)` 会映射到空字符串，读 IDB 空 key；没有用例。只在坏数据，P3。
- **空 mime / 空白 id 也接受**；`id.length > 0` 只挡空串，不 trim。坏数据边界，P3。
- **丢缺 mime 的条目是否合理**：`MediaMeta` schema 要求 mime，正常世界不会缺；但贴图 loader 只吃 id/key，一个 id/key 有效、mime 缺失的旧条目会被丢，玩家贴图读不到。属于保守取舍，P3。
- 类型放宽没破坏 PlayerView 传 World 的契约；`world=null`/`media=null`/非数组都清空。

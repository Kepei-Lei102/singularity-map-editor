## P2（1 个，阻断合入）

### P2-1 玩家实时层的 ghost 仍然画成实心贴图，不是虚线轮廓

72 的灰区借图问题本身已经修掉；但玩家**实时层**还有一个独立的 ghost 问题：

- `playerMap` 的物件载荷（`sync.ts:358-361`）只发 `id/kind/name/x/y/w/h/anchor/height/color/icon/state/states/notes/hidden/media/secrets`，**没有 `blocksWhen`**。
- `drawObject` 判断 ghost 用的是 `!!o.blocksWhen && !o.blocksWhen.includes(o.state)`（`render.ts:231`）。玩家物件没有 `blocksWhen`，ghost 恒为 false。
- 于是玩家实时层走普通实体分支（`render.ts:243-257`），有贴图就 `drawImage`，没有贴图就彩色方块；不会走 `render.ts:235-242` 的虚线轮廓。玩家看到的“不挡路”物件是堵路的实心图。

探针（2×2 物件，`states=['收','开']`、`state=1`、`blocksWhen=[0]`，物件贴图已挂，全 fog=1）：

- 玩家载荷：`blocksWhen: undefined`，`state: 1`。
- `render(mode:'player')`：`drawImage=1`，`strokeRect=0`，`fillText` 没有 `★`（按有贴图处理）。
- 主机 `render(mode:'edit')` 同一物件：`drawImage=0`，`strokeRect>0`（虚线），即现有 `objectappearance.test` 的 ghost 测试走的是这条路。
- 部分可见 ghost：玩家实时层仍是实心贴图；灰区记忆层是彩色方块加默认黑框（`strokeRect=1`），也没有虚线。

这直接违背本轮 docs 的“可开合的物件在‘不挡路’状态仍只画虚线轮廓，不画贴图”。测试缺口也很明确：`objectappearance.test.mjs:104` 的 ghost 用例调用默认 `renderOnce(world, map)`（host/edit），`objectappearance.test.mjs:159` 的玩家渲染用例用普通物件，没有玩家 ghost 用例。

修复方向：把 `blocksWhen` 一并放进玩家物件载荷（它不是隐藏信息，`states/state` 已经发）；更好是只发渲染需要的“当前是否挡路/挡视”派生字段，避免把完整 `blocksWhen` 暴露给玩家侧逻辑。补一条玩家实时层 ghost 测试，断言 `drawImage=0` 且有虚线 `strokeRect`。

**这不是 73 修复引入的新回归，是 72 的 3-B 玩家路径漏项，72 报告也没覆盖；但它是本轮产品语义的一部分，因此 73 仍不能推。**

## P2-1（已修，验证通过）

灰区记忆不再借当前实时贴图：

- `drawObjects` 新增 `textureOf` 参数（`render.ts:670-676`）；实时层传 `liveTextureOf = objectTextures.get(ob.id)`（`render.ts:677-681`），记忆层传 `() => undefined`（`render.ts:683-687`）。
- `labelSets` 也保存 `textureOf`（`render.ts:675`），代表标签用同一个 resolver（`render.ts:730-739`）；灰区记忆标签恢复图标/正常描边。
- `drawTag` 走 `objectTextures.get(t.id)`（`render.ts:912`），但 `tagged` 只在非玩家模式收集当前选中/悬停物件（`render.ts:877-887`），不会碰灰区记忆。

验证：

- 新的部分可见用例（2×2 物件，1 个 fog1 格、其余 fog2，`identity:{party:true}`）通过：`seen.objects` 有记忆；`drawImage=1`（只有实时层）；`fillText` 包含 `★`（记忆标签没有被当成有贴图）。
- 全可见：`drawImage=1`，没有记忆层；现有玩家渲染用例仍通过。
- 全不可见：眼睛物件组/物件都不发，`drawImage=0`；现有“看不见的物件连贴图组一起不发”用例覆盖载荷。
- 部分可见：实时层画当前贴图；记忆层画彩色方块，标签带 `★`；没有第二张 `drawImage`。
- 变异：把记忆 resolver 改成 `liveTextureOf`、把 `labelSets` 的 resolver 改成 `liveTextureOf`、或让 `drawObjects` 忽略 `textureOf` 直接 `objectTextures.get(ob.id)`，三条都会让新用例 `灰区记忆物件不借当前贴图...` 红；旧的全 fog=1 玩家渲染用例仍然绿。说明新测试确实咬住 P2，不是旧用例替代品。

## P3（7 个，72 的 6 个仍留，另 1 个旧 ghost 记忆）

1. **UI 异步上传落账前不复查试玩/权限/当前选中。**
   `uploadTexture`（`Inspector.tsx:423-453`）await 后只查 `worldContext` 和物件存在，不查 `ui.trial`/`canTexture`/选中对象。上传途中进试玩会把贴图写进沙盒世界；endTrial 后 blob 成孤儿且不走 `offerDeleteOrphanBlob`；切换选中会把图挂到原物件。无测试。

2. **玩家部分可见物件组只带可见 cells、没有 full bounds，但渲染不用 cells；玩家端 `replaceWorld`/`syncObjectGroups` 会补成全脚印。**
   `playerMap` 的 `visibleGroup` 部分可见时不带 bounds（`sync.ts:291-301`），schema 也不强制 cells 等于脚印。当前渲染不消费组 cells（`drawObject` 用物件矩形），所以视觉没额外形状泄露，但数据承诺和后续 3-C/玩家端归一化不一致；无部分可见载荷测试。

3. **`imageOf` 返回 null 时回退是彩色方块 + 默认黑框 + 按有贴图处理的标签。**
   `drawObject` 的 `textured` 只看 spec，`img` 为 null 时走 `fillRect` 和默认黑框；标签仍 `decorated`（无图标、暗描边）。图片加载前、加载失败、或调用方没传 `imageOf`（`renderMapForAI` 没传，走默认 `textureImage`）会出现。无 `imageOf: () => null` 测试。

4. **`setObjectTexture` 的可选 `media` 和返回值边界没测。**
   `actions.ts:1473-1499` 的 `update` 回调提前 return 时函数仍返回 `id`；`media` 传入已存在 media id 时不更新 `name/key`，新 blob 可能成孤儿。测试只覆盖 missing/doc/weird/zone/上传事务。

5. **`deleteMedia` 清物件贴图但保留空物件组；UI 随后没有入口清掉它。**
   `actions.ts:1045-1057` 对所有 `m.groups` 清 `texture`，组和 cells 留下；`ObjectInspector` 的“清除贴图”只在 `objectTexture && textureGroup` 时渲染（`Inspector.tsx:525-533`），贴图清掉后空组无法从 UI 删。无空组策略测试。

6. **UI 其余接线和 drawTag 没有测试。**
   现有 UI 测试只覆盖普通物件入口、选已有图、清除、建筑/zone 隐藏；没有上传/孤儿、fit/不透明度绑定、试玩隐藏、`textureGroup` 过期引用、`TexturePreview`，也没有 `drawTag` 的“有贴图不叠图标”及标签状态/高度文案断言。

7. **灰区记忆里的 ghost 仍是实心色块（旧问题，不是新 P2）。**
   `SeenObject` 本身没有 `blocksWhen`（`types.ts:268-281`），`fromMemory` 一直不带（`render.ts:382-387`）。本轮修完后灰区 ghost 不再借贴图，但仍是彩色方块 + 默认黑框；这不是本轮引入，也不是新 P2。若要一并处理，需要扩展 `SeenObject`/记忆快照带 `blocksWhen`（或“当时是否挡路”），属于 3-C/记忆语义，不是 3-B 的必要修复。

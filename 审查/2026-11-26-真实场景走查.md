- 临时 zip、解包文件和截图都在 `/tmp` 或 `.runtime/`，走查结束已清理；**走查阶段没有改代码**，本轮的顺手改动在下面单独列出。

## 走通的路径

1. **导入**：文件 → 导入 zip/JSON；68 MB 的 zip 带 28 个媒体文件，导入完成，替换当前世界。
2. **地图切换**：两张图都能切；房间列表、连接点、建筑层、互动排布随图切换。
3. **画房的最短链路**：新建房间 → 自动选中房间笔刷 → 在画布上刷入格子；`roomCells` 写回成功。本次只验证链路，没有画完整房间。
4. **门与记录**：在检查器点一扇门的「开门」→ 状态变为「关门」，记录里落了一条「关闭 → 打开」。
5. **备团 / 带团**：备团显示预测流程图、房间互动排布、只读提示；带团显示流程图和记录，地图可操作。
6. **试玩 / 玩家窗口**：无队伍时点「▶ 试玩」会自动建一个「白板玩家」，打开玩家端；玩家端显示地图、迷雾和 0/0 状态条。点掉「点一下这里开始」后正常出图。
7. **队伍**：队伍面板「＋」能新建角色；角色有当前途径、ME、六维、在地图上放棋子等入口。
8. **媒体库**：28 个文件都列出来了，带类型和大小，有「主持人播放 / 同步给玩家」入口。

## 发现

### P0 / P1 / P2

没有。

走查中曾经把「没有队伍时试玩自动造白板玩家 0/0」当成 P2；后来对照 `README.md` 和 `需求.md`：试玩本来就是**白板占位沙盒**，用 WASD 走、看视野，不读取队伍里的正式角色，正式跑团用「带团」。所以这不是 bug，原建议的「试玩前拦住、要求先加角色」也不该做。真正的问题是 UI 没把这个概念说清楚，见下面 P3。

### P3

- **试玩的白板占位角色容易和正式角色混淆。** 试玩条只写「白板玩家」，玩家端也只显示「白板玩家 0 / 0」；第一次用真实工程的人会以为角色没导进来。本轮已在试玩条加「白板占位」标签、玩家端状态条加「试玩占位」徽标，不改试玩行为。
- **媒体库没有缩略图。** 28 个文件只有文件名、类型、大小和播放按钮；真实模组里找一张图要靠文件名猜。本轮已在图片媒体前加缩略图；加载中、文件不在本机或解码失败时给固定尺寸的省略占位，鼠标悬停可看全名。
- **队伍只有手动「＋」，没有角色卡导入。** 真实角色卡（六维、ME、技能）只能逐项手填；这次没有角色卡数据，所以只验证了新建空白角色能出面板。P3 / 以后功能。
- **需求文档的规则边界已过时。** `需求.md` 还写「移动范围、攻击范围、借机攻击还没做」；代码里借机攻击、攻击距离、贴身移动限制都有实现，`CLOSE_RANGE = 4` 只在 `rules/combat.ts` 定义，没有使用点。下一轮不要按旧文档重复开功能。
- **「导入后自动适配」不需要改。** 初始视图在没有保存过视角时会执行 `fitView`；走查里看到的「只显示一角」是试玩镜头跟随白板角色造成的，不是导入。真正要重看全图时用「适配」或「回到棋子」。

## 本轮顺手改动

- `src/components/TrialHud.tsx`：试玩条加「白板占位」说明，tooltip 写清「试玩角色是新建的白板玩家，不是你队伍里的角色」。
- `src/components/PlayerView.tsx`：试玩玩家端状态条加「试玩占位」徽标；正式窗口 `trialFlags` 为 null，不会误显示。

- `src/styles.css`：对应的小徽标和缩略图样式，裁剪只作用于文字行，不命中占位槽。
- `scripts/ui-polish.test.mjs`：新增 1 条接线测试，锁住试玩徽标和缩略图/占位结构。

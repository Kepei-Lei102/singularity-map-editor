## 焦点 2：`MapObject.ghost` 字段

结论：主路径安全，但作为持久化类型上的派生字段有 P3 级污染/误读风险。

- `MapObject.ghost` 只是可选类型（`types.ts:150-151`）；`playerMap` 只给玩家物件填，主机 `map.objects` 正常不出现。
- `checkWorld(playerWorld(...))` 通过；`ghost` 不会让校验炸掉。
- 但 schema **没有校验/剥离** `ghost`：我构造 host 物件 `ghost:false` + `blocksWhen=[0]` + `state=1` 后 `checkWorld` 仍通过；`ghost:'yes'` 也通过。宿主端渲染会优先信 `o.ghost ??`，于是：
  - 任何从玩家世界/旧备份/手改 JSON 进入主机世界对象上的 `ghost`，会让主机渲染跳过 `blocksWhen`，状态改了也不更新（stale 派生值），和“host 没有该字段时回退”不一致。
  - `checkWorld` 不校验 boolean，错误值（字符串）会被 truthy 当真。
- 正常编辑器路径不会给 host 对象写 `ghost`：`newObject` 不生成，`playerWorld` 只用于玩家载荷/AI 渲染，玩家端也没有导入导出/回写 host 的路径；所以这是 P3 防御性问题，不是当前 P2。
- 建议：不要把 `ghost` 放进持久化的 `MapObject`，改为玩家载荷专用类型（如 `PlayerMapObject` / `ObjectView`），或 `checkWorld` 在 host 侧拒绝/剥离；至少加 `optBool` 并只允许玩家载荷。若保留，`ghost` 名字可以，但必须保证 host 永不持久化。

## P3（9 个）

1. **UI 异步上传落账前不复查试玩/权限/当前选中。**
   `uploadTexture` await 后只查 `worldContext` 和物件存在，不查 `ui.trial`/`canTexture`/选中对象。上传途中进试玩会把贴图写进沙盒世界，endTrial 后 blob 成孤儿且不走 `offerDeleteOrphanBlob`；切换选中会把图挂到原物件。无测试。

2. **玩家部分可见物件组只带可见 cells、没有 full bounds，但渲染不用 cells；玩家端 `replaceWorld`/`syncObjectGroups` 会补成全脚印。**
   schema 不强制 cells 等于脚印；当前视觉没额外泄露，但数据承诺和后续 3-C/玩家端归一化不一致；无部分可见载荷测试。

3. **`imageOf` 返回 null 时回退是彩色方块 + 默认黑框 + 按有贴图处理的标签。**
   `textured` 只看 spec；`img` 为 null 时走 `fillRect` 和默认黑框，标签仍 `decorated`（无图标/暗描边）。图片加载前、失败或没传 `imageOf`（`renderMapForAI`）会出现；无 `imageOf: () => null` 测试。

4. **`setObjectTexture` 的可选 `media` 和返回值边界没测。**
   `actions.ts:1473-1499` 的 `update` 回调提前 return 时函数仍返回 `id`；`media` 用已存在 id 时不更新 `name/key`，新 blob 可能孤儿。

5. **`deleteMedia` 清物件贴图但保留空物件组；UI 随后没有入口清掉它。**
   `actions.ts:1045-1057` 只清 `texture`，组和 cells 留下；`ObjectInspector` 的“清除贴图”只在 `objectTexture && textureGroup` 时渲染。无空组策略测试。

6. **UI 其余接线和 drawTag 没有测试。**
   只覆盖普通物件入口、选已有图、清除、建筑/zone 隐藏；没有上传/孤儿、fit/不透明度绑定、试玩隐藏、`textureGroup` 过期引用、`TexturePreview`；也没有 `drawTag` 的“有贴图不叠图标”及标签状态/高度断言。

7. **灰区记忆里的 ghost 仍是实心色块（旧问题，不是新 P2）。**
   `SeenObject` 没有 `blocksWhen`（`types.ts:268-281`），`fromMemory` 一直不带。本轮修完后灰区 ghost 不借贴图，但仍是彩色方块+默认黑框；按 3-C 处理即可。

8. **`ghost` 作为持久化 `MapObject` 字段的 schema/污染风险（本轮新增字段带来的 P3，不是 P2）。**
   normal host 不写，但 `checkWorld` 接受任意 `ghost`、不校验 boolean、不剥离；host 导入/旧备份/手改 JSON 可带 stale `ghost`，renderer 优先信它并跳过 `blocksWhen`。建议玩家载荷专用类型或 host 侧剥离/校验。

9. **`ghost` 派生与测试覆盖的剩余缺口。**
   新测试只覆盖“全可见 + 已知身份 + 有贴图”；无贴图、未知身份、部分可见、幽灵+贴图标签、以及 `ghost` 在玩家载荷里只出现在当前层（记忆层仍无）都没有测试。未知身份时 `state` 被抹成 0，但 `ghost` 仍按真实状态派生，会告诉玩家该未辨识物件当前不挡路；如果这算物理可见状态可接受，但应有明确口径和测试。

## 结论

玩家实时 ghost 的 P2 已修：载荷带派生 `ghost`，实时层正确地只画虚线、不画贴图/底色；主机无字段时回退 `blocksWhen`；新测试确实咬住（去掉 sync 派生或 renderer 回退都会红），host 回退由旧测试保护。灰区 ghost 仍按 3-C 留 P3。

`MapObject.ghost` 的正常路径安全，但作为持久化派生字段有 schema 接受/不剥离/宿主端优先信任的 P3 风险，建议后续收紧。没有新增 P0/P1/P2；本轮可推。

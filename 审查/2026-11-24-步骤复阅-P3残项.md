### 1.2 条件减少 / 三条中间编辑：顺序会漂移（P3）

探针结果（未改源码，只通过面板点击）：

- **三条 state 条件编辑中间一条**：
  - 初始 `[state[0], prop, state[0], actorHas, state[1]]`（三条 state 条件，中间那条是 `[0]`）；
  - 点中间条件的 1（中间条件变 `[0,1]`）；
  - 实际变成 `[state[0], prop, state[1], actorHas, state[0,1]]`。
  - 原因：`toggleState:120-123` 用 `rest + 被编辑条件` 构造 `next`，被编辑条件被追加到末尾；`setStateConditions:104-107` 再按原来的 state 槽位依次填 `next`，于是后面的条件被填到前面槽位、编辑条件落到最后。
- **删除靠前的 state 条件**：
  - `[state[0], prop, state[1], actorHas]` 点掉 `state[0]` → `[state[1], prop, actorHas]`：`state[1]` 从 `prop` 后面移到 `prop` 前面。
  - `[state[0], actorHas, state[1]]` 点掉 `state[0]` → `[state[1], actorHas]`：`state[1]` 移到 `actorHas` 前面。
- **后果**：没有条件丢失；非 state 条件都保留；运行时 `checkPreconditions` 是 AND，交换顺序不改变通过/失败结果，所以不是 P2。但“保持原槽位顺序”的注释和本轮目标没有在“减少一条 / 三条中间编辑”下成立；UI 的「条件 1/2」位次和数组顺序会漂移，属 P3。
- **数量增多**：当前 UI 没有“新增一条 targetStateIn”的入口，只能从“无 state 条件”勾选生成第一条；`setStateConditions` 的 `while` 支持 `next` 变多时追加到末尾，但这条路径没有 UI 测试。

### 1.3 去重：排序后的相同集合能去重；未排序的同一集合不去重（P3）

- `toggleState:119` 只把**被编辑条件**的 states 排序；`:123` 的 dedup 按 `states` 长度和逐项值比较，因此只有其他条件本身也已排序时，相同集合才会被判为重复。
- 新测试 `object-interaction-ui.test.mjs:465-479`（`[0,1]` + `[1]`，点掉 0）通过，结果只存一条 `[1]`。

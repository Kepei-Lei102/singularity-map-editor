你在审查一个 React + TypeScript + Vite 写的跑团地图编辑器（目录就是当前仓库）。需求文档在 `需求.md`，源码在 `src/`，命令行工具在 `scripts/`。

请只读代码，不要修改任何文件，也不要运行会写文件的命令（可以运行 `npx tsc --noEmit` 做类型检查）。

审查重点：**会出错的地方**（逻辑错误、边界情况、状态不同步、数据丢失），而不是代码风格。尤其看这几块：

1. `src/store.ts`：撤销 / 重做、合并编辑（coalesce）、批量拖动、试玩沙盒结束时的恢复，会不会丢数据或者撤销到错的状态。
2. `src/memory.ts`、`src/perception.ts`：三态迷雾和玩家记忆；视野"全队共享 / 各自独立"切换时，记忆会不会串、会不会丢。
3. `src/trial.ts`：试玩模式（走格子、回合、标记、Ctrl/Esc 退出），退出后世界是否完全恢复。
4. `src/actions.ts`：导入、导出、保存回硬盘（文件夹格式 world.json + media/）、Rabbithole 导入，会不会写坏文件或丢媒体。
5. `src/npc.ts`、`src/components/NpcPanel.tsx`（最新写的）：按现实日期判断 NPC 何时出现、何时回访；"跳过等待"、重置、导入同名覆盖时保留进度，这些对不对。
6. `src/render.ts`、`src/components/MapCanvas.tsx`：坐标换算、一格多物、迷雾下的显示，有没有越界或者把主持人才能看的东西画给玩家。
7. `src/sync.ts`、`src/components/PlayerView.tsx`：玩家窗口有没有可能看到主持人才能看的信息（隐藏物件、未揭示的线索、NPC 备注）。
8. `scripts/open.mjs`、`scripts/tsmap.mjs`：本地服务器的保存接口，路径处理和文件夹写入是否安全。

## P3

1. **旧 id 已经是合成 id、但没有 `sourceId` 时会归一错**
   `memorySourceOf`（`memory.ts:76`）直接拿整个旧 id 当 source。探针：旧组 `id:'g~版本'`、无 `sourceId`、同贴图，结果同时留下 `g~版本~版本` 和实时组 `g~版本` 两组，没并回去。
   现实迁移里 67 之后的记忆组都会写 `sourceId`，所以这是异常/手工/外部导入数据才可达，定 P3；但文档写的是“没有 `sourceId` 的旧组会归一”，实现和文档不完全一致。测试只覆盖了旧 id 为 `g` 的情况，没有覆盖合成 id + 无 source。

2. **有 `textureKey`、没有 `texture` 的旧组会丢版本**
   `textureKeyOf`（`memory.ts:75`）只看 `texture`，不看旧 `textureKey`；探针输出 `id:'g~none'`、`textureKey:'none'`，原版本消失。A 的 `deleteMedia` 也只在 `g.texture?.mediaId === mediaId` 时才清 `textureKey`（`actions.ts:1040`），因此“只剩 textureKey 的旧组”不会被清掉。定 P3（旧存档/异常数据）。

3. **opacity 三位小数归一，会把小于 0.001 的差异并成同一版**
   `0.3004` 与 `0.3` 的版本键都是 `~0.3`；探针显示旧灰格最后拿的是实时组的 `0.3`，旧记忆不再保留 `0.3004`。`0.0004` 与 `0` 同样并成 `0`。
   0.0004 的 alpha 差在 8 位合成里不到 0.13/255，基本不可见，所以不定 P2；但这是版本语义而不是渲染精度，且新测试只用了 `1` 和 `0.5`，没有任何三位小数用例，去掉 `Math.round` 后测试仍是全绿。

4. **`groupRevs` 没有测试钉住，实时组同 id 时会覆盖旧 rev**
   `memory.ts:107` 对实时组执行 `nextRevs.set(id, rev)`，会覆盖 `memory.ts:94` 刚从旧组并进来的 rev。正常 `rev` 单调递增时这是对的（当前 rev > 旧 rev）；但导入数据/手改 `observationSeq` 时旧 rev 可能更高，会丢。删掉 `memory.ts:110` 的 clean、或删掉 `memory.ts:94` 的旧 rev 合并，现有测试都仍全绿，说明 rev 行为没有被测试覆盖。定 P3。

5. **`pruneMemory` 会清组，但不清理 `groupRevs`**
   探针：`L.seen.groups` 清空后 `L.seen.groupRevs` 仍保留 `{'g~版本':5}`。`mergeLayers` 只遍历实际存在的组 id，所以 stale rev 不影响渲染；属残留数据。新测试只断言组清空，没有断言 rev 同步清掉。

6. **旧组与旧组之间同 source/同版本的并组没有被测试钉住**
   把 `memory.ts:91` 的并集改成 `? before` 后所有测试仍绿（22/22）。原因是新测试“旧 id 归一”同时有实时组，实时循环又补上了并集；真正“两个旧灰组同版本、没有实时组”的场景没有覆盖。

7. **A 的小补丁仍有测试缺口**
   `deleteMedia` 的 `textureKey` 清理去掉后测试仍全绿；`m.seen.groups.every(g => g.texture === undefined)` 只查 texture，不查 textureKey。视图层 `m.views` 的贴图清理仍无测试；`sourceId` / `groupRevs` 的清理也仍未覆盖。这是 68 延续的 P3，不是新回归。

8. **`playerMap` 直接构造层测试离真实 payload 有距离**
   三个新 `playerMap` 测试都直接传 `map` + `L`，没经过 `playerWorld` 的有效性、媒体过滤和 layer 选择；碰撞用例只断言 `startsWith(collision)`，没有钉死后缀 `x1`，也没有覆盖 `collision + 'x1'` 已被实时组占用时应跳到 `x2` 的情况。定 P3。

9. **fit/opacity 版本的测试断言偏弱**

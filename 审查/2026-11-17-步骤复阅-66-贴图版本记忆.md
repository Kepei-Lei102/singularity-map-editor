## 结论

**不可推。P0/P1/P2/P3 = 0/0/1/10。**

按版本拆记忆的**核心语义正确**：灰格留旧 `texture`，可见格按当前
`mediaId~fit~opacity` 生成新记忆组；同一格在灰→可见→灰、换两次图、换回
旧图、全组可见换图、全灰换图、删组、擦可见格、无贴图组的序列里，都实测
没有同一格同时落在两个版本（玩家层）。P2-2 的 `bounds`、组名/媒体名、媒体
去重也仍成立。

但玩家载荷还剩一个 P2：`playerMap` 的 `seen.groups` 直接 `{...g}` 展开，
把内部字段 `sourceId`、`textureKey` 带了出去；`id` 本身又是
`原组id~mediaId~fit~opacity`，等于把版本键也带出去。这与文档“只留 id、
贴图媒体 id 和存储名”不一致，且 `sourceId` 会暴露原组 id。新增测试没有
检查这两个字段，去掉字段的 mutation 仍 14/14 全绿。

## P2

### P2（新）玩家包里的记忆组带 `sourceId`/`textureKey`，`id` 也编码了版本键

- 位置：`src/runtime/sync.ts:296-304`。`seenGroups` 对每个记忆组执行
  `{ ...g, name: '贴图', cells, bounds }`，没有删除 `g.sourceId` 和
  `g.textureKey`。
- 实测 `playerWorld` 的 JSON（B 灰、A 可见、tex1）：
  `seen.groups[0]` 为
  `{"id":"g~tex1~fill~1","name":"贴图","cells":[744],"z":0,"texture":{"mediaId":"tex1"},"sourceId":"g","textureKey":"tex1~fill~1","bounds":{...}}`。
  `sourceId`、`textureKey` 都出现；`id` 里也带 `g~tex1~fill~1`。
- 影响：
  - `sourceId` 是记忆组来自哪个实时组，玩家本来只能看到泛化后的「贴图」，
    现在能拿到原组 id；
  - `textureKey`/`id` 暴露 `mediaId~fit~opacity`，其中 mediaId 虽然已允许，
    但 fit/opacity 和“哪一版”是内部实现；
  - 老工程同步后，旧记忆组也会被补上这两个字段（实测 legacy 记忆组
    `sourceId:'g'`、`textureKey:'tex1~fill~1'`），不是只影响新组。
- 测试没有覆盖：`strip_internal`（在 `sync.ts` 删掉 `sourceId`/`textureKey`
  再展开）14/14 全绿；新测试只检查名字和 `secret-tex`。
- 修法：`playerMap` 的 `seenGroups` 先剥离 `sourceId`/`textureKey`；记忆组
  对玩家的 `id` 也要用不透明的版本号/hash，不能直接用 `textureKey` 拼。
  提到 P2 而不是 P3，是因为这是玩家载荷的字段泄露，不是单纯的宿主内部数据。

## 65 P2-1 拆法复核：主体已闭合

用 shared 与 individual 两种视野、Node bundle 实测：

- A 可见、B 灰，tex1→tex2：玩家实时 A 为 tex2，`seen.groups` B 为 tex1；
  A 也转灰后，`seen.groups` 同时有 tex2(A) 和 tex1(B)，两版各自带自己格子的
  `bounds`。
- 同一格 B：灰→可见（tex2）→灰，B 的旧 tex1 记忆在可见时被 tex2 替换；
  再换回 tex1，B 灰区保留 tex2（它最后一次看见的是 tex2）；没有同格重复。
- 换图两次（tex1→tex2→tex3）时 A 可见：B 灰区始终 tex1；A 转灰后只有
  tex1(B) 和 tex3(A)，tex2 只停留在“A 当时可见”的临时版本，不产生多余记忆。
- 换回旧图：可见 A 回到 tex1 时，旧同版本灰格重新并到同一 id；不会出现
  tex1 两份同格。
- 全组可见时换图：旧记忆组全部格子都是 fog1，旧组被删除；新组是当前图。
  之后全组转灰只有当前版本一份。
- 全灰时换图：没有可见格生成新版本，旧灰格保持旧图，不跟着换。
- 删组：可见格从记忆移除，灰区旧格保留；全灰删组后玩家仍记得旧图。
- 擦可见格：可见格从记忆移除；灰格保留。
- 无贴图组：可见格不生成空记忆组；灰区无贴图组不画。
- 物件组：`syncLayer`/`playerMap`/`drawSeen` 仍过滤 `objectId`。

独立视野：a 看见 A+B、b 只看见 A 时，b 的玩家包是实时 A、记忆 B(tex1)；
a 的包是 A+B 当前 tex2，互不串。共享视野下 B 灰、A 可见也符合。切回
实时、擦格、删组、全可见/全灰均实测；没有 P2 级别的错版本或同格重复。

### P3-2 旧工程记忆组仍保留原 id，实时组/记忆组 id 不隔离，且同纹理会多一份

  `m.seen` 同时有旧 `g`（B 灰、tex1）和新建的 `g~tex1~fill~1`（A 可见、

- 两者格子不重（A fog1 被旧组剔除，B fog2 不进新组），所以不会画两遍；
  但记忆组是同一纹理的两份，且 id 不再隔离。等 B 可见后旧组消失、新组
  吞并，最终会收敛。
- 旧工程 `checkWorld` 通过，没有崩溃。按 P3，不影响本轮玩家显示；若以后
  有消费方按 id 合并实时/记忆，需要统一。

### P3-3 `mergeLayers` 会把同一格放进两个版本组

- `mergeLayers` 先按记忆组 id 分组，再对每个 id 做格子并集；不同版本 id
  (`g~tex1~fill~1` / `g~tex2~fill~1`) 之间没有去重。
- 实测：a 的 `g~tex1` 和 b 的 `g~tex2` 都含同一小格，合并后
  `out.seen.groups` 两个组都含这一格。
- 这条主要落在主持人 `m.seen`；独立玩家用 `m.views[pcId]`，共享只有一层，
  所以玩家包暂不受影响。按 P3；若主持人侧以后用合并记忆渲染，需要按格选
  最新 rev 去重。

### P3-4 `mergeLayers` 对旧 id 仍是“最新贴图覆盖整组”

- 现有 `mergeLayers` 测试仍以同 id `g`、不同 texture 验证“取最新一版”。
  新拆法用版本 id 后，真正的新记忆组一般不再跨版本合并；但旧工程/旧 id
  仍会走这条逻辑。按 P3，跟 P3-2 一起看。

### P3-5 fit/opacity/浮点版本键没有测试

- `textureKeyOf` 用 `${mediaId}~${fit ?? 'fill'}~${opacity ?? 1}`。实测
  fill/1→contain/0.5、再回 fill/1：旧灰格留 fill/1，可见格 contain/0.5，
  再回 fill/1 时同版本并回一组，没有同格重复。
- 测试只换 mediaId，没有 fit/opacity 组合；opacity 用原始浮点字符串，
  浮点抖动会产生额外版本 id（视觉上可能相同）。按 P3；若要稳定，建议把
  opacity 量化后再拼 key。

### P3-6 schema 不校验 `sourceId`/`textureKey`/`bounds`/`groupRevs`

- `cellGroup` 只校验 id/name/cells/texture/objectId/z；`sourceId` 和
  `textureKey` 任意字符串都放过，`bounds` 也不校验，`groupRevs` 完全不进
  schema。记忆组 id 是任意非空字符串，`~` 和长 id 都允许。
- 旧工程/导入数据可以带任意这些字段；`checkWorld` 通过。按 P3，和
  bounds 校验一起补。

### P3-7 `memoryDirty` 的 groups 仍会让每次涂格全量重算

  pointermove 都改 groups，于是每次 update 都跑 `syncMemory`（所有地图、
  所有视野）。触发正确，但可能卡。按 P3；可在 batch 结束或按图局部同步。

### P3-8 媒体删除/删物件仍只清实时组，不清记忆组

## 重点逐条

1. **拆法语义**：满足“灰格留旧图、可见格用新图”；同一格灰→可见→灰、
   换两次图、换回旧图、全可见换图、全灰换图、删组、擦格、无贴图组都实测，
   玩家层没有同格重复/错版本；旧工程和 merge 两个边角在 P3。
2. **playerMap 隔离/bounds/名字/媒体**：
   - 新的版本组 id 与实时组原 id 不同，实时/记忆分离；旧工程 id 不分离（P3-2）。
   - 部分可见实时组不带 bounds；记忆组按记得格算 bounds；实测通过。
   - 组名/媒体名仍泛化成「贴图」；媒体 Set 去重，`pm.media.map(name)` 两个
     都是「贴图」；`secret-tex`/`暗格` 不出现。
   - **JSON 仍带 `sourceId`/`textureKey`，`id` 编码了版本键（P2）**。
3. **merge/prune/独立/共享/旧工程/schema**：
   - 独立/共享都按各自视野拆版本，互不串；prune 只按 fog>0 保留格；
   - 旧记忆组能过 `checkWorld`，同步后补 `sourceId`/`textureKey`；
   - `mergeLayers` 跨版本同格重复（P3-3），旧 id 最新贴图（P3-4）。
4. **测试咬合**：
   - 旧组不保留旧 texture：fail；旧组不保留 fog2：fail；当前可见格不按

   - fit/opacity、浮点 opacity、旧工程 id 隔离没有用例（P3-5/P3-2）。

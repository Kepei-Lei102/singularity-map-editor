## 5) P3 清单

1. **预检查失败会清掉玩家已掷结果**：`trial.ts:1286,1302` 的 `closePendingJudgment` 清 `judgmentResult` 并 `pushJudgeCancel`；实测 P1-B 第二颗已进 `judgmentResult`，删棋子后失败即变 `null`。不升 P1（无广播、目标不存在），但不可恢复；建议写“判定取消：对象已不存在”日志或保留结果供主持人记录。
2. **无窗口 API 路径的 rolledBy/persona**：`settlePendingJudgment(..., false)` 无窗口时 `checkBy='player'`、`persona='player'`、`damage.by='witness'`；正常 UI 走 `byStandIn=true`，故只算边缘。`beginFall` 无窗口用 `host`、新 fallback 用 `witness`，同类角色枚举不统一（`trial.ts:586 vs 1314`）。
3. **`forPlayer` 仍留 `attack`/`standIn`**：`sync.ts:97-107` 删除 `jump/door/fall/place`，但 attack pending 的 `world/judge-request` 仍带 `attackerTokenId/targetTokenId/sharp`；`PlayerView` 不消费，`check` 保留必要。属载荷收窄不彻底，P3。
4. **无 `roundsLeft` 时的 note 文案**：preserve 本身正确；`{label:'濒死'}` 没有倒计时，note 仍说“倒计时没有重置”，略不精确（`trial.ts:733-734`）。
5. **`p.check` 单属性/优势仍降成单骰**：`playerDiceMode` 对任意 `p.check.attrs.length` 返回 single（`sync.ts:91`）；`publishPendingRoll` 对单属性 check 的 `values:[x]` 仍被 `publishJudgment` 拒（`p.check` 要求≥2）。与旧 P3-3 一致，未扩大；多属性 check 实测 2 颗正常。`PlayerView` 和 `JudgmentPanel` 对 `p.check` 优/劣势也都仍按 single，属同一既有问题。
6. **`p.attack`/`p.door` 既有“先结算后 publish”**：`trial.ts:1281,1329-1333`，publish 失败时效果/事件可能已经写入但没有正式判定；本轮未改，P3（不纳入 P1，因为不在 22 修范围，且没有本轮探针）。
7. **`publishPendingRoll` 失败时 pending 保留**：实测第二颗用重复 rollId → 返回“这次掷骰已经发布过”，`pending` 仍在、无事件/无广播；这是正确保底，不是 P1；但玩家需重掷/主持人需处理，提示可更清楚。

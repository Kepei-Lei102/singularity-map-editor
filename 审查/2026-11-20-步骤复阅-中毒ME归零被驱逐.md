## 一、P2-1 修复确认（已收口）

```ts
// 没填 ME 的角色不扣也不拦（和技能/移动的 ME 口径一致），中毒伤害不落地。
if (pc.me === undefined) {
```

## 二、重点确认

### 1. `store.update` 在 `withVision/syncMemory` 之后清状态

**不会造成视野/记忆/脏集不一致。** 状态不参与视野或记忆：

- `src/scene/dirty.ts:50-51` 明确写“棋子改动里只有位置/朝向/姿态/归属会影响视野；改名、HP、状态标签不该触发重算”，`tokensVisionChanged` 只比较 `x/y/subcell/facing/stance/pcId`。
- `src/scene/sightIndex.ts:28-29` 的 `refsOf` 只有地形、cells/fineCells、材质、objects、architecture，没有 token 或 status。
- `memory.ts` 的视线/记忆同步也不读 token `status`。

因此 `src/core/store.ts:161-173` 的清状态放在 `withVision/syncMemory` 之后是安全的；`bumpStateRevs` 只处理物件 `state/stateRev`，与 token status 无关。只有未来状态开始参与视线时才需要重审这个顺序。

### 2. 未填 ME 的 PC

已收口：按“没填”处理，不扣、不写 0、不挂被驱逐；不再越界。见 P2-1 修复确认。

### 3. `continue` / NPC 边界

- 被驱逐状态替换原中毒状态，且没有 `roundsLeft`；后续整轮在 `trial.ts:946` 因 `st.roundsLeft === undefined` 直接跳过，不会自动掉。`continue` 跳过原中毒这一回合的倒计时是作者要的“不跟整轮倒计时”。
- 状态槽只有一个，不存在漏掉第二个状态的场景。
- NPC（`pcId` 为空）不会走 `pc` 分支，也不会挂被驱逐；中毒 ME 伤害对 NPC 本来就不落地，符合范围。
- 测试 `scripts/combat.test.mjs:939-940` 的第二次 `trialEndTurn` 确实进入下一整轮：第一次 `endsRound` 在 `setTr` 里把 `ended` 重置为 `{}`，第二次会重新结算；被驱逐因无 `roundsLeft` 保留，用例有效。

### 4. 自动解除 log 与 `endsWhenMePositive`

- log 已改为动态 label（`store.ts:167-169`）：先取 `const label = k.status.label`，再删除状态，写“解除${label}”；被驱逐仍为“解除被驱逐”，测试断言通过。
- 同一状态删除后下一次 update 不再命中，不会重复写解除 log。
- 中毒归零本身有两条 log（伤害+被驱逐），ME 恢复再一条，属于预期 note 量。
- `endsWhenMePositive` 仍是“带 flag 即自动解除”的语义；见 P3-1。

- 旧版本（本批修复前）没有“被驱逐”：ME0 用例第 933 行会失败，ME 恢复用例第 956 行会失败。

### P3-2 sweep 后连接残留

- `sweepRooms`（`server/index.ts:307-318`）发 `room.closed { reason:'expired' }` 并
  `roomConns.delete`，**不关闭 ws，也不清 `conn.roomId/token/binding`**；
  `conns` 仍保留这些 Conn，直到客户端自己关闭。过期房的主持/玩家还能发：
  玩家 relay → `relay-failed`，host `room.create` → `bad-request`（不是 room-closed），
  连接继续占 `maxConnections` 名额。
- `scripts/server.test.mjs:246-249` 只验证 host relay 回 `relay-failed`，没有验证
  player 侧、host `room.create`、连接是否释放。
- 建议 sweep 对过期房连接 `ws.close(4002,'room closed')` 或清掉 role/roomId；
  至少把“过期后发消息”用例补全。

### P3-3 serve / 生产依赖

- `scripts/serve.mjs:12-16` 用 esbuild 现场打包；`esbuild` 不是 `package.json` 的
  direct dependency（来自 Vite 的 devDependency）。`npm ci --omit=dev` 后
  `npm run server` 会找不到 esbuild；当前只有“带 dev 依赖”的本地/测试环境能起。
- `serve.mjs:17-22` 不传 `allowNoOrigin`，也没有 `ALLOW_NO_ORIGIN` 环境变量；
  文档 `:108` 说非浏览器客户端要 `allowNoOrigin`，但 `npm run server` 无法配置。
- `serve.mjs:10-16` build/start 失败时没有 `try/finally` 清 temp；正常 SIGINT/SIGTERM
  路径有清。
- `serve.mjs` 不设 `NODE_ENV`，默认 `allowNoOrigin=true`；生产部署必须自己
  `NODE_ENV=production`，否则非浏览器无 Origin 会放行（P3-5 一并）。

### P3-5 配置与限流边界

- `MAX_ROOMS/MAX_CONNECTIONS/MAX_MESSAGE_BYTES` 用 `Number()`，没有正整数校验；
  `''`→0、非数字→NaN 会让上限失效或 `maxPayload` 行为异常。
- 速率限制在 `isEnvelope`/`from` 检查之后（`server/index.ts:143-158`）：
  非法 JSON、坏信封、带 `from` 的请求不计入 60/s，可无限刷；且是每连接，
  没有每 IP/全局限制。`maxPayload` 8MB 也没有总量限制。
- 这些是 P3，但在上线前应至少加配置校验和“坏信封也计数”。

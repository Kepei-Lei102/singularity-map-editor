## 可选参数 hook

- 默认 `subscribeAssetTransferStats`、`assetTransferStats` 是模块级函数，身份稳定；`delayMs` 默认常量150。`MediaDock` 不传参数，依赖数组三个值稳定，**生产里不会因 props 函数身份变化重复订阅**。
- `useState<AssetTransferStats>(() => snapshot())` 是 lazy initializer，初次拿当前快照，正确；默认 `assetTransferStats` 无副作用。
- `useEffect` 依赖 `[subscribe, snapshot, delayMs]`：如果将来有调用方传内联函数，每次渲染会 cleanup/re-subscribe，并丢掉未触发的 timer；当前唯一调用点是 MediaDock，不受影响。`snapshot` 换了但未通知时 state 不会立即同步，属注入 API 的边界，P3。
- 导出 hook 用于测试合理；生产 bundle 中它仍被 MediaDock 使用，deployment 的 `const transfer = useThrottledAssetTransferStats()` 守卫仍在。

## ticker 边界

- `rateFromSamples` 加 `+1900ms -> 500`、`+2001ms -> 0`。`+1900` 会咬住旧的“最后两次采样之间”公式（旧公式返回1000），`+2001` 覆盖 stale 归0。
- **`+2000ms` 没断言**；按当前实现，base 循环会把最后一个样本（at=now-2000）当成 base，seconds=2，bytes差0，返回0。也就是说恰好2秒时速率已归0，而 docs 说“超过2秒没有新块会回0”，边界语义不完全一致。不在本包改可以，但应记为 P3。
- **仍没有“有 flow 时 ticker 续排/结束后停止/2秒归0”的行为测试**；这里只测纯函数，ticker 本身仍只有源码守卫。

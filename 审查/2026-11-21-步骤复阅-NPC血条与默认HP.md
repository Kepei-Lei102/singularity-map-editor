## 1. `npcHpPool` 的默认值与夹取边界

`src/rules/combat.ts:150-162` 是唯一口径，实测（probe）：

| 输入 | 输出 | 说明 |
|---|---:|---|
| `{}` | `{hp:10,max:10}` | 都没填 → 默认 10 / 满血 |
| `{hpMax:0}` | `{hp:10,max:10}` | ≤0 → 默认 10 |
| `{hpMax:-1}` | `{hp:10,max:10}` | 负数 → 默认 10 |
| `{hpMax:0.4}` / `{hpMax:0.5}` | `{hp:1,max:1}` | 正小数先四舍五入再 `max(1)` |
| `{hpMax:1}` | `{hp:1,max:1}` | 合法小上限 |
| `{hpMax:10.4}` / `10.6` | `{hp:10,max:10}` / `{hp:11,max:11}` | `Math.round` |
| `{hp:15,hpMax:10}` | `{hp:10,max:10}` | 超上限夹到上限 |
| `{hp:-3,hpMax:10}` | `{hp:0,max:10}` | 负 HP 夹到 0 |
| `{hp:5,hpMax:20}` | `{hp:5,max:20}` | 显式 HP 保留 |
| `{hp:5.5,hpMax:20}` | `{hp:6,max:20}` | HP 四舍五入 |
| `{hp:20.9,hpMax:10.1}` | `{hp:10,max:10}` | 先取整上限，再夹 HP |

- **没有 `hp`、也没有 `hpMax` 的旧 NPC** 读出来就是 10/10；不会再有“没有血条”的 NPC。

## 2. `hpOfToken` / `canTarget` / `attackTargets` / `attackContext`

- `hpOfToken`（`src/rules/combat.ts:248-253`）：NPC 读 `npcHpPool(t).hp`；PC 读角色卡；PC 找不到角色卡时返回 `Infinity`（旧行为，未改）。NPC 路径正确。
- `canTarget`（`:236-245`）：
  - NPC `hp<=0` **不拦**，符合“0 HP NPC 仍可打”；
  - PC `hp<=0` **拦**（理由“目标已经倒下”）；
  - 尸体本身没有在这里判，但 `attackTargets` 先 `filter(!t.corpse)`，`attackContext` 也先拒绝尸体；正常路径不会打到尸体。`canTarget` 单独被调用时会放过尸体，见 P3-7。
- `attackTargets`（`:279-296`）：
  - 尸体过滤；
  - NPC `hp` 用 `npcHpPool`，0 HP 也返回数字；
  - PC 的 `dying`（`status.label === '濒死'`）先拦，其余走 `canTarget`；
  - 实测：PC `hp0` 无状态 → `canHit:false`、理由“目标已经倒下”；NPC `hp0` → `canHit:true`；NPC `status:'濒死'` → `canHit:true`；NPC `down:true` → `canHit:true`；尸体不出现。
- `attackContext`（`src/runtime/trial.ts:1143-1147`）现在有三道目标检查：
  - `target.corpse` → “已经死了，不用再打”；
  - PC `status:'濒死'` → “已经濒死了”；
  - **PC `hpOfToken(w,target) <= 0` → “已经没有 HP，不能再打”**（P2-1 修复）。
- **目标列表与直接发起入口现在口径一致**：PC 0 HP 两边都拒；NPC 0 HP 两边都放。

## 6. 硬上限、技能抬上限与“只改 hpMax”

- 普通攻击、借机、摔伤、tick、救治、机器人都在写 HP 前经过 `npcHpPool`，**不会超过当前 `max`**；Inspector 的 HP 输入也用 `max` 夹。
- **技能抬 `hpMax` 后的行为**（直接改棋子模拟，因为当前 `src/rules/skills-data.ts` 没有实际改 `hpMax` 的生产技能）：

  - `hp` 未填、`hpMax:20` 时按满血 20；这是“hp 没填按满血”的自然结果；
  - 上限降低时 `npcHpPool` 把当前 HP 夹到新上限；
  - 没有发现“只改 hpMax 就把 hp 清零/重置”的路径。
- **“技能可提高上限”目前没有生产技能验证**：代码只保证字段可变，Inspector/外部 update 能改；如果这一步要交付某个具体技能，需另补实现与测试（P3-5）。

## 7. Inspector 的默认/清空/边界

`src/components/Inspector.tsx:762-777`、`src/components/fields.tsx:16-23`：

- 未填 `hpMax`：显示 10；未填 `hp`：显示 `npcHpPool(t).hp`（满血）；默认显示正确。
- HP 输入 `min/max` 用 `npcHpPool`，`onChange` 先 `Math.max(0, Math.min(Math.round(v),max))`，再 `x.hpMax ??= max`；输入超过上限会夹。

- 提示文案“NPC 默认 HP 上限 10；不填上限就是 10，填了才按填的值硬夹”与显示/默认一致。

**可提交。P2-1 已收口。** `attackContext` 现在与 `canTarget` 一致：PC 0 HP（含仅 down、无濒死状态）直接 `trialAttack` 会被拒绝，不写 `0→0`、不置 down、不落事件；NPC 0 HP 仍可打且不显示 −N；旧 PC 0 HP 成功用例已改成拒绝用例，并补了 `canHit === false`。`npcHpPool` 的默认值、满血、上下夹取、`hpOfToken`/`attackTargets`、六条 HP 路径、Inspector 有效上限显示均成立。

剩余 P3（原始 `hpMax` 不归一/清空、手填小数口径、借机 PC 既有例外、测试缺口、旧档迁移、无生产技能、注释/helper、down 缺 hp）均不阻断本次提交。若作者要把借机 PC 0 HP/濒死也统一硬拦，或要把小数编辑与 helper 完全对齐，建议另开步骤处理。

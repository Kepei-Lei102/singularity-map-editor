## 重点结论（按作者五点）

### 1. `ended`、`turn`、手动切人

- **正常顺序正确**：结束过的 tokenId 记在 `ended`；只有 `t.players.every(...)` 才结算，`turn` 只在整轮结束 +1。首人结束不扣流血、第二人结束才结算，作者测试覆盖。
- **重复结束不提前结算**：同一个人再结束只重写 `ended[tokenId]`，不会误触发整轮；但每次结束都重置全队资源（见 P2#1）。
- **0 人**：`endsRound = t.players.length === 0 || ...` 恒真；没有玩家时按空格也会结算一次状态并 `turn+1`，属于边界未挡（P3#2）。
- **死亡/昏厥玩家**：仍留在 `t.players`，不会自动算“已结束”。主持人必须切到尸体/昏厥者再按空格，否则整轮永远不结算；没有“提前结算”，但存在漏结算风险（P3#2）。

### 2. 流血/中毒/眩晕与 `skipTurns` 双字段

- 流血/中毒：`roundsLeft` 正常递减；先掷伤害再减 1，最后一回合仍会跳一次伤害；不挡行动（`blocksAction:false` / 默认 false）正确。
- 眩晕：`skipTurns` 在 `switchTrialPlayer` 进入时消耗；整轮结算显式跳过 `skipTurns` 状态，不跟 `roundsLeft` 一起减；在自己的回合结束时若 `skipTurns<=0` 删除状态。多人按 Tab 切换的路径基本自洽。
- **单人/当前角色路径会卡死（P1）**：`trialEndTurn` 只清 `skipTurns<=0` 的当前状态；而 `skipTurns:1` 只在 `switchTrialPlayer` 里减。单人战斗里给当前角色上眩晕后，正常按空格结束回合，`turn` 从 1 涨到 4，`skipTurns` 始终为 1，状态一直在，动作一直挡；只有再点同一个玩家/Tab 触发一次 switch 才会消费。实测 `setTrialStatus('眩晕',5,{skipTurns:1,blocksAction:true})` 后连续 3 次 `trialEndTurn`：`turn=4, skip=1, status=眩晕`。
- 自定义 HUD 输入“眩晕”不带 `skipTurns`（只有预设带），会变成“按 roundsLeft 倒计时、挡行动但不跳过回合”的另一种眩晕；字段语义不统一（P3#3）。

### 3. 流血归零与 NPC

- PC 路径正确：流血扣到 0 转 `{label:'濒死', roundsLeft:3}`，不昏厥；三整轮后 `settleDeath` + `corpse=true`。
- **NPC 濒死到点不清倒地（P2#2）**：`trialEndTurn` 濒死分支只有 `if (k.pcId) { const pc...; if (pc) { settleDeath; k.corpse=true } }`，NPC 没 `pcId` 时只 `delete k.status`，不设 `down/corpse`。实测 `hpMax:80, hp:0, status:{label:'濒死',roundsLeft:1}` 的 NPC 结束一轮后 `status=undefined, corpse=undefined, down=undefined, hp=0`，还站着；之后 `hpOfToken` 对 NPC 返回 `Infinity`，还能继续被攻击。流血把 NPC 打到 0 会进濒死，但到点同样站着。
- PC/NPC 的“NPC 不撕卡”口径应落成 NPC 至少 `down=true`（或明确 corpse），不能站着且 HP 0；NPC 流血转濒死也没有“流血倒下”日志（PC 分支有，NPC 分支没有，P3）。

### 4. 状态挡行动

- **攻击/移动/姿态三条主路径正确**：`trialAttack` 的 `attackContext`、`trialMoveStep`、`trialStance` 都走 `statusBlocksAction`；流血/中毒默认放行，眩晕/其余状态挡住。攻击发起和结算都复用 `attackContext`，中途补状态也会被二次拦截。
- **其他动作入口漏挡（P2#3）**：`trialRescue`、`trialOpenDoor`、`trialPickLock`、`trialRamDoor`、`trialSense`、`trialRun`、`trialOpportunityAttack` 都没有 `statusBlocksAction`，只依赖 `acted`。当 A 结束回合把全队 `acted` 清空后，眩晕 B 可以成功救治濒死队友。实测：B `skipTurns:0, blocksAction:true`，A 结束后切到 B，`trialRescue('tc',{roll:30})` 返回成功、目标回 1 HP。眩晕的“挡行动”没有覆盖这些入口；借机攻击也不检查眩晕敌人。
- 流血/中毒没有误伤：攻击/移动/姿态都放行。

### 5. 文档与测试

- **文档第 3 行仍写“流血/中毒/眩晕的自动结算还没接”**，和 v0.2 已落地矛盾（P3#1）。
- `docs` 文件列表把 `rules/combat.ts` 写成“回合状态（纯函数）”，但实际结算在 `trial.ts` 内重新实现；`rules/combat.ts` 的 `CombatEffect/tickEffects` 仍是旧 `perRound/target` 口径，未接新 `damageDie/damageTarget`，两套状态 schema 并存（P3#1）。
- 33 条 combat 测试没有覆盖：单人眩晕按空格路径、NPC 濒死到点、NPC 流血归零、同一轮手动切人后的 `acted/charge`、`perRound` 固定伤害路径。作者三个突变都能红，但上述行为都全绿（P3#2）。

## P1

1. **单人/当前角色眩晕永不解除**：`trialEndTurn` 不消费当前 `skipTurns`，正常空格路径 `turn` 一直加、状态一直挡；只有额外 switch 才能解锁。建议整轮边界或下一次“当前角色重新开始回合”时消费/清除，并补一条“单人眩晕连续按空格”测试。

## P2

1. **整轮资源仍按“每个玩家结束”重置**：`trialEndTurn` 每次结束都 `acted:{}`、`moved:{}`、`movePoints` 全队重算、`opportunityUsed` 全清，并对所有玩家 `tickCharge`。实测 A 结束（B 未结束）后 B 的 `acted:true` 被清空，B 的 `charge` 还从 0 涨到 0.5。手动切人时 B 可在同一整轮内再次攻击/移动；多人队蓄力按人数加速，和 `turn` 只在整轮 +1 的口径冲突。应在单人名下清表，且 `charge/opportunity` 只在整轮边界推进。
2. **NPC 濒死到点不倒地**：如上，NPC 站着、HP 0、可再被攻击；流血归零 NPC 同样。至少设 `down=true`（或 corpse）并写日志，补 PC/NPC 双路径测试。
3. **眩晕只挡攻击/移动/姿态，漏挡救治/开门/撬锁/撞门/感知/跑法/借机攻击**：`acted` 被别的玩家结束清掉后可实际执行；应把 `statusBlocksAction` 下推到所有动作入口或在入口统一 guard。

## P3

1. **文档/规则双口径**：`docs/战斗模式-v0.1.md:3` 仍写自动结算未接；`rules/combat.ts` 的 `CombatEffect/tickEffects` 与新 `TokenStatus` 的 `damageDie/damageTarget` 并存且生产未用。
2. **死亡/昏厥玩家不自动 `ended`，0 人 `endsRound` 恒真**：尸体/昏厥者需主持人手动结束，否则漏结算；`t.players.length===0` 时任何一次结束都会结算并 `turn+1`。建议终态自动记 ended，0 人直接 return。
3. **状态字段/HUD 边界**：自定义输入“眩晕”不带 `skipTurns`；`switchTrialPlayer` 每次点同一个人都会消耗一层 `skipTurns`；`perRound` 固定伤害路径无测试；NPC 流血无日志。都不影响主路径，但建议收紧字段语义。

## 结论

- **不可推。** 回合骨架主路径和三种状态的基本结算成立，但单人眩晕死锁、整轮资源按人重置、NPC 濒死不倒地、眩晕漏挡其他动作都是实际行为问题，需先修 P1/P2；P3 文档/测试收口可随后补。

### 2.3 ObjectInteraction：`preconditionStates` 合并 / repair 去重

**P2-1（本轮唯一 P2）：多条 `targetStateIn` 的 UI 合并按“并集”展示，编辑时塌成一条，改写运行时语义。**

- `src/components/ObjectInteraction.tsx:60-63`：
  ```ts
  const all = (ov.preconditions ?? []).flatMap((p) => p.kind === 'targetStateIn' ? p.states : []);
  return [...new Set(all)].sort((a, b) => a - b);
  ```
  这里做的是 **并集**。
- `src/rules/interaction.ts:704-718` 的 `checkPreconditions` 对 `preconditions` **逐条 AND**；`:710` 每条 `targetStateIn` 都必须包含目标状态。因此两条 `{states:[0]}`、`{states:[1]}` 是**交集为空、任何状态都不成立**；但 UI 会把 0 和 1 都显示为勾选，看起来像“0 或 1 都允许”。
- `src/components/ObjectInteraction.tsx:98-104` 的 `toggleState` 先取上述并集，再 `setConditions(i,'targetStateIn',[{kind:'targetStateIn',states:next}])`，**把所有 `targetStateIn` 合并成一条**。
- 新测试 `scripts/object-interaction-ui.test.mjs:425-441` 正好复现了这个问题：数据 `[0]`、`[1]` 两条 → UI 两个勾选框都为 checked（`436-437`）→ 点掉 0 后存储变成 `[{kind:'targetStateIn',states:[1]}]`（`440`）。**测试只断言显示和存储，没有断言运行时语义；测试把“从不可能”改成“状态 1 可成立”当成了预期。**
- 我用 `checkPreconditions` 实测：两条 `[0]`/`[1]`、目标状态 0 时返回 `ok:false, unmet:[{states:[1]}]`；改成单条 `[1]` 后状态 1 返回 `ok:true`。也就是说一次复选框编辑可以静默把动作从“永远不能发动”变成“状态 1 能发动”。
- **修法**：`preconditionStates` 若仍要合并显示，应取**交集**而不是并集；或者在 UI 中按每条 `targetStateIn` 分开展示/编辑，避免 `toggleState` 把多条塌成一条。至少不要用并集驱动单个写回。补一条运行时断言（不只看 checked/存储）。
- **严重度 P2**：这是对合法世界数据的静默语义改写；UI 正常只写一条，所以不是常规流程必现，但它不是纯样式/文案问题。

**其余两项语义核对**

- `src/components/ObjectInteraction.tsx:54` 的 `splitTags` 去重是输入层幂等操作；重复 `targetHasProp`/`actorHas` 是 AND 同一条，去重不改变运行时结果。UI 测试 `scripts/object-interaction-ui.test.mjs:406-411` 用重复“易燃物”断言只写一条，行为正确。
- `src/core/schema.js:144-157` 的 repair 去重：
  - 同 kind 同值（`targetHasProp:prop`、`actorHas:tag`、`targetStateIn:states.join(',')`、`withinRange:cells`、`targetEnabled`）删重复；这些重复在 `checkPreconditions` 里是幂等 AND，**不改变语义**。
  - 不同值的两条 `targetStateIn` **不会**被 repair 合并，运行时 AND 语义保留；问题在 UI 编辑（P2-1），不在 repair。
  - `scripts/object-interaction.test.mjs:405-419` 只测了 `targetHasProp` 重复；`targetStateIn`/`withinRange`/`actorHas`/`targetEnabled` 的重复没有测试。**P3-4。**

## P0：`migrateWorld` 用“字段缺失”区分新旧档，导致新格式的“存在但无人知道”被误迁成“全队知道”

### 位置

- `src/scene/memory.ts:385-392`：迁移条件只有
  `if (t.weakness?.psychological && !t.weaknessKnownBy)`。
- 这段迁移**不在** `if (v1)` 里，v2 世界也会执行。
- 调用点不止读档：`src/core/store.ts:29`（load）、`src/core/store.ts:396`（`replaceWorld`）、`src/runtime/actions.ts:1026`（工程导入）都会走 `migrateWorld`。

### 为什么是错的

旧档的 `weakness.psychological: true` 表示“队里已经知道”；新格式的 `weakness.psychological: true` 表示“客观上有这条弱点”。两者字段形状完全相同，`weaknessKnownBy` 缺失既可能是旧档，也可能是新档里“宿主勾了有心理弱点、但还没勾谁知道”。当前代码把后者也当成旧档迁移：

1. 在新 v2 世界（`emptyWorld().version === 2`）里，目标 `weakness: { psychological: true }`、没有 `weaknessKnownBy`；
2. 经过 `replaceWorld` 或读档后，目标变成 `weaknessKnownBy = { a: { psychological: true }, b: { psychological: true } }`（实际探针结果）；
3. `knowsPsychologicalWeakness` 对所有队内 PC 返回 true；
4. `playerToken` 据此把 `weakness.psychological: true` 下发，玩家端直接看到“这个人有心理弱点”；
5. `trialPsychUtterance` 会掷 1D8 并提示“已知弱点 1D8”，`settleAttack` 的 007/灵巧会抽两种附加效果，而不是一种。

实际探针：

- v2 目标心理弱点存在、`weaknessKnownBy` 缺失，`replaceWorld` 后 `weaknessKnownBy` 变成 `{a:…, b:…}`；
- 同一世界目标在玩家 `a` / `b` 的可见视野里，`playerWorld(a)`、`playerWorld(b)` 的该 token 都是 `weakness: { psychological: true }`；
- 用“不知道”的说话人跑 `trialPsychUtterance`，传给 roller 的骰面是 `[8]`（正确应为 `[4]`），提示“已知弱点 1D8”；
- 007-9-203 对“不知道”的目标跑到 `settleAttack`，仍出现“降智 + 恐惧”两种 rider（正确应只抽一种）。

现有测试正好绕开：

- `scripts/psychology.test.mjs:56-67` 的“不知道 1D4”用 `roller: () => 4`，1D4 和 1D8 都返回 4，ME 都是 6；这个断言不能证明骰面是 4。因为迁移 bug，该用例实际已经是 1D8，却仍通过。
- `scripts/psychology.test.mjs:119-135` 的“旧档迁移”用的是 `api.emptyWorld()`（version 2）。v2 本身既是旧档也是当前格式，这个夹具只能证明“缺字段就迁”，不能证明“新档私有的存在但无人知道不被迁”；缺少新旧同形的歧义用例。
- `scripts/attack-skills.test.mjs:136` 给灵巧攻击目标补了 `weaknessKnownBy`，只测了“知道”的一侧；没有“目标有心理弱点、攻击者不知道”的集成用例。
- 没有测 `replaceWorld`/读档往返后新档目标的 `weaknessKnownBy` 是否仍为空。

### 旧档口径本身是对的部分

- 旧档当前就是 v2；`emptyWorld()` 的 v2 可以作旧档夹具。
- 旧 `true`：迁移成“有心理弱点 + 当前队内每个 PC 的 knownBy”；这点符合要求。
- 旧 `false`：不迁成存在（当前代码不写 `weaknessKnownBy`，`weakness.psychological` 保持 false）；这点也对。

问题只在**新旧分界**：旧 v2 和新 v2 的 `weakness.psychological` 同形，不能拿 `weaknessKnownBy` 是否存在当旧档标记。未提交前已用当前代码保存的 v2 新档无法与旧 v2 区分；本包未发布，建议重存/清理；若已有此类档，需要额外的格式标记或人工核对。

### 必须的修法

关键点：**不能简单改成“只有 version === 1 才迁”**。旧档本身就是 v2（`src/core/types.ts:849`、`src/core/defaults.ts:52` 当前都是 2；旧工程也是 2），那样会把真正的旧 v2 档漏掉。必须在 `weaknessKnownBy` 缺失之外增加显式的新旧格式标记。

首选：给存档格式加版本。

1. 把 `World.version` 提到 3；`migrateWorld` 只对 `< 3` 的来源（v1/v2/无版本）执行旧 known 迁移，新 v3 的 `weakness.psychological: true` + 缺 `weaknessKnownBy` 必须保持“存在但无人知道”。
2. 同步更新 `src/core/types.ts`（version 字面量）、`src/core/defaults.ts`（`emptyWorld`）、`src/core/schema.js:519`（`version !== 3` 报错）、`src/runtime/actions.ts` 的 `parseWorld`（当前 `subterrain.test.mjs:249-252` 还把 v3 当非法版本，需改成 v3 合法、v4/未知非法）、`migrateWorld` 末尾的 `w.version`。
3. 旧档口径不变：旧 true → 存在 + 全队 knownBy；旧 false → 不迁成存在；迁移条件仍保留 `t.weaknessKnownBy === undefined`，旧档已经有该字段的不要覆盖。
4. 不 bump 的备选方案也必须定义新格式不变量：`weakness.psychological: true` 必须带 `weaknessKnownBy`（可为 `{}`），Inspector 勾“有心理弱点”时初始化 `{}`，导入/保存归一化；迁移只把缺字段当旧档，且不能在新世界 `replaceWorld` 路径上把缺字段当旧档。这个方案仍然对“新世界缺字段”敏感，必须有 schema/测试兜住。
5. 迁移测试：旧 v2 true 仍迁成存在 + 全队、旧 v2 false 不迁成存在；新 v3 true 无 knownBy 保持无 knownBy；新 v3 knownBy 只含 a 仍只含 a；`replaceWorld`/读档往返后“无人知道”仍无人知道。
6. 玩家投影/攻击测试：玩家 `a` 不知道时 `playerWorld(a)` 不出现 psychological；攻击者 a 不知道时 rider 只抽一种；知道的是 b、攻击者 a 时也只抽一种。
7. 给“不知道 1D4”的测试换一个能验骰面的 roller（例如断言 `sides === 4`），不要只用同一个点数 4。

## P2：NPC 目标 ME 归零后的“被驱逐”不会随 ME 恢复自动解除

### 位置

- `src/runtime/trial.ts:1258-1261` 会给**任意 token**（包括 NPC）写
  `status = { label: BANISHED_LABEL, blocksAction: true, endsWhenMePositive: true }`。
- `src/core/store.ts:204-221` 的自动解除只处理 PC：
  `const pc = k.pcId ? d.party.find(...) : undefined; if (pc && pc.me >= 1) { delete k.status; }`
  NPC 走 `k.me`，`pc` 为 undefined，永远不进解除分支。

### 探针

- NPC 目标 `me: 5`，嘴炮命中 8 → `me: 0`，`status: 被驱逐`；
- 之后 `update` 把该 NPC 的 `me` 改成 1 → `me: 1`，`status` 仍是 `被驱逐`；
- 同样流程换成 PC 目标，`update` 后 `status` 正确清空（现有 `psychology.test.mjs:97-107` 只测了 PC）。

### 影响

NPC 的心理真伤目标 ME 恢复后仍然“被驱逐 + blocksAction”，只能主持人手动点状态 ×；这与 `store.ts:204-205` 注释“不论 ME 是怎么恢复的”和 `docs/战斗模式-v0.1.md:111` 的规则不一致。范围窄（NPC），定 P2。

### 修法

自动解除把 NPC token 自身的 `me` 也算进来：

```ts
const pc = k.pcId ? d.party.find((x) => x.id === k.pcId) : undefined;
const me = pc ? pc.me : k.me;
if (me !== undefined && me >= 1) { ... }
```

补 NPC 用例：`me:5 → 0 → 1`，断言 `status` 为 undefined。

## P2：事件账本在“没填 ME / 已 0 ME”时仍记 1D8/1D4，像是扣了伤害

### 位置

- `src/runtime/trial.ts:1248-1277`：
  - `before == null`：只改 `msg`，`deltas` 为空；
  - `after === 0 && before === 0`：只给 `msg` 追加“已经没有 ME”，`deltas` 仍为空；
  - 但 `appendEvent(... note: hit ? (known ? '心理弱点已知：1D8 ME' : '心理弱点未知：1D4 ME') : '落空')` 不看是否真的落地。

### 探针

- 目标没有 ME：事件 note = `心理弱点已知：1D8 ME`，`deltas = []`；
- 目标 ME 已经是 0：事件 note 同上，`deltas = []`；
- 两种情况的 `trial.msg` 分别写了“没填 ME，心理伤害没落地”/“已经没有 ME”，说明主持人提示是对的，事件账本没有同步。

### 影响

状态 delta 本身没有漏（没有状态变化就不该有 delta）；漏的是事件账本对“为什么没扣”的记录，账本会声称一次不存在 1D8/1D4 扣血。属于窄范围真实 bug，定 P2。

### 修法

按实际落地结果拼 `note`：

- `hit && before == null` → `……：目标没填 ME，伤害未落地`；
- `hit && before === 0` → `……：目标已无 ME，未再扣`；
- 正常扣血才写 `已知/未知 1D8/1D4`；
- 落空仍写“落空”。

补事件断言：无 ME、已 0、正常扣到 0 三种，至少检查 `event.note` 与 `event.target.deltas`。

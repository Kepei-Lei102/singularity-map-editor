## 级联覆盖与归一

`syncObjectGroups` 放在 `syncMemory` 里能覆盖本轮所有路径，原因是相关修改都会让 `memoryDirty` 为真：

- 物件移动 / 改尺寸 / 改锚点 → `objects` 引用变；拖动和 Inspector 走 `update`，`syncMemory` 执行。
- `moveSlidingObject` → 改 `objects`；探针确认新组格子跟到新脚印，`sliding.test` 新测试也能咬住。
- `resetRoom` / `applyRoomLayout` → 改 `objects`；探针确认 resetRoom 后格子回到复位点脚印，`applyRoomLayout` 走同一 `update`。
- `reshapeMaps` → `cells`/`fineCells`/`groups` 和物件坐标都变；测试确认扩图后按新脚印重算；物件被裁掉时 `m.groups` 和记忆组按 `liveObjects` 删除。
- `duplicateMap` → 地图数变；物件 id 重映射，`copy.groups` 的 `objectId` 重映射到副本物件，测试确认只有一个物件组。
- `replaceWorld` / 导入 → 直接 `produce(withVision(migrateWorld(w), …), syncMemory)`，旧异形/单格组在进世界时归一到脚印。
- `undo` / `redo` 不调用 `syncMemory`，但每个快照都是同步后的世界；探针确认 undo/redo 的组格子与当时物件脚印一致。
- 试玩：`beginSandbox` 记住原世界；试玩中的 `update` 仍走 `syncMemory`；`endSandbox` 换回原世界。探针在真正进入试玩后确认试玩中格子跟脚印，结束试玩恢复原格子。
- `deleteMapObject` 同时删 `m.groups`、`m.seen.groups`、各 `m.views[*].seen.groups` 的物件组；删物件测试确认。

没有发现“改了物件却漏掉同步”的 update 路径；补丁也没有依赖 `m.width/height` 变化必须单独触发，因为 `reshapeMaps` 总是同时改 cells/fineCells。

## 归一安全性

- `cells` 强制成 `objectFootprintCells`，`bounds` 用 `groupBounds` 重算；空脚印时删 `bounds`，不会留下违法矩形。
- 旧异形/单格组进 `replaceWorld` 后被归一；测试和探针都确认。
- `schema` 新查“同一物件最多一个组”；`cellGroups` 原有检查仍然覆盖 cell key、texture、objectId 存在性、bounds。
- `deleteMapObject` / `reshapeMaps` 会删悬空的物件组；`duplicateMap` 只复制可重映射的物件组。
- 记忆层本来就把 `objectId` 组排除在贴图记忆之外（`memory.ts:95/101`），旧记忆里的物件组会被 `syncLayer` 丢掉；探针构造 `seen.groups` 物件组后，`clearObjectTexture` 后内存里也不再有 objectId 组。
- 渲染层在 `render.ts:42/47` 已经过滤 `objectId` 组；3-A 没有意外把它当普通地面组画出来。

## P3

1. **`setObjectTexture` 不校验 `mediaId` 和 `fit`，会返回一个 ID，但世界立刻不合法。**
   探针：`setObjectTexture(..., 'missing')` 返回组 ID，随后 `checkWorld` 报“找不到媒体 missing”；传 `fit: 'weird'` 返回 ID，`checkWorld` 报“只能是 fill / contain”。当前没有 UI 调用者，3-B 接 UI 时应从图片列表取值；但作为数据 API，至少应在 `set` 前查 `world.media` 和 `fit` 枚举，避免调用方拿到 ID 后才发现世界非法。无测试。

2. **schema 只查重复、不查 `cells` 等于脚印，和运行时归一存在不一致；直接 `update` 造两个组不会被运行时合并。**
   探针：直接往 `groups` 塞第二个 `objectId` 组，`syncObjectGroups` 会更新两个组但不会去重，`checkWorld` 报“不止一个”。直接造异形 cells 则会被下一次 `syncMemory` 校正回脚印（探针确认），所以 UI 路径没有“自由涂形状”的漏洞；但 `update` 本身不拒绝重复组，自动保存可能先写入非法状态，直到下一次 `checkWorld` 才暴露。schema 不强制脚印是旧数据兼容的有意选择，运行时归一兜底；这个“update 不守 schema”的不变式没有测试。

3. **`setObjectTexture` 自己的 cells/bounds 重算没有被测试单独咬住。**
   删除 `setObjectTexture` 里的 `g.cells = objectFootprintCells(...)`（保留 `syncObjectGroups`）后 `objectgroup.test` 12/12 仍绿，因为同一个 `update` 里的 `syncMemory` 会补正；这说明测试只钉住了共享同步路径，没有钉住 setter 本身。删除 `syncObjectGroups` 里的 cells 赋值或 bounds 重算则分别有 4 个和 2 个测试红，主路径是有效的。setter 的重复计算是防御性冗余，不是错误，但属于测试盲区。

4. **级联测试有缺口，`sliding.test` 改 fixture 削弱了对 object group 的 `shiftGroups` 覆盖。**
   - 删除 `syncObjectGroups`：objectgroup 4 个失败，sliding 新测试失败；但删 `reshapeMaps` 里的物件组 prune 后 12/12 仍绿（没有“物件被裁掉后物件组一起消失”的测试）。`deleteMapObject` 对 `m.seen.groups` / `m.views` 的 prune 也没有测试。`applyRoomLayout` 的物件组级联没有自动化测试；`resetRoom` / `trial` / `undo-redo` 仅有本轮探针，没有入库测试。
   - `sliding.test` 原 fixture 用 `fineKeyOf(map,9,9)` 的任意一格物件组，改成了对象的脚印格；copy/reshape 测试现在期望的是“对象脚印”，删除 `syncObjectGroups` 后该测试仍绿（因为 `shiftGroups` 平移后的格子也等于平移后的脚印）。原测试里“物件组任意格子跟着扩图平移”的那条覆盖没有了；这是 3-A 语义变化（物件组不再允许任意形状）带来的合理让步，而且普通组的平移仍有其他测试，但这是一次覆盖削弱，值得记录。

5. **UI 过滤和画笔拦截没有自动化测试；`ui.groupId` 指向物件组时会悬空一阵。**
   `Inspector.tsx:75` 过滤 `objectId`，`MapCanvas.tsx:311` 在 `groupPaint` 时 toast 拦截，二者都没有测试。`deleteMapObject` 和 `reshapeMaps` 删除/裁剪物件组时不会重置 `ui.groupId`；如果它正好指向物件组，`CellGroups` 的 `group` 为 undefined（不会崩，但面板不再显示“正在画”），画笔会 toast。`deleteCellGroup` 会重置 `ui.groupId`，`clearObjectTexture` 走它，所以 clear 路径没问题。3-B 接 UI 前这只会造成一点困惑，不是当前可见故障。

6. **schema 不拒绝建筑物件上的物件组，`setObjectTexture` 也只挡了建筑、没挡 zone。**
   `setObjectTexture` 对 wall/door 返回 null（测试覆盖），但 schema 仍允许导入一个带 `objectId` 指向墙/门的组；`syncObjectGroups` 会照常归一它。`setObjectTexture` 对 `kind: 'zone'` 的触发区不返回 null（只检查 `isArchitectureObject`），如果 3-B 只想给家具挂外观，需要再加 kind 判断。本轮渲染层过滤 `objectId` 组，所以两者都还不会显示成普通贴图；属于 3-B 前的语义边界，不是 blocker。

7. **`syncObjectGroups` 每次 `syncMemory` 都扫描所有地图的所有物件组，性能没有测试。**
   现在物件组数量少时没问题；如果 3-B 大量使用物件贴图，每次拖动都重复分配脚印数组并比较。没有大批量物件组的性能用例。当前量级不构成 P2，记为 P3。

## 结论

3-A 的数据与级联方向正确：统一放在 `syncMemory` 覆盖了拖动、改尺寸、房间复位/排布、滑块、扩缩图、复制地图、导入、试玩、撤销/重做；旧异形组和 bounds 会归一，删除/裁剪会清悬空组；重复物件组由 schema 拦住，UI 通用列表和画笔也做了过滤/拦截。`setObjectTexture` 的重复设、fit/opacity 保留、clear、建筑拒绝都有测试能咬住。

剩余问题集中在 API 的 media/fit 校验、schema 与 update 的不变式、setter 自身没被单独测试、级联测试缺口和 UI 无测试；均为 P3，不阻断合入。**P0 / P1 / P2 均为 0。**

## P0

### P0-1 新档「有心理弱点但没人知道」重载后被迁移成「全队知道」

代码位置：

- 迁移：`src/scene/memory.ts:385-392`
  ```ts
  // 旧档的 weakness.psychological 是「队里已知」的布尔...
  for (const t of m.tokens ?? []) {
    if (t.weakness?.psychological && !t.weaknessKnownBy) {
      t.weaknessKnownBy = {};
      for (const p of w.party) t.weaknessKnownBy[p.id] = { psychological: true };
    }
  }
  ```
- 载入：`src/core/store.ts:25-29` 的 `load()` 在读取存档后直接 `migrateWorld(...)`，没有任何“旧版本才迁”的门。
- 编辑器新增数据：`src/components/Inspector.tsx:785-789` 勾「有心理弱点」时只写 `weakness.psychological=true`，**不初始化 `weaknessKnownBy`**；只有再逐个勾“谁知道”才会写。
- 玩家载荷：`src/runtime/hostSession.ts:221-227` 的 `playerToken` 用 `weaknessKnownBy[pcId]` 决定是否下发 `psychological`；`playerMap` 在 `:329-331` 对全部可见棋子调用它。

可复现路径（`/tmp/psych-migration-new.mjs`）：

1. 新建 version 2 世界，目标棋子设 `weakness.psychological=true`，不设 `weaknessKnownBy`（= 客观上存在、当前没人知道）；
2. 调 `api.migrateWorld(w)`；
3. 结果 `weaknessKnownBy={a:{psychological:true},b:{...}}` —— 全队都知道了。

我用两个 party 成员复现，输出：

```
version 2 knownBy { a: { psychological: true }, b: { psychological: true } }
```

现实触发链：GM 勾「有心理弱点」→ 不勾任何“谁知道”→ 自动存档 → 重开/刷新 → `load()` 走 `migrateWorld` → 每个队员都收到“目标有心理弱点”。这是**隐藏弱点向全体玩家泄露**，也把“客观存在但无人知道”的新数据永久写成全队知道。属于 P0 的“泄密/坏数据”。

为什么无法靠现有字段区分：

- 旧档 `weakness.psychological=true` 的语义是“队里已知”；新档同一字段的语义是“客观存在”。
- `weaknessKnownBy` 缺失在旧档表示“按旧迁移”，在新档也可能是“没人知道”，两者形状完全相同；当前没有 version/标记区分，且 `migrateWorld` 每次载入都跑。
- 现有迁移测试 `scripts/psychology.test.mjs:119-135` 用 `api.emptyWorld()`（version 2）造“旧档”并期望迁移，**等于把这个歧义固化成测试通过**；它没有“新档 true + 无 knownBy 重载后仍无人知道”的反例。

必须修：

1. 给新旧语义一个可判定的边界，例如把世界版本升到 3：旧 version ≤2 的 true 迁成存在 + 全队 knownBy；新 version 3 的 true 保留“无人知道”。同时 `checkWorld` 的 version 校验、`migrateWorld` 的 target version 一起调整。
2. 无论用哪种版本方案，`Inspector.tsx` 勾“有心理弱点”时应初始化 `weaknessKnownBy = {}`（明确表达“存在、当前无人知道”），不要留空字段；否则任何“无已知”新数据都会继续落进旧迁移分支。
3. 增加两条回归测试：
   - 旧 version true + 无 knownBy → 全队 knownBy；
   - 新 version true + 无 knownBy（或显式 `{}`）→ 保存/重载后 knownBy 仍为空，玩家载荷不出现 psychological。
4. 迁移测试不要再用 `emptyWorld()` 的 version 2 假装旧档；显式设旧 version。

## P2

### P2-1 玩家载荷的“幽灵心理弱点”：knownBy 不校验实际 weakness

`hostSession.ts:221-227` 的 `playerToken`：

```ts
const known = !!pcId && !!t.weaknessKnownBy?.[pcId]?.psychological;
```

它没有要求 `t.weakness?.psychological` 为真。于是只要数据里存在 `weaknessKnownBy[当前玩家].psychological=true`，而目标根本没有心理弱点（或 `weakness.psychological=false`），玩家载荷仍会被写成 `weakness:{psychological:true}`。

复现 `/tmp/psych-review2.mjs` 的 `stale`：

```
check: 'pass'                                   // checkWorld 接受
player: { psychological: true }                 // 玩家却看到有心理弱点
```

当前 `checkWorld` 只做了类型检查（`schema.js:785-791`），没有跨字段约束；这是“坏数据被 schema 放行 + 玩家端把它当真实弱点展示”。属 P2，范围是手工/导入/旧数据，不是默认 UI 路径，但必须修，因为它是数据泄漏的错误展示。

必须修：

- `playerToken` 至少改为 `!!t.weakness?.psychological && !!t.weaknessKnownBy?.[pcId]?.psychological`；
- schema 增加跨字段拒绝：`weaknessKnownBy` 存在时要求 `weakness.psychological === true`；对未知 observer ID 是否允许单独定（见 P3）；
- 增加测试：无心理弱点 + knownBy → `playerWorld` 的 `weakness` 不含 psychological，且 schema 拒绝（或迁移清理）。

### P2-2 NPC 的“被驱逐”状态恢复 ME 后不会解除

`src/core/store.ts:204-221` 的自动解除只处理 PC：

- 增加 NPC ME 归零 → 恢复到 1 → 状态解除的测试（当前只有 PC 测试 `psychology.test.mjs:97-109`）。

### P2-3 无 ME / ME 已为 0 的目标，事件账本仍写“1D8/1D4 ME”

`trial.ts:1248-1264` 对 `before == null` 只设置消息，不产生 `me` delta；`:1270-1278` 的事件 note 仍然按 `hit/known` 写“心理弱点已知：1D8 ME”或“未知：1D4 ME”。因此：

- 目标没填 ME：`msg` 说“没填 ME，心理伤害没落地”，但事件 delta 为空、note 仍声称 1D8/1D4；
- 目标 ME 已经为 0：也只追加“已经没有 ME”，事件 note 仍声称伤害。

复现 `/tmp/psych-review2.mjs` 的 `noMe`：

```

deltas: []
note: "心理弱点已知：1D8 ME"
```

这是事件账本与屏幕消息不一致，属 P2（范围窄，但账本是用户明确要求复核的对象）。修法：事件 note 按实际 `deltas` 生成；无 ME 时写“无 ME 可扣/未落地”，不要写伤害公式。

## 逐项回答重点问题

### `weakness.psychological` 语义是否清楚

- `types.ts:232-241` 的注释方向是对的：psychological = 客观存在；physical 仍暂用旧“已知”口径。字段名 `weakness.psychological` 本身不区分“存在”，靠注释约定，容易被旧代码误读；P0 的迁移就是典型后果。建议要么把新字段/版本显式化，要么在 schema 层强制 `psychological` 与 `weaknessKnownBy` 的配套关系。

### schema 是否允许坏数据

- **是**。它只拒非法类型（测试只覆盖 `psychological:'yes'`），允许：
  - `weaknessKnownBy` 无实际心理弱点；
  - `weakness.psychological=false` 但 knownBy true；
  - 未知 observer ID；
  - `weaknessKnownBy={}` / 多余字段（后者无害）。
  前两项会直接导致 P2-1 的玩家载荷幽灵弱点，建议 schema 跨字段拒绝或迁移时清理。

### 旧档迁移

- 旧 true：当前会迁成“存在 + 全队 knownBy”，旧 false：不迁（`weaknessKnownBy` 保持 undefined），这两点符合要求；
- **但迁移没有版本/标记边界**，新档“有心理弱点但无人知道”也会被当成旧 true，造成 P0-1。必须修 P0，再谈迁移通过。

## 第二部分：新发现

以下包含本轮新发现及确认仍存在的残留问题。

### 1. P1 — 导入进行中进入试玩，退出后留下世界／媒体错配

**`src/actions.ts:591`、`src/actions.ts:601`、`src/actions.ts:695`**

导入只在最初检查试玩状态，异步提交前后没有检查世界或沙盒是否改变。

**具体触发：** A 工程包含媒体 `m=A`；开始导入同 ID、内容为 B 的工程，在媒体事务完成前点击“试玩”；导入完成后退出试玩。

**后果：** 沙盒恢复 A 世界，但 Blob 已变成 B。内存复现结果为 **A 世界＋B 媒体**。事务等待期间的普通编辑也可能被后续 `replaceWorld(w)` 丢弃。

**建议：** 导入期间阻止进入试玩／替换世界，或者使用操作代号与世界版本检查，在写入媒体前确认操作仍有效；备份与提交应对应同一世界快照。

### 2. P1 — 保存／导出与导入交错，会打包出混合工程

**`src/actions.ts:451`、`src/actions.ts:457`**

`buildProjectZip()` 固定了世界 JSON，却逐个读取可能正在被导入替换的媒体，没有一致性快照。

**具体触发：** 对 A 开始保存／导出，在读取媒体期间导入包含同 ID 新媒体的 B；随后继续打包。

**后果：** 已复现 ZIP 内是 **A 的 world.json＋B 的媒体**；保存回文件还会把混合工程写入正式存档。

**建议：** 保存、导出、导入及恢复使用同一协调机制；在锁内取得 JSON 和整批 Blob 的一致快照，再在锁外压缩。

### 3. P1 — 标签页隔离没有覆盖媒体库和备份

**`src/media.ts:6`、`src/actions.ts:517`、`src/actions.ts:563`**

`exclusive` 是模块局部变量，而媒体数据库、媒体键和备份槽在同源标签页间共享。

**具体触发：** 两个标签页均打开 A；第二页导入同 ID 媒体不同的 B；第一页继续预览或导出 A，或者点击恢复。

**后果：** 已复现第一页导出 **A 世界＋B 媒体**；第一页恢复后，第二页又变成 **B 世界＋A 媒体**。即使两次导入没有并发也会发生，会话换号不能解决。

**建议：** 按工程／编辑实例隔离媒体与备份引用；跨页互斥只能解决写入竞争，不能解决两个活跃世界长期引用同一可变媒体键的问题。

### 4. P1 — 导入失败会破坏旧格式备份的媒体清单

**`src/actions.ts:539`、`src/actions.ts:596`**

写新备份时删除旧版独立媒体清单，但事务失败只恢复世界备份键，没有恢复该清单。

**具体触发：** 保留旧格式备份：`BACKUP_KEY` 直接存 A 世界，`OLD_BACKUP_MEDIA_KEY` 存 `["m"]`；当前为 B。下一次导入的媒体事务失败，再恢复原备份。

**后果：** 恢复读取到 A 世界，却认为没有需要交换的媒体；已复现 **A 世界＋B 媒体**，操作仍提示恢复成功。

**建议：** 提交成功前保留旧清单，或者失败时同时恢复两个键；更稳妥的是先把旧格式迁移成完整备份记录。

### 5. P1 — 会话撞车检测只接受 250ms 内的回应

**`src/sync.ts:187`、`src/sync.ts:192`**

超过 `quietUntil` 的 `taken` 被直接忽略，超时就被当成会话没有冲突。

**具体触发：** 复制使用会话 S 的编辑器标签页；原页面忙于计算或消息处理延迟，使 claim／taken 往返超过 250ms。

**后果：** 两页继续使用 S。内存调度将回应推迟到 300ms 后，两个实例确实保持相同 SESSION，副本世界仍以 S 发出，原玩家窗口无法区分。

**建议：** 使用独立实例 ID 和明确的会话所有权规则；迟到的冲突消息也必须处理，不能把短超时当成唯一性证明。

### 6. P1 — Rabbithole 输入在尺寸校验前就开始分配和遍历地图

**`src/importRabbithole.ts:75`、`src/importRabbithole.ts:90`**

输出世界的校验发生得太晚，原始格子坐标可以先制造极大的 `W/H`。

**具体触发：** Rabbithole JSON 的某层包含格子键 `"0,0"` 和 `"0,9007199254740992"`，其他必要数组正常。

**后果：** 在任何工程校验之前，`newMap()` 已收到宽度 `9007199254740996`，开始巨量循环和数组增长，页面会失去响应或耗尽内存。本轮用分配函数替身确认了传入尺寸，没有实际执行巨量循环。

**建议：** 在调用 `newMap()`、矩形拆分或构造数组之前，检查原始坐标为安全整数，并验证加边框后的尺寸不超过限制。

### 7. P1 — NPC 缺少 `beatsDone` 仍能通过两次工程校验，随后使界面崩溃

## P2-1 修法确认

**删组比清 `objectId` 合适。** 组里的 `objectId` 语义是“物件自带贴图、替换外观”；
物件被裁掉后，这组贴图没有目标，继续清空 `objectId` 会把它降级成地面贴花，
既改变作者意图，也可能把原物件位置的纹理铺到地上。直接删组符合
“物件没了，组一起消失”，也让 `checkWorld` 的 objectId 引用保持强一致。

只清 `objectId` 的另一个问题是：组还留着 `cells` 和 `texture`，下一个渲染段
会把它们当普通贴花画出来，等于凭空多了一块地面装饰；删组更干净。

## P3

### P3-1 `reshapeMaps` 只过滤 `m.groups`，`m.seen.groups` 仍可能引用被裁物件

- 位置：`src/runtime/actions.ts:735-737`。
- 现在用 `liveObjects` 过滤的是 `m.groups`；`m.seen.groups` 只平移、不过滤。
  schema 对记忆组不查 `objectId` 是否存在（这是 62 设计：记忆组只查结构），
  所以不会报错；但后续渲染若用记忆组的 `objectId` 找物件，会读到已删物件。
- 按 P3；接渲染时要么过滤/清记忆组的 `objectId`，要么明确记忆组不用 `objectId`。

### P3-2 `reshapeMaps` 会把整组都裁空的 groups 留下来

- `shiftGroups` 对出界格 `flatMap` 丢弃，但不删空组；缩图后可能有 `cells: []`
  的组。schema 允许空 cells，故不报错；`groupBounds` 会返回 null，后续渲染
  需要自己跳过。按 P3；与 P2-1 同属组清理缺口，但空组不导致校验失败。

### P3-3 `groupBounds` 的 height 是可选参数，不传时越界安全整数仍返回巨大包围盒

- 位置：`src/core/grid.ts:62-73`。
- 给 height 时，`999999` 被过滤、返回 null（测试和 mutation 都咬住）；
  不传 height 时仍是旧行为，越界 key 会生成巨大 `y1`。
- 后续渲染若图省事只传 `width`，脏数据会得到巨大包围盒；schema 虽然保证
  入库数据在界内，但 helper 是导出函数。建议渲染入口固定传 height，或让
  height 必填（改动调用方只有本段新增测试）。按 P3。

### P3-4 `shiftGroupCells` 只挡负数/非安全整数，不挡正数越界 key

- 位置：`src/core/grid.ts:96-105`。
- 现在跳过 `key < 0` 和 `!Number.isSafeInteger`，但没检查 `key < width*3*height*3`；
  一个正数越界 key 在 `dy3` 为负时可以落回地图内，被当成合法格。
- 组数据入库前 schema 会挡住，`reshapeMaps` 的 inlined `shiftGroups` 也不复用
  这个 helper；按 P3 补上界检查即可。

### P3-5 `duplicateMap` 丢悬空 objectId 组的分支没有测试

- 位置：`src/runtime/actions.ts:808-812`。
- 代码已改为 `if (g.objectId && !objectIds.has(g.objectId)) return []`，不再静默
  变 undefined；但 mutation 去掉这一行，`sliding.test.mjs` 仍 **64/64 全绿**。
- 说明没有“源组 objectId 指向不存在物件 → 复制时整组消失”的用例。按 P3；
  补一条直接构造坏源组的测试（不用过 checkWorld，复制入口应自己容错）。

### P3-6 `mergeLayers`/`syncLayer` 的 groups 同步仍留给后续段

- `emptyVision`/`cloneLayer` 已带 groups，但 `mergeLayers` 的 `out` 不合并
  `seen.groups`，`syncLayer` 也不写；individual/grouped 模式同步一次会把它清空。
- 本轮交办明确“仍没做，记 P3 不阻塞”；接 syncMemory 时必须补 merge/clone
  并覆盖测试，否则记忆组快照会被空数组覆盖。

### P1-1 假账：已修

- 打已昏厥且 hp 0：`deltas: []`，`note`「这一下数值没有变化（目标已经在倒地状态，或没有可扣的血量）」，账本句子同款 [A3/J]。
- 「命中但零变化时 note 一定出现」：条件在 `trial.ts:823`（`if (r.hit && !deltas.length)`），`!pool` 分支另有 note（`trial.ts:799`）。实测命中+零变化只有「目标已倒地/hp0」这一种，note 必现；命中必 damage≥1，hp>0 必有 hp delta，hp=0 且有非濒死状态必有 status delta，所以没有漏网路径。

### P2-1 `status.from`：已修
- 晕厥 hp2→0（钝器）：`hp 2→0`、`status from:"晕厥" → "昏厥"` [A4]。
- 中毒 hp2→0（钝器）：`from:"中毒"→"昏厥"` [M]；锐器：`from:"中毒"→"濒死"` [A13]。
- 无状态 hp2→0：钝器 `from:null→"昏厥"` [A5]；锐器 `from:null→"濒死"`（且 `roundsLeft:3`）[A6]。
- **濒死→濒死**：**不可达**。`attackContext` 对 `target.status?.label === '濒死'` 直接返回「目标 已经濒死了」（`trial.ts:724`），探针 A8/A9 都只拿到这句错误、没有事件。结论：这条路径不用管 from/to，账本里不会出现。
- **昏厥→濒死（锐器）**：**不发生**。`downed = already ?? kind`（`trial.ts:813`）——已倒地时 `already`（`'down'`）盖过锐器的 `kind`（`'dying'`），所以锐器打已昏厥的人**仍是昏厥**：`deltas: []`、`note`「数值没有变化」、token 依旧 `down:true` 无 status [A7]。账本没撒谎；但如果作者的规则是「锐器补刀要把昏厥升级成濒死」，这条**没实现**（既有逻辑，不是本轮引入）——见口径 1。
- **例外（本轮漏账）**：若棋子同时 `down:true` 且挂着「中毒/晕厥」`status`，`already='down'`、`oldLabel='中毒'`、`downed==='down'` → 不记 status delta，可 `trial.ts:819` 的 `delete dt.status` 照删 → 账本说「数值没有变化」，状态实际被抹掉 [G]。见新问题 2。

## 新问题（都 P3，不影响正常路径）

1. **repair 与 check 校验面不一致**：repair 只丢「形状」坏条目（`schema.js:132-135`），check 还查 `at/session/枚举/delta 字段`（`schema.js:582-606`）。一条缺 `at` 或是枚举写错的事件：repair 修不了（`fixed:[]`），check 拒整份存档（C11）。建议 repair 用与 check 同一套规则丢条目，或 check 报错时提示「删掉 events[i] 可导入」。
2. **`down` + `status` 共存时状态被删但不入账**：`downed = already ?? kind` 让已倒地吞掉 `kind`，而 `trial.ts:819` 的 `delete dt.status` 照执行 → `deltas:[]`、note「数值没有变化」，实际「晕厥/中毒」被抹掉 [G]。可达路径：`SkillPanel.applySyncope`（`SkillPanel.tsx:61`）和 `applyAdHoc` 的 token-status（`interaction.ts:664`）都不检查 `down/corpse`，能给已昏厥棋子挂状态。建议：`delete dt.status` 前若有旧 `status` 就记一条 `from: oldLabel → to: null/倒地`，或只在本来没状态时才删。
3. **`byStandIn` 是死字段**：`sync.ts:390` 硬编码 `false`，全仓没有写 `true` 的地方；`JudgmentPanel.tsx:115` 的 witness 分支不可达（实际代掷走 `:78`）。三来源现在仍正确，但这段代码容易误导。建议删字段/分支，或让 sync 真带上。
4. **落空 + 无血条时 note 措辞归错因**（A2/I）：落空本来就没伤害，句子却说「没有血条…伤害没落地」。建议落空时不写 note，或写成「目标没有血条；这一下本来也没造成伤害」。
5. **数据层两套档位词并存**：`check.tier:'fumble'` + `check.outcome:'落空'`；卡片仍渲染「大失败 · 落空」（`TrialEventCard.tsx:32`）。建议攻击事件把 `tier` 置 `null`，或在类型注释里写明「tier 只对判定有意义」。
6. **事件账本有 200 上限，日志没有**：`appendEvent` 每条事件加一条 log（`events.ts:25`），205 条事件 → log 205 条（H）。长局存档会涨；既有行为，但本轮起每次攻击都写一行，值得给 log 也设上限。
7. 测试缺口见 P3-2。

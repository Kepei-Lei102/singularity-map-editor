## 1. P2-1 复核：上限输入不再逐键改世界

**代码（`src/components/Inspector.tsx`）：**

- HP 行 `:765-766` 的当前 HP 输入不变；上限行 `:768-772` 改为：

```tsx
<NpcHpMaxInput value={npcHpPool(t).max}
  onChange={(v) => up((x) => {
    x.hpMax = v;
    x.hp = clampHpToMax(x.hp, v);
  })} />
```

- `NpcHpMaxInput:847-861`：

```tsx
const [text, setText] = useState<string | null>(null);
const commit = () => {
  if (text === null) return;
  onChange(parseNpcHpMaxInput(text));
  setText(null);
};
<input type="number" min={0} value={text ?? String(value)}
  onChange={(e) => setText(e.target.value)}
  onBlur={commit}
  onKeyDown={(e) => { if (e.key === 'Enter') commit(); if (e.key === 'Escape') setText(null); }} />
```

- 关键点：**`onChange` 只 `setText`，不调用父层**；父层 `onChange` 只在 `onBlur` 或 Enter 的 `commit` 里跑。键入中间值不会再写进 world。
- `parseNpcHpMaxInput` / `clampHpToMax`（`src/rules/combat.ts:183-193`）：空 / 非法 / `≤0` → 10；正小数四舍五入，至少 1；只当 `hp !== undefined && hp > max` 时夹。

**输入序列 probe（复刻同一段 handler，起始 NPC `hp:10 / hpMax:10`）：**

| 键入序列 | 键入过程中 world | blur 提交后 |
|---|---|---|
| `2` → `20` | 两次都 `hp:10 / hpMax:10`（未动） | `hp:10 / hpMax:20` |
| `1` → `15` | 不动 | `hp:10 / hpMax:15` |
| `1` → `100` | 不动 | `hp:10 / hpMax:100` |
| `1` → `10` | 不动 | `hp:10 / hpMax:10` |
| `0` → `0.4` | 不动 | `hp:1 / hpMax:1` |
| `0` → `0` | 不动 | `hp:10 / hpMax:10` |
| `2` → `20`，Enter 后再模拟 blur | 不动 | 仍 `hp:10 / hpMax:20`（未重复夹坏） |

- 上一轮复现的“键入 20 后 `hp:2 / hpMax:20`”不存在；`100` 不再从 10 掉到 1。
- **Enter 后紧跟 blur**：第一次 `commit` 把 `text` 置 `null`，第二次 `commit` 在 `if (text === null) return` 处早退；即使 React 在极窄窗口里让 blur 拿到旧闭包，第二次 `onChange` 也只是写同值，`update` 不产生实际变化，不会二次夹 HP。
- **Escape**：现在只清本地 `text`；提交前没有逐键写 world，是真正的“取消编辑”，不会留下中间 `max:2/hp:2` 撤销点。
- **清空 / 0 / 负数 / 非法**：`parse` 都回 10；父层 `x.hpMax = 10`，当前 HP 只在 `>10` 时被夹到 10（原 `hp:15` → `10/10`，原 `hp:10` 保持 `10/10`）。
- **`0.4 / 1.6 / 10.4 / 20`**：分别 1 / 2 / 10 / 20；与 `combat.test.mjs:71-85` 的 helper 表一致。
- **已有 raw `hpMax:0`**：`store.update` 归一后写回 10（`combat.test.mjs:56-69`）；输入框显示有效值 10，不再显示原始 0。
- **`hp` 未填的 helper 口径**：`clampHpToMax(undefined, 20)` 返回 `undefined`，单测 `:81`；但实际 world 里 NPC 经 `normalizeNpcHp` 后 `hp` 已是确定值（无 hp 的 token 在 `replaceWorld`/`update` 后就是满血值）。probe：
  - 旧 token 无 `hp/hpMax` → `replaceWorld` 后 `hp:10 / hpMax:10`；
  - 再把上限改 20 → `hp:10 / hpMax:20`，**不会回满到 20**，但没有 HP 损失。
  - 因此“`hp` 未填保持 undefined”只在 helper 层成立；组件层实际看到的是已归一值。见 P3-1，不是 P2。

**仍未覆盖的输入边角（P3）：** 没有组件级/输入序列自动测试（只有 `parse`/`clamp` helper 测试）；`type=number` 没有 `max`/`step`，手滑 `999999` 会写进 world；输入后不 blur 直接卸载组件会丢掉未提交文本（旧 max 保留）。不造成 HP 缩水。

## 3. `normalizeNpcHp` 在 `update` 的 `produce` 内：时机、幂等、迁移必要性

**代码（`src/core/store.ts:145-148`）：**

```ts
// NPC 血条每次改世界都归一…必须在同一个 produce 里做：produce 返回的对象是冻结的，出去再改会静默失败。
let next = produce(world, (d) => { fn(d); normalizeNpcHp(d as unknown as World); });
if (next === world) return;
```

- **时机正确**：`normalizeNpcHp` 必须在 `produce` 回调里跑；produce 返回的 world 是冻结的，出去再赋值会静默失败。lead 之前测到的“冻结后改不动”成立，当前写法是正确修法。
- **实际 update 生效**：`combat.test.mjs:56-69` 在 `api.update` 里写 `hp=5/hpMax=0`，读回 `hpMax:10/hp:5`；若归一在 produce 外，这条测试会失败。
- **幂等**：probe 对同一 world 连续两次 `update`（第二次只改同一个名字）后 token JSON 相同；`normalizeNpcHp` 写同值不会产生 draft 变化，`next === world` 早退，不会每步多一个撤销点。
- **PC token 不被写**：probe 的 PC token `hp:3/hpMax:0` 经 `update` 后仍是 `hp:3/hpMax:0`（`if (t.pcId) continue`）。PC HP 走角色卡，token 上的 `hpMax:0` 不参与 NPC 血条；保留 raw 值不影响结算（P3-8）。
- **`migrateWorld` 仍然必要**（`src/scene/memory.ts:357`）：
  - `load()`（`store.ts:28`）读档后直接进入 UI，不经过 `update`；
  - `replaceWorld()`（`store.ts:236`）导入/换世界，先 `migrateWorld`；
  - `parseWorld()`（`actions.ts:1000`）工程解析也走 `migrateWorld`。
  - 去掉 `migrateWorld` 里的归一，首次渲染/首次攻击前仍可能拿到 raw `hpMax:0`/缺 hp。两处都保留是**幂等冗余**，不是重复写坏数据。
- **会话里 raw `hpMax:0`**：`store.update` 现在会写回 10；`Inspector` HP 输入也不会再让 raw 0 长期存在（P3-8 仅 PC token 例外）。
- **实际 `hp` undefined 不可见**：无 hp 的 NPC 在 `replaceWorld`/首次 `update` 就归一成满血；因此组件层“改上限时 `hp` 仍 undefined”不会出现。没有数据损失；见 P3-1。
- **`down/濒死/急救机器人/昏厥/corpse` 缺 hp 归 0**：`combat.ts:162-166` 的 `downed` 覆盖这五类；`normalizeNpcHp` 写回 `0`。显式 `hp` 仍尊重（NPC down `hp:4` 保持 4，仍可被攻击，符合作者口径）。
- **PC 跳过、尸体、正常状态**：PC 全跳过；NPC 尸体/等待救援按 0；普通状态（中毒/流血/眩晕）按满血；与 `docs/战斗模式-v0.1.md:79-83` 一致。
- **本节没有 P2。**

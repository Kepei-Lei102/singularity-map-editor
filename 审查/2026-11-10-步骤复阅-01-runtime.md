## 问题清单

### P1-1 `deltas` 不判「是否真变了」：落空、再打倒地目标都会写出假改动

位置：`src/runtime/trial.ts:798`（`hp` delta）、`src/runtime/trial.ts:810`（`status` delta）、`src/runtime/trial.ts:801-802`（`already`/`next<=0` 分支）；契约 `src/core/types.ts:560`（`Delta` 的 `from/to` 是「从 X 改为 Y」）。

触发与证据（探针）：
- 落空：`attackBand(3)==='miss'`，伤害 0 → 事件 `deltas=[{"kind":"hp","id":"b","name":"乙","from":2,"to":2}]`，日志「…大失败：乙 的 HP 从 2 改为 2」。
- 打已倒地目标：目标 `hp:0`、`down:true` 再挨一刀 → `deltas=[hp 0→0, status "昏厥"→"昏厥"]`，日志「乙 的 HP 从 0 改为 0；乙 的状态从 昏厥 改为 昏厥」。
- 根因：`hp` delta 无条件 `push`（`next === pool.hp` 也 push）；`status` delta 无条件 `push`（`downed === already` 时也 push）。

建议修法：
```ts
if (next !== pool.hp) deltas.push({ kind: 'hp', … });
…
if (downed !== already) deltas.push({ kind: 'status', … });
```
落空会被第一条自然挡住（`r.damage === 0` → `next === pool.hp`）。这条是新账本的核心契约，早修比以后接移动/跳跃时再统一便宜。

### P2-1 目标带非「濒死」状态时，`status.from` 写成 `null`（日志说「从 无」）

位置：`src/runtime/trial.ts:801`（`already` 只认 `dt.status?.label==='濒死'` 与 `dt.down`）、`:810`。

触发：给 NPC 挂 `{label:'晕厥', roundsLeft:2}`、`hp:1`，一刀打到 0（探针实际输出）→ `deltas` 的 status 为 `from:null, to:"昏厥"`，日志「箱子怪 的状态从 无 改为 昏厥」；而这一刀实际上把 `dt.status` 删了，旧状态是「晕厥」。

建议修法：
```ts
const prev = dt.status?.label ?? (dt.down ? downedLabel('down') : null);
const already = dt.status?.label === '濒死' ? 'dying' : dt.down ? 'down' : null; // 仍用于 downed 计算
… from: prev
```
`downedLabel(already as Downed)` 的 cast 也就不需要了。

### P2-3 `Delta.id` 混了两种身份域（pcId / tokenId），类型上看不出来

位置：`src/runtime/trial.ts:798`、`:810`；类型 `src/core/types.ts:560`（只有 `id: Id`，没注明是哪种 id）。

现状：`hp` delta 用 `dt.pcId ?? dt.id`，与「PC 改 `party.hp`、NPC 改 `token.hp`」是对得上的；但 `status` delta 改的是**棋子**（`dt.status`/`dt.down`），id 却优先给 pcId。同一个 pc 绑定两个棋子（编辑器允许手工绑）时，`id` 指不出是哪一个棋子的状态；下游若按 id 去 `maps[].tokens` 找会找不到。

建议修法：`Delta` 里拆成 `{ pcId?: Id; tokenId: Id }`，或至少加注释「hp/me 上是 pcId，status/moved 上是 tokenId」；接移动/跳跃时建议一律 `tokenId` + 单独的 `pcId`。

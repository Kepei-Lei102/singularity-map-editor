## 焦点核对：主体接线正确

### 事件 actor / target

- 出手敌人：`{ kind: e.pcId ? 'pc' : 'npc', id: e.pcId ?? e.id, name: e.name }`（`src/runtime/trial.ts:2405`）。
- 被打目标：`{ kind: mv.pcId ? 'pc' : 'npc', id: mv.pcId ?? mv.id, name: mv.name }`（`:2408`）。
- 和 `settleAttack` 的口径一致：PC 目标用 `pcId`，NPC 目标用 token id（`src/runtime/trial.ts:1820`）；HP delta 也用同一 id（`:2366`），状态 delta 用 token id（和 `settleAttack:1924`、`events.test.mjs:108` 一致）。
- 实测：PC 打 PC 时 `actor={kind:'pc',id:'b'}`、`target={kind:'pc',id:'a'}`；PC 打 NPC 时 `target={kind:'npc',id:'ta'}`；NPC 敌人出手时 `actor={kind:'npc',id:'tc'}`。均正确。

### 多敌人、顺序与上限

- 每个通过 `!corpse && !down && !opportunityUsed && !statusBlocksAction` 的敌人各追加一条事件；多个敌人实测得到 2 条 `events` / 2 条 `log`，顺序为 `enemies` 数组顺序，先事件后日志。
- `appendEvent`（`src/rules/events.ts:22-25`）先 push `events`、再 push `log`；`events` 上限 200（超出从头部 splice），`log` 按现有设计不截断（`types.ts:468` 注释也这么写）。实测连续 append 203 条：`events=200`、`logs=203`，顺序正确，不是本批缺陷。
- 落空事件：`deltas=[]`、无 `note`；和 `settleAttack` 落空口径一致（`events.test.mjs:83`），不需要额外 note。

### NPC 扣血 / 无血条

- PC 目标看角色卡 `hpOf`；NPC 目标只在 `hpMax > 0` 时取 `{ hp: hp ?? hpMax, max: hpMax }`，和 `settleAttack:1890-1893` 的“填了血条才扣”一致。
- 实测：NPC `hp=10/hpMax=10` 被打 4 → token `hp=6`，event HP delta `10→6`；NPC 无 `hp/hpMax` → `deltas=[]`，`note='目标没有血条，伤害没落地'`，token 不变。
- NPC 无血条但触发 009：仍会挂眩晕（event status delta `null→眩晕`，note 为“没有血条…；眩晕打击…”）。这与 `settleAttack` 在无血条分支仍先 `applyRiders()` 的既有口径一致；没有新增测试锁住它，属于 P3。

### 009 与 HP 归零顺序

- 先扣 HP、再处理 `next <= 0` 的倒地，再判断 009 被动；已 down/濒死目标不会被归零分支重新处理，归零后的目标也不会再叠眩晕。
- 普通命中且目标未倒地：HP delta 与 status delta（`from` 为旧状态名）都正确；已有 `events.test.mjs:100-109` 的同类口径可对照。

## P3（均不阻塞提交）

### P3-1 已 down 目标的 UI msg 仍会追加“，昏厥”

`src/runtime/trial.ts:2385` 在 `already === 'down'` 分支也执行 `noted += '，昏厥'`。event 账本是干净的（无 status delta、note 为 undefined），但 UI msg 会变成：

